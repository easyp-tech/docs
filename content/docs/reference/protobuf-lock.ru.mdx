Файл <code>protobuf.lock</code> создаётся командами <code>easyp get</code>, <code>easyp mod tidy</code> и <code>easyp mod update</code>. Он фиксирует выбранный граф Git-зависимостей точными коммитами и хешами содержимого. Это делает исходники зависимостей воспроизводимыми при доступности зафиксированных коммитов и успешной проверке целостности.

## Команды жизненного цикла

- <code>easyp get</code> добавляет прямое требование, записывает транзитивные требования как indirect и обновляет lock.
- <code>easyp mod tidy</code> разрешает объявленные требования, обновляет indirect-записи и lock. Для требования, оставшегося без ограничений версии, сохраняет прежний коммит из lock.
- <code>easyp mod update</code> обновляет SemVer-зависимости в пределах текущей мажорной версии, освежает всё ещё неограниченные требования до HEAD и сохраняет явные хеши коммитов.
- <code>easyp mod download</code> загружает точные коммиты из lock и проверяет содержимое, не меняя зафиксированные версии.

## Неизменность версий и кеш

При <code>tidy</code>, <code>get</code> и <code>update</code> повторно полученный ранее зафиксированный SemVer сравнивается с его записанными коммитом и хешем. Перепубликованный тег вызывает <code>ErrLockedVersionChanged</code> до установки нового графа и записи манифеста или lock. Проверка действует и для транзитивных требований, независимо от прогретого кеша. Новую версию по-прежнему можно выбрать; неограниченные требования без версии обновляются при <code>mod update</code>.

<code>mod download</code> использует коммит из lock даже после переноса тега, если этот коммит доступен.

<code>hash</code> вычисляется через Go <code>dirhash.Hash1</code> по всем обычным файлам, отслеживаемым Git в коммите, с путями относительно репозитория. Хеш проверяется и при скачивании, и при повторном использовании установленного модуля; повреждённая установка отклоняется.

Для каждого Git remote кеш v1 повторно использует хранилище объектов. Известный точный коммит можно получить без обращения к remote. При холодном запросе сначала выполняется shallow-загрузка точного коммита с глубиной один; если сервер её отклоняет, используется доступная история объявленных ссылок. Всё равно требуется исходный коммит: HEAD вместо него не подставляется. Проверки тегов обновляются отдельно, поэтому кеш не скрывает перенос тега. Отсутствующий в кеше коммит всё ещё может потребовать доступа к источнику.

Идентификатор <code>source</code> и SemVer в <code>version</code> должны соответствовать [правилам major-версий](/ru/docs/reference/protobuf-mod): v0/v1 без суффикса, v2+ с соответствующим <code>/vN</code>. Некорректные суффиксы отклоняются до установки. Для v2+ без суффикса пути запись <code>+incompatible</code> дополнительно требует отсутствия нативного manifest в точной ревизии, в том числе при уже заполненном кеше. Коммит проверяется по точному нативному имени модуля, включая frozen-режим.

## Справка MCP

<code>easyp_config_describe</code> описывает формат, не читая локальные файлы. Укажите <code>file: protobuf.lock</code> и <code>path: modules[].commit</code>. См. [справку по конфигурации через MCP](/ru/docs/cli/configuration).
