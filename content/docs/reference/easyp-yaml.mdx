title: "easyp.yaml Reference"
description: "Complete specification for easyp.yaml, configuring producer-side linting rules, breaking change detection, path exclusions, and policy inheritance."
---

The `easyp.yaml` file defines **producer-side policy configuration** for Protocol Buffer schema repositories. It specifies linting standards, breaking change checks against Git baselines, and issue exclusions. Directory cascading is available; explicit `extends` references are reserved until their resolution rules are specified.

`easyp.yaml` files cascade hierarchically down directory structures: for any given `.proto` file, EasyP traverses up the directory tree to find the nearest `easyp.yaml` and applies its configuration.

## Example Configuration

```yaml
version: v1

linters:
  default: STANDARD
  enable:
    - ENUM_VALUE_PREFIX
    - RPC_REQUEST_RESPONSE_UNIQUE
  disable:
    - PACKAGE_VERSION_SUFFIX

linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
  SERVICE_SUFFIX:
    suffix: Service

issues:
  exclude-rules:
    - linters:
        - FIELD_LOWER_SNAKE_CASE

breaking:
  baseline: git:main
  ignore:
    - gen
```

## Directory Cascading

EasyP applies the **nearest file rule**: when evaluating a `.proto` file, EasyP searches upward through parent directories for an `easyp.yaml`. 

```text
proto/
├── easyp.yaml          # STANDARD policy applies to root & user/
├── user/
│   └── v1/user.proto
└── legacy/
    ├── easyp.yaml      # MINIMAL policy override applies strictly to legacy/
    └── old.proto
```

Sections are inherited as whole units from the nearest declaring file, preventing confusing partial merges.

The v1 `breaking.baseline` selects the Git branch used by the existing EasyP breaking checker. Its rule set is unchanged. Category selection and unstable-package filtering need separate rule semantics and are not active yet. A path-bearing `issues.exclude-rules` entry currently produces an error; pathless entries work without choosing an implicit glob base. Explicit `linters.extends` and `breaking.extends` currently produce errors: the syntax does not yet define a Git ref, policy path, merge precedence, or lock/integrity behavior.
