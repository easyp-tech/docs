<code>protobuf.lock</code> is generated by <code>easyp get</code>, <code>easyp mod tidy</code>, and <code>easyp mod update</code>. It records the selected Git dependency graph with exact commits and content hashes, making dependency sources reproducible while the pinned commits remain available and integrity checks succeed.

## Lifecycle commands

- <code>easyp get</code> adds a direct requirement, records transitive requirements as indirect, and updates the lock.
- <code>easyp mod tidy</code> resolves declared requirements, updates indirect entries and the lock, and preserves an existing lock pin for a requirement that remains unconstrained.
- <code>easyp mod update</code> refreshes SemVer dependencies within their current major versions, refreshes still-unconstrained requirements to HEAD, and preserves explicit commit pins.
- <code>easyp mod download</code> downloads exact locked commits and verifies their contents without changing locked versions.

## Immutable versions and cache reuse

During <code>tidy</code>, <code>get</code>, and <code>update</code>, every fetched previously locked SemVer is compared with its recorded commit and hash. A republished tag raises <code>ErrLockedVersionChanged</code> before installing the new graph or writing the manifest or lock. This includes transitive requirements and works independently of a warm installed-module cache. A new version may still be selected; unconstrained versionless requirements still refresh during <code>mod update</code>.

<code>mod download</code> uses the locked commit even after a tag moves, provided that commit remains available.

The <code>hash</code> uses Go's <code>dirhash.Hash1</code> over all regular files tracked by Git at the commit, with repository-relative paths. EasyP verifies it on download and when reusing an installed module; corrupt installations are rejected.

The v1 cache reuses an object store per Git remote. A known exact commit can be fetched without contacting the remote. A cold request first tries a depth-one fetch of the exact commit; if the server rejects that request, EasyP falls back to advertised reachable history. The original commit is still required: HEAD is never substituted. Tag lookups are refreshed separately so cache reuse cannot hide a retag. A commit absent from cache can still require access to its source.

The <code>source</code> identity and SemVer <code>version</code> must satisfy the [major-version rules](/docs/reference/protobuf-mod): unsuffixed v0/v1, matching <code>/vN</code> for v2+. Invalid suffixes fail before installation. An unsuffixed v2+ <code>+incompatible</code> entry additionally requires the exact revision to have no native manifest, including when installed content is already cached. Commit pins still verify the exact native module identity, including in frozen mode.

## MCP reference

<code>easyp_config_describe</code> describes this format without reading local files. Use <code>file: protobuf.lock</code> and <code>path: modules[].commit</code>. See [configuration reference via MCP](/docs/cli/configuration).
