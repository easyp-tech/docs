---
title: "Справочник easyp.gen.yaml"
description: "Полная спецификация файла easyp.gen.yaml, управляющего кодогенерацией на стороне потребителя, выводами плагинов, WASM/remote запуском и managed-опциями."
---

Файл `easyp.gen.yaml` задаёт **правила генерации кода на стороне потребителя**. Находясь рядом с приложением или сервисом, он определяет, какие модули и пакеты компилировать, какие плагины вызывать, куда записывать сгенерированный код и какие managed-опции (такие как `package_prefix`) применять.

В соответствии с принципом недублирования источников EasyP, `easyp.gen.yaml` **никогда** не содержит URL репозиториев или версий зависимостей — источники и версии протоколов определяются строго через `protobuf.mod` и `protobuf.lock`.

## Примеры конфигураций

### Проектный генератор (`backend/easyp.gen.yaml`)

```yaml
version: v1

generate:
  modules:
    - proto/user
    - proto/order

plugins:
  - name: go
    version: v1.34.2
    out: ./gen/go
    opts:
      paths: source_relative
  - name: go-grpc
    version: v1.4.0
    out: ./gen/go
    opts:
      paths: source_relative
      require_unimplemented_servers: false

options:
  go:
    package_prefix: github.com/acme/backend/gen/go
```

### Удалённая веб-генерация (`frontend/easyp.gen.yaml`)

```yaml
version: v1

generate:
  modules:
    - proto/user

plugins:
  - remote: gen.easyp.tech/es
    version: v2.0.0
    out: ./src/gen
    opts:
      target: ts
```

## Managed Options (`options`)

Вместо явного прописывания опций вроде `option go_package = "..."` внутри каждого `.proto` файла, блок `options` в EasyP группирует настройки по целевым языкам программирования.

Например, указание `options.go.package_prefix: github.com/acme/backend/gen/go` автоматически вычисляет пути импортов на основе структуры директорий модуля без модификации исходных `.proto` файлов.
