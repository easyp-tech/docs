title: "Справочник easyp.gen.yaml"
description: "Полная спецификация файла easyp.gen.yaml, управляющего кодогенерацией на стороне потребителя, выводами плагинов, WASM/remote запуском и managed-опциями."
---

Файл `easyp.gen.yaml` задаёт **правила генерации кода на стороне потребителя**. Находясь рядом с приложением или сервисом, он определяет, какие модули компилировать, какие плагины вызывать, куда записывать сгенерированный код и какие managed-опции применять.

В соответствии с принципом недублирования источников EasyP, `easyp.gen.yaml` **никогда** не содержит URL репозиториев или версий зависимостей — источники и версии протоколов определяются строго через `protobuf.mod` и `protobuf.lock`.

## Примеры конфигураций

### Проектный генератор (`backend/easyp.gen.yaml`)

```yaml
version: v1

generate:
  modules:
    - proto/user
    - proto/order

plugins:
  - name: go
    out: ./gen/go
    opts:
      paths: source_relative
  - name: go-grpc
    out: ./gen/go
    opts:
      paths: source_relative
      require_unimplemented_servers: false

options:
  go:
    package_prefix: github.com/acme/backend/gen/go
```

### Удалённая веб-генерация (`frontend/easyp.gen.yaml`)

```yaml
version: v1

generate:
  modules:
    - proto/user

plugins:
  - remote: gen.easyp.tech/es
    version: v2.0.0
    out: ./src/gen
    opts:
      target: ts
```

## Managed Options (`options`)

Вместо явного прописывания опций вроде `option go_package = "..."` внутри каждого `.proto` файла, блок `options` в EasyP группирует настройки по целевым языкам программирования.

Например, указание `options.go.package_prefix: github.com/acme/backend/gen/go` автоматически вычисляет пути импортов на основе структуры директорий модуля без модификации исходных `.proto` файлов.

Существующие правила managed mode доступны в `generate.managed`. Например, переопределение для конкретного Protobuf-пакета:

```yaml
version: v1
generate:
  managed:
    enabled: true
    override:
      - file_option: go_package_prefix
        package: user.v1
        value: github.com/acme/backend/gen/user
plugins:
  - name: go
    out: ./gen/go
```

Корневой `easyp.gen.yaml` может задавать `options.go.package_prefix` по умолчанию для вложенных генераторов. Локальные правила `generate.managed` имеют приоритет над унаследованным префиксом. Префикс, заданный в том же файле генератора, имеет наивысший приоритет. Списки плагинов не наследуются.

Сейчас v1 генерирует модули целиком. `generate.packages` оставлено для будущей версии после определения синтаксиса выбора пакетов.

Удалённому плагину нужен `version`, например `v2.0.0`. EasyP передаёт именно эту версию удалённому генератору. Для локального `protoc-gen-*` и встроенного WASM версию определяет выбранный исполняемый файл; отдельное поле `version` отклоняется, поскольку EasyP не может его проверить.
