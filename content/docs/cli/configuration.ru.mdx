В пилотной версии v1 зависимости, генерация и правила проверки находятся в разных файлах:

| Файл | Назначение |
|------|------------|
| [`protobuf.mod`](/ru/docs/reference/protobuf-mod) | Имя модуля, корни исходников, зависимости и локальные замены |
| [`protobuf.lock`](/ru/docs/reference/protobuf-lock) | Зафиксированные Git-коммиты и хеши содержимого; создаётся командой `easyp mod tidy` |
| [`easyp.gen.yaml`](/ru/docs/reference/easyp-gen-yaml) | Модули для генерации, плагины, выходные каталоги и managed mode |
| [`easyp.yaml`](/ru/docs/reference/easyp-yaml) | Правила линтинга и проверки совместимости |

Команды CLI читают формат v1 напрямую и не переходят на старую логику генерации, линтинга, проверки совместимости или управления модулями. Зависимость в Git при этом может использовать старый формат EasyP или Buf: адаптер извлекает её требования и корни `.proto` для разрешения импортов.

## Обычный порядок работы

```bash
easyp init --module github.com/acme/contracts
easyp mod tidy
easyp mod download
easyp generate
easyp lint --path proto
easyp breaking --path proto --against main
```

`mod tidy` разрешает зависимости и записывает `protobuf.lock`. `mod download` скачивает только зафиксированные коммиты. `mod update` обновляет версии в пределах текущей мажорной версии и пересоздаёт lock. Локальные `replace` работают при генерации и линтинге; перед `mod tidy` или `mod update` их нужно убрать, чтобы получить воспроизводимый lock.

## Флаги команд

| Команда | Основные флаги |
|---------|----------------|
| `generate` | `--project`, `--descriptor_set_out`, `--include_imports` |
| `lint` | `--path` (`-p`), `--root` (`-r`) |
| `breaking` | `--path` (`-p`), `--root` (`-r`), `--against` |
| `init` | `--dir` (`-d`), `--module` |
| `validate-config` | `--config` (псевдоним `--cfg`), `--format` |

Общие флаги: `--cfg` (псевдоним `--config`, по умолчанию `easyp.yaml`), `--debug` (`-d`) и `--format` (`-f`, `text` или `json`). Переменные `EASYP_CFG`, `EASYP_DEBUG` и `EASYP_FORMAT` задают значения по умолчанию. Кеш модулей находится в `EASYPPATH` или `$HOME/.easyp`.

`generate` ищет `easyp.gen.yaml` внутри текущего каталога. Флаг `--project` выбирает один проект-потребитель. Список модулей и корни исходников берутся из `protobuf.mod`. Поле `generate.packages` зарезервировано: непустое значение пока вызывает ошибку. Старые флаги `generate --path` и `generate --root` удалены.

`lint` и `breaking` читают `easyp.yaml` версии v1. Для импортов они используют корни ближайшего модуля и его зафиксированных или локальных зависимостей. Политика может существовать без `protobuf.mod`; тогда используются проверяемые файлы и встроенные импорты.

`breaking` применяет ближайшую секцию `breaking` к каждому файлу с ошибкой. Если вложенные политики выбирают разные Git-базы, команда сравнивает файлы с каждой базой и относит ошибку только к выбравшей её политике.

`validate-config --cfg <файл> --format json` принимает `easyp.yaml`, `easyp.gen.yaml`, `protobuf.mod` и `protobuf.lock`. Некорректная версия lock-файла, неполные записи и неверные хеши выдаются как ошибки проверки.

В пилотной версии v1 нет команд `mod vendor` и `ls-files`.

## Минимальный пример

```text
module github.com/acme/contracts
roots proto
require github.com/acme/shared v1.2.0
```

```yaml
# easyp.gen.yaml
version: v1
generate:
  modules: [github.com/acme/contracts]
plugins:
  - name: go
    out: ./gen/go
```

```yaml
# easyp.yaml
version: v1
linters:
  default: STANDARD
breaking:
  baseline: git:main
```

Точные поля и текущие ограничения описаны в справочниках по ссылкам выше.
