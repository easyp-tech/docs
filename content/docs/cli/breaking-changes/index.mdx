---
title: "Breaking Changes Detection"
description: "Compare protobuf schemas with a Git ref using EasyP v1."
---

`easyp breaking` compares current `.proto` files with a Git reference and reports incompatible changes detected by the existing checker.

```yaml
# easyp.yaml
version: v1
breaking:
  baseline: git:main
  ignore: [experimental]
```

```bash
easyp breaking --path proto --against main
easyp --format json breaking --path proto
```

`breaking.baseline` selects the Git ref. If it is absent, `--against` supplies the ref (default `master`). `--path` selects a directory relative to the scan root; `--root` changes that root from the policy file's directory. `breaking.ignore` excludes directories from the check.

The v1 pilot keeps the existing breaking check set. `breaking.categories`, `breaking.ignore_unstable`, and `breaking.extends` are not implemented and return an error instead of silently changing behavior. The old `breaking_check.against_git_ref` key is not accepted by the v1 CLI.

See the [`easyp.yaml` reference](/docs/reference/easyp-yaml) for the policy format. For imports, the checker uses the module and dependency roots resolved for the scan root; a policy can also run without a module manifest.
