---
title: "Rpc No Delete"
description: "Проверяет, что ни один RPC-метод не был удалён из сервиса."
---

- **ID правила:** `RPC_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

Это правило проверяет, что из `service` не удалён ни один RPC-метод. Удаление RPC ломает как сгенерированный клиентский и серверный код, так и живые сетевые вызовы.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse);
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  // RPC DeleteUser удалён
}
```

**Ошибка:**

```text
services.proto:7:3: RPC "DeleteUser" on service "myapi.v1.UserService" was deleted. (RPC_NO_DELETE)
```

### Правильно

Вместо удаления пометьте RPC-метод как устаревший:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse) {
    option deprecated = true;
  }
}
```

## Стратегия миграции

1. Пометьте RPC опцией `option deprecated = true;` и предупредите потребителей API.
2. Сохраняйте обработчик на сервере до завершения миграции клиентов.
3. Удалите RPC только в новой мажорной версии пакета (например, `myapi.v2`).
