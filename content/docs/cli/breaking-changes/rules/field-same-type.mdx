---
title: "Field Same Type"
description: "Checks that fields keep the exact same protobuf type in source-compatibility profiles."
---

- **Rule ID:** `FIELD_SAME_TYPE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that message and extension fields keep their exact protobuf type (scalar kind or fully qualified message/enum name). Changing a field's type breaks generated source code because field types and method signatures change.

<Callout type="info">
`FIELD_SAME_TYPE` enforces strict type equality for `FILE` and `PACKAGE` profiles — even for transitions that are wire-compatible (such as `int32` → `int64` or `int32` → `uint32`). For binary or JSON compatibility instead of generated-source compatibility, use the `WIRE` or `WIRE_JSON` profile:

- [`FIELD_WIRE_COMPATIBLE_TYPE`](/docs/cli/breaking-changes/rules/field-wire-compatible-type) (`WIRE`) allows binary-compatible transitions such as `int32` ↔ `uint32` ↔ `int64` ↔ `uint64` ↔ `bool`, `sint32` ↔ `sint64`, `fixed32` ↔ `sfixed32`, `fixed64` ↔ `sfixed64`, `string` → `bytes`, and structurally compatible message/enum types.
- [`FIELD_WIRE_JSON_COMPATIBLE_TYPE`](/docs/cli/breaking-changes/rules/field-wire-json-compatible-type) (`WIRE_JSON`) allows `int32` ↔ `uint32`, `int64` ↔ `uint64`, `fixed32` ↔ `sfixed32`, `fixed64` ↔ `sfixed64`, and JSON-compatible message/enum types (rejecting `int32` → `int64` because 64-bit integers serialize as JSON strings, and rejecting `string` → `bytes` because `bytes` uses base64).
</Callout>

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  int32 price = 2;
  bool available = 3;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  string price = 2; // Changed from int32 to string
  bool available = 3;
}
```

**Error:**

```text
product.proto:7:3: Field "price" (2) on "myapi.v1.Product" changed type from int32 to string. (FIELD_SAME_TYPE)
```

### Good

Add a new field with the desired type and deprecate the old field:

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  int32 price = 2 [deprecated = true];
  bool available = 3;
  string price_formatted = 4;
}
```

Or change the type in a new major package version (for example, `myapi.v2`).
