---
title: "Service Moved"
description: "Checks that services are not moved to a different .proto file in the FILE profile."
---

- **Rule ID:** `SERVICE_MOVED`
- **Profiles:** `FILE`

In the `FILE` profile, moving a `service` to a different `.proto` file (even within the same protobuf package) breaks generated file-level service stubs and language imports. Use the `PACKAGE` profile if moving declarations between files in the same package is allowed.

## Examples

### Bad

**Before:**

```proto
// File: myapi/v1/user.proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}
```

**After:**

```proto
// File: myapi/v1/user_service.proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}
```

**Error:**

```text
myapi/v1/user.proto:6:1: Service "myapi.v1.UserService" was moved from "myapi/v1/user.proto" to "myapi/v1/user_service.proto". (SERVICE_MOVED)
```

### Good

Keep the service in its original `.proto` file when checking with `FILE`:

```proto
// File: myapi/v1/user.proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}
```
