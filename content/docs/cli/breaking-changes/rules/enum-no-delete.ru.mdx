---
title: "Enum No Delete"
description: "Проверяет, что ни одно объявление enum (верхнего уровня или вложенное) не было удалено."
---

- **ID правила:** `ENUM_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что из protobuf-пакета не удалено ни одно объявление `enum` (верхнего уровня или вложенное). Удаление enum убирает сгенерированные типы и константы, ломая компиляцию клиентов, которые на него ссылаются.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

enum UserRole {
  USER_ROLE_UNSPECIFIED = 0;
  USER_ROLE_ADMIN = 1;
  USER_ROLE_USER = 2;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

// Enum UserRole удалён
```

**Ошибка:**

```text
order.proto:10:1: Enum "myapi.v1.UserRole" was deleted. (ENUM_NO_DELETE)
```

### Правильно

Вместо удаления сохраните enum и пометьте его как устаревший в текущей мажорной версии:

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

enum UserRole {
  option deprecated = true;
  USER_ROLE_UNSPECIFIED = 0;
  USER_ROLE_ADMIN = 1;
  USER_ROLE_USER = 2;
}

enum UserPermission {
  USER_PERMISSION_UNSPECIFIED = 0;
  USER_PERMISSION_READ = 1;
  USER_PERMISSION_WRITE = 2;
}
```

## Стратегия миграции

1. Пометьте старый enum опцией `option deprecated = true;` и пометьте устаревшими поля, которые его используют.
2. При необходимости добавьте новый enum рядом со старым.
3. Удалите устаревший enum только в новой мажорной версии пакета (например, `myapi.v2`).
