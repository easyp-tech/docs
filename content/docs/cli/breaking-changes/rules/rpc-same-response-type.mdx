---
title: "Rpc Same Response Type"
description: "Checks that every RPC method keeps the same fully qualified response message type."
---

- **Rule ID:** `RPC_SAME_RESPONSE_TYPE`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that an RPC method keeps the same fully qualified response message type. Changing the response type breaks generated client/server method signatures and can break deserialization for existing clients.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserResponse {
  string user_id = 1;
  string name = 2;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponseV2);
}

message GetUserResponseV2 {
  string id = 1;
  string full_name = 2;
}
```

**Error:**

```text
user_service.proto:6:3: RPC "GetUser" response type changed from "myapi.v1.GetUserResponse" to "myapi.v1.GetUserResponseV2". (RPC_SAME_RESPONSE_TYPE)
```

### Good

Extend the existing response message with new fields when the change is additive:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserResponse {
  string user_id = 1;
  string name = 2;
  string email = 3;
}
```

Or add a new RPC method alongside the deprecated original when a completely new response message is required:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse) {
    option deprecated = true;
  }
  rpc GetUserV2(GetUserRequest) returns (GetUserResponseV2);
}
```
