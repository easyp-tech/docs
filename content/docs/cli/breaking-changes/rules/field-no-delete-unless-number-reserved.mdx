---
title: "Field No Delete Unless Number Reserved"
description: "Checks that any field deleted in WIRE or WIRE_JSON has its field number reserved."
---

- **Rule ID:** `FIELD_NO_DELETE_UNLESS_NUMBER_RESERVED`
- **Profiles:** `WIRE_JSON`, `WIRE`

In `WIRE` and `WIRE_JSON` profiles, deleting a non-required field is permitted only if its field number is permanently reserved using `reserved <number>;`. Without reserving the number, a future field could reuse the same wire tag with an incompatible type and corrupt stored or in-flight data.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  string phone = 2;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}
```

**Error:**

```text
user.proto:7:3: Deleted field "phone" number 2 on "myapi.v1.User" must be reserved. (FIELD_NO_DELETE_UNLESS_NUMBER_RESERVED)
```

### Good

Reserve the deleted field number (and its name too if you also check `WIRE_JSON`):

```proto
syntax = "proto3";

package myapi.v1;

message User {
  reserved 2;
  reserved "phone";
  string name = 1;
}
```
