---
title: "Enum Value No Delete"
description: "Проверяет, что ни одно значение enum не было удалено в профилях совместимости исходного кода."
---

- **ID правила:** `ENUM_VALUE_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что из `enum` не удалено ни одно значение. Удаление значения enum убирает соответствующую сгенерированную константу и ломает клиентский код (например, ветки `switch` и сравнения).

<Callout type="info">
Директива `reserved` для удалённого номера или имени **не** удовлетворяет `ENUM_VALUE_NO_DELETE` в профилях `FILE` и `PACKAGE`, поскольку сгенерированная константа всё равно исчезает. Резервирование номера (и имени для JSON) достаточно только для [`ENUM_VALUE_NO_DELETE_UNLESS_NUMBER_RESERVED`](/ru/docs/cli/breaking-changes/rules/enum-value-no-delete-unless-number-reserved) (`WIRE`, `WIRE_JSON`) и [`ENUM_VALUE_NO_DELETE_UNLESS_NAME_RESERVED`](/ru/docs/cli/breaking-changes/rules/enum-value-no-delete-unless-name-reserved) (`WIRE_JSON`).
</Callout>

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
  ORDER_STATUS_CANCELLED = 5;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  reserved 5;
  reserved "ORDER_STATUS_CANCELLED";

  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
}
```

**Ошибка:**

```text
order.proto:5:1: Enum value "ORDER_STATUS_CANCELLED" = 5 in "myapi.v1.OrderStatus" was deleted. (ENUM_VALUE_NO_DELETE)
```

### Правильно

В профилях `FILE` и `PACKAGE` оставьте значение и пометьте его как `deprecated`:

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
  ORDER_STATUS_CANCELLED = 5 [deprecated = true];
}
```

## Стратегия миграции

1. Пометьте значение опцией `[deprecated = true]` и перестаньте записывать его в новом коде.
2. Продолжайте обрабатывать старое значение, пока оно встречается в сохранённых данных или старых клиентах.
3. При использовании профилей `WIRE`/`WIRE_JSON` зарезервируйте номер (и имя для `WIRE_JSON`) при удалении значения; для `FILE`/`PACKAGE` удаляйте значение только в новой мажорной версии пакета (например, `myapi.v2`).
