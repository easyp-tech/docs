---
title: "Field Same Jstype"
description: "Checks that fields keep the same jstype code-generation option."
---

- **Rule ID:** `FIELD_SAME_JSTYPE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that fields preserve their `[jstype = ...]` option (`JS_NORMAL`, `JS_STRING`, or `JS_NUMBER`). Changing `jstype` alters generated JavaScript/TypeScript field types for 64-bit integer fields.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message Account {
  int64 balance_cents = 1 [jstype = JS_STRING];
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message Account {
  int64 balance_cents = 1 [jstype = JS_NUMBER];
}
```

**Error:**

```text
account.proto:6:3: Field "myapi.v1.Account.balance_cents" changed jstype option. (FIELD_SAME_JSTYPE)
```

### Good

Keep `[jstype = ...]` unchanged on existing fields:

```proto
syntax = "proto3";

package myapi.v1;

message Account {
  int64 balance_cents = 1 [jstype = JS_STRING];
}
```
