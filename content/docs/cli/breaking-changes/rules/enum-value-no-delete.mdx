---
title: "Enum Value No Delete"
description: "Checks that no enum values are deleted in source-compatibility profiles."
---

- **Rule ID:** `ENUM_VALUE_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that no enum values are deleted from an enum. Deleting an enum value removes the corresponding generated constant and breaks client code that references it (such as `switch` statements or comparisons).

<Callout type="info">
Adding `reserved` for a deleted enum number or name does **not** satisfy `ENUM_VALUE_NO_DELETE` in `FILE` or `PACKAGE` profiles, because generated source constants are still removed. Reserving deleted enum numbers (and names for JSON) only satisfies [`ENUM_VALUE_NO_DELETE_UNLESS_NUMBER_RESERVED`](/docs/cli/breaking-changes/rules/enum-value-no-delete-unless-number-reserved) (`WIRE`, `WIRE_JSON`) and [`ENUM_VALUE_NO_DELETE_UNLESS_NAME_RESERVED`](/docs/cli/breaking-changes/rules/enum-value-no-delete-unless-name-reserved) (`WIRE_JSON`).
</Callout>

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
  ORDER_STATUS_CANCELLED = 5;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  reserved 5;
  reserved "ORDER_STATUS_CANCELLED";

  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
}
```

**Error:**

```text
order.proto:5:1: Enum value "ORDER_STATUS_CANCELLED" = 5 in "myapi.v1.OrderStatus" was deleted. (ENUM_VALUE_NO_DELETE)
```

### Good

Keep the enum value and mark it deprecated instead of deleting it in `FILE`/`PACKAGE` profiles:

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
  ORDER_STATUS_CANCELLED = 5 [deprecated = true];
}
```

## Migration Strategy

1. Deprecate the enum value with `[deprecated = true]` and stop producing it in new code.
2. Keep handling the deprecated value while existing stored data or older clients still use it.
3. If your policy uses `WIRE` or `WIRE_JSON`, reserve the deleted number (and name for `WIRE_JSON`) when removing the value; if your policy uses `FILE` or `PACKAGE`, remove it only in a new major package version (for example, `myapi.v2`).
