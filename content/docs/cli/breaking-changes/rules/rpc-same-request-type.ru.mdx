---
title: "Rpc Same Request Type"
description: "Проверяет, что каждый RPC-метод сохраняет то же полное имя типа сообщения запроса."
---

- **ID правила:** `RPC_SAME_REQUEST_TYPE`
- **Профили:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

Это правило проверяет, что RPC-метод сохраняет прежнее полное имя типа сообщения запроса. Изменение типа запроса ломает сигнатуры методов в сгенерированном коде и может сделать запросы существующих клиентов несовместимыми с сервером.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserRequest {
  string user_id = 1;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequestV2) returns (GetUserResponse);
}

message GetUserRequestV2 {
  string id = 1;
  bool include_profile = 2;
}
```

**Ошибка:**

```text
user_service.proto:6:3: RPC "GetUser" request type changed from "myapi.v1.GetUserRequest" to "myapi.v1.GetUserRequestV2". (RPC_SAME_REQUEST_TYPE)
```

### Правильно

Если изменение аддитивно, просто добавьте новые поля в существующее сообщение запроса:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserRequest {
  string user_id = 1;
  bool include_profile = 2;
}
```

Если требуется полностью новая структура запроса, добавьте новый RPC-метод и пометьте старый как `deprecated`:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse) {
    option deprecated = true;
  }
  rpc GetUserV2(GetUserRequestV2) returns (GetUserResponse);
}
```
