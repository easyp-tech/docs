---
title: "Rpc Same Response Type"
description: "Проверяет, что каждый RPC-метод сохраняет то же полное имя типа сообщения ответа."
---

- **ID правила:** `RPC_SAME_RESPONSE_TYPE`
- **Профили:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

Это правило проверяет, что RPC-метод сохраняет прежнее полное имя типа сообщения ответа. Изменение типа ответа ломает сигнатуры методов в сгенерированном коде и может нарушить десериализацию ответов существующими клиентами.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserResponse {
  string user_id = 1;
  string name = 2;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponseV2);
}

message GetUserResponseV2 {
  string id = 1;
  string full_name = 2;
}
```

**Ошибка:**

```text
user_service.proto:6:3: RPC "GetUser" response type changed from "myapi.v1.GetUserResponse" to "myapi.v1.GetUserResponseV2". (RPC_SAME_RESPONSE_TYPE)
```

### Правильно

Если изменение аддитивно, добавьте новые поля в существующее сообщение ответа:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserResponse {
  string user_id = 1;
  string name = 2;
  string email = 3;
}
```

Если нужна совершенно новая структура ответа, добавьте новый RPC-метод и пометьте старый как `deprecated`:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse) {
    option deprecated = true;
  }
  rpc GetUserV2(GetUserRequest) returns (GetUserResponseV2);
}
```
