---
title: "Rpc No Delete"
description: "Checks that no RPC methods are deleted from a service."
---

- **Rule ID:** `RPC_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that no RPC methods are deleted from a `service`. Deleting an RPC breaks both generated client/server stubs and live RPC calls on the wire.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse);
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  // DeleteUser RPC was deleted
}
```

**Error:**

```text
services.proto:7:3: RPC "DeleteUser" on service "myapi.v1.UserService" was deleted. (RPC_NO_DELETE)
```

### Good

Mark the RPC deprecated instead of deleting it:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
  rpc DeleteUser(DeleteUserRequest) returns (DeleteUserResponse) {
    option deprecated = true;
  }
}
```

## Migration Strategy

1. Mark the RPC with `option deprecated = true;` and notify clients.
2. Keep the RPC handler returning a clear error or delegating to the replacement until clients migrate.
3. Remove the RPC only in a new major package version (for example, `myapi.v2`).
