---
title: "Field Same Cardinality"
description: "Checks that fields keep the exact same cardinality and presence semantics in source-compatibility profiles."
---

- **Rule ID:** `FIELD_SAME_CARDINALITY`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that every field preserves its exact cardinality and presence model (`optional_implicit`, `optional_explicit`, `required`, `repeated`, or `map`).

In proto3, regular singular fields (such as `string email = 2;`) are **not** `required` — they use **implicit presence** (`optional_implicit`), while `optional string email = 2;` uses **explicit presence** (`optional_explicit`). Changing between implicit and explicit presence changes generated code types and accessors (for example, `string` vs `*string` in Go), so `FIELD_SAME_CARDINALITY` rejects it in `FILE` and `PACKAGE` profiles.

<Callout type="info">
Toggling between implicit and explicit `optional` presence (`string` ↔ `optional string`) is wire- and JSON-compatible, so it is allowed in `WIRE` and `WIRE_JSON` profiles (see [`FIELD_WIRE_COMPATIBLE_CARDINALITY`](/docs/cli/breaking-changes/rules/field-wire-compatible-cardinality) and [`FIELD_WIRE_JSON_COMPATIBLE_CARDINALITY`](/docs/cli/breaking-changes/rules/field-wire-json-compatible-cardinality)).
</Callout>

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  string email = 2;
  repeated string tags = 3;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  optional string email = 2; // optional_implicit -> optional_explicit
  string tags = 3;           // repeated -> optional_implicit
}
```

**Error:**

```text
user.proto:7:3: Field "email" (2) on "myapi.v1.User" changed cardinality from optional_implicit to optional_explicit. (FIELD_SAME_CARDINALITY)
user.proto:8:3: Field "tags" (3) on "myapi.v1.User" changed cardinality from repeated to optional_implicit. (FIELD_SAME_CARDINALITY)
```

### Good

Keep the existing field's cardinality unchanged and add a new field with the desired cardinality:

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  string email = 2 [deprecated = true];
  repeated string tags = 3;
  optional string email_address = 4;
}
```

## Cardinality Matrix (`FILE` / `PACKAGE` vs `WIRE_JSON` / `WIRE`)

| Transition | `FILE` / `PACKAGE` | `WIRE_JSON` | `WIRE` |
| --- | --- | --- | --- |
| `optional_implicit` ↔ `optional_explicit` | Reject | Allow | Allow |
| `repeated` ↔ `map` (compatible entry message) | Reject | Reject | Allow |
| `singular` ↔ `repeated` or `map` | Reject | Reject | Reject |
| `required` ↔ anything else | Reject | Reject | Reject |
