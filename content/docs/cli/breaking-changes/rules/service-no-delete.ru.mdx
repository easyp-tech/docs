---
title: "Service No Delete"
description: "Проверяет, что ни одно объявление сервиса не было удалено."
---

- **ID правила:** `SERVICE_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

Это правило проверяет, что ни одно объявление `service` не было удалено. Удаление сервиса убирает сгенерированные клиентские и серверные интерфейсы и ломает все RPC-эндпоинты этого сервиса.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

service OrderService {
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse);
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

// Сервис OrderService удалён
```

**Ошибка:**

```text
services.proto:9:1: Service "myapi.v1.OrderService" was deleted. (SERVICE_NO_DELETE)
```

### Правильно

Вместо удаления пометьте сервис как устаревший:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

service OrderService {
  option deprecated = true;
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse) {
    option deprecated = true;
  }
}
```

## Стратегия миграции

1. Пометьте сервис опцией `option deprecated = true;` и сообщите клиентам о сроках вывода из эксплуатации.
2. Сохраняйте сервис активным до завершения миграции клиентов.
3. Удалите сервис только в новой мажорной версии пакета (например, `myapi.v2`).
