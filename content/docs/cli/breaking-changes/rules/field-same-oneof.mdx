---
title: "Field Same Oneof"
description: "Checks that fields do not move into, out of, or between real oneof blocks."
---

- **Rule ID:** `FIELD_SAME_ONEOF`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that a field keeps the same real `oneof` membership (synthetic oneofs created by proto3 `optional` fields are ignored). Moving a field into a `oneof`, moving it out of a `oneof`, or moving it to a different `oneof` changes mutual-exclusivity semantics and generated types across all four profiles (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message Contact {
  oneof destination {
    string email = 1;
    string phone = 2;
  }
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message Contact {
  oneof destination {
    string email = 1;
  }
  string phone = 2;
}
```

**Error:**

```text
contact.proto:8:5: Field "phone" (2) changed real oneof membership. (FIELD_SAME_ONEOF)
```

### Good

Keep existing fields in their original `oneof` and add new fields outside or inside a new `oneof`:

```proto
syntax = "proto3";

package myapi.v1;

message Contact {
  oneof destination {
    string email = 1;
    string phone = 2 [deprecated = true];
  }
  string secondary_phone = 3;
}
```
