---
title: "Rpc Same Request Type"
description: "Checks that every RPC method keeps the same fully qualified request message type."
---

- **Rule ID:** `RPC_SAME_REQUEST_TYPE`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that an RPC method keeps the same fully qualified request message type. Changing the request type breaks generated client/server method signatures and can invalidate serialized requests sent by existing clients.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserRequest {
  string user_id = 1;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequestV2) returns (GetUserResponse);
}

message GetUserRequestV2 {
  string id = 1;
  bool include_profile = 2;
}
```

**Error:**

```text
user_service.proto:6:3: RPC "GetUser" request type changed from "myapi.v1.GetUserRequest" to "myapi.v1.GetUserRequestV2". (RPC_SAME_REQUEST_TYPE)
```

### Good

Extend the existing request message with new fields when the change is additive:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

message GetUserRequest {
  string user_id = 1;
  bool include_profile = 2;
}
```

Or add a new RPC method alongside the deprecated original when a completely new request message is required:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse) {
    option deprecated = true;
  }
  rpc GetUserV2(GetUserRequestV2) returns (GetUserResponse);
}
```
