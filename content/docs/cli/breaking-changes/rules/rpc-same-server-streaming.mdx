---
title: "Rpc Same Server Streaming"
description: "Checks that RPC methods do not change server streaming behavior."
---

- **Rule ID:** `RPC_SAME_SERVER_STREAMING`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that an RPC method does not toggle `stream` on its response type. Switching between unary and server-streaming breaks both live RPC framing and generated client/server interfaces across all four profiles (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

service EventService {
  rpc WatchEvents(WatchEventsRequest) returns (WatchEventsResponse);
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

service EventService {
  rpc WatchEvents(WatchEventsRequest) returns (stream WatchEventsResponse);
}
```

**Error:**

```text
event.proto:6:3: RPC "WatchEvents" changed server streaming behavior. (RPC_SAME_SERVER_STREAMING)
```

### Good

Add a new server-streaming RPC method instead of altering an existing unary RPC:

```proto
syntax = "proto3";

package myapi.v1;

service EventService {
  rpc WatchEvents(WatchEventsRequest) returns (WatchEventsResponse);
  rpc StreamEvents(StreamEventsRequest) returns (stream StreamEventsResponse);
}
```
