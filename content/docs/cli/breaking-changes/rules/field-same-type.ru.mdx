---
title: "Field Same Type"
description: "Проверяет, что поля сохраняют точный protobuf-тип в профилях совместимости исходного кода."
---

- **ID правила:** `FIELD_SAME_TYPE`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что поля сообщений и расширений сохраняют точный protobuf-тип (скалярный тип или полное имя сообщения/enum). Изменение типа поля ломает сгенерированный исходный код, поскольку меняются типы полей и сигнатуры методов доступа.

<Callout type="info">
`FIELD_SAME_TYPE` требует строгого совпадения типов в профилях `FILE` и `PACKAGE` — даже для wire-совместимых переходов (например, `int32` → `int64` или `int32` → `uint32`). Если требуется проверять бинарную или JSON-совместимость вместо совместимости сгенерированного кода, используйте профили `WIRE` или `WIRE_JSON`:

- [`FIELD_WIRE_COMPATIBLE_TYPE`](/ru/docs/cli/breaking-changes/rules/field-wire-compatible-type) (`WIRE`) допускает бинарно совместимые переходы: `int32` ↔ `uint32` ↔ `int64` ↔ `uint64` ↔ `bool`, `sint32` ↔ `sint64`, `fixed32` ↔ `sfixed32`, `fixed64` ↔ `sfixed64`, `string` → `bytes`, а также структурно совместимые сообщения и enum.
- [`FIELD_WIRE_JSON_COMPATIBLE_TYPE`](/ru/docs/cli/breaking-changes/rules/field-wire-json-compatible-type) (`WIRE_JSON`) допускает `int32` ↔ `uint32`, `int64` ↔ `uint64`, `fixed32` ↔ `sfixed32`, `fixed64` ↔ `sfixed64` и JSON-совместимые сообщения/enum (отклоняя `int32` → `int64`, так как 64-битные числа сериализуются в JSON строками, и `string` → `bytes`, так как `bytes` кодируется в base64).
</Callout>

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  int32 price = 2;
  bool available = 3;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  string price = 2; // Изменено с int32 на string
  bool available = 3;
}
```

**Ошибка:**

```text
product.proto:7:3: Field "price" (2) on "myapi.v1.Product" changed type from int32 to string. (FIELD_SAME_TYPE)
```

### Правильно

Добавьте новое поле с нужным типом и пометьте старое как `deprecated`:

```proto
syntax = "proto3";

package myapi.v1;

message Product {
  string name = 1;
  int32 price = 2 [deprecated = true];
  bool available = 3;
  string price_formatted = 4;
}
```

Либо измените тип поля в новой мажорной версии пакета (например, `myapi.v2`).
