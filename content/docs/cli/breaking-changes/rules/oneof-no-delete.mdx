---
title: "Oneof No Delete"
description: "Checks that no real oneof blocks are deleted from messages."
---

- **Rule ID:** `ONEOF_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that no real `oneof` declarations are deleted from a message (synthetic oneofs created by proto3 `optional` fields are ignored). Deleting a `oneof` removes generated wrapper types and breaks mutual-exclusivity semantics.

<Callout type="info">
Moving existing fields out of a real `oneof` also triggers [`FIELD_SAME_ONEOF`](/docs/cli/breaking-changes/rules/field-same-oneof) across all four profiles (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).
</Callout>

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;

  oneof credentials {
    string password = 2;
    string api_key = 3;
  }
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;
  string password = 2;
  string api_key = 3;
}
```

**Error:**

```text
login.proto:8:3: Oneof "credentials" on "myapi.v1.LoginRequest" was deleted. (ONEOF_NO_DELETE)
```

### Good

Keep the existing `oneof`, deprecate its fields (note that Protobuf does not support `option deprecated = true;` directly on a `oneof`), and introduce a replacement `oneof` if needed:

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;

  oneof credentials {
    string password = 2 [deprecated = true];
    string api_key = 3 [deprecated = true];
  }

  oneof auth_method {
    string password_v2 = 4;
    string oauth_token = 5;
  }
}
```
