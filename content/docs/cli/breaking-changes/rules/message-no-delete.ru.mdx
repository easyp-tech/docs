---
title: "Message No Delete"
description: "Проверяет, что ни одно объявление сообщения (верхнего уровня или вложенное) не было удалено."
---

- **ID правила:** `MESSAGE_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что из protobuf-пакета не удалено ни одно объявление `message` (верхнего уровня или вложенное; синтетические entry-сообщения `map` не проверяются). Удаление сообщения убирает сгенерированные типы и ломает компиляцию клиентов.

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

message Address {
  string street = 1;
  string city = 2;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

// Сообщение Address удалено
```

**Ошибка:**

```text
user.proto:9:1: Message "myapi.v1.Address" was deleted. (MESSAGE_NO_DELETE)
```

### Правильно

Вместо удаления пометьте сообщение как устаревшее в текущей мажорной версии:

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

message Address {
  option deprecated = true;
  string street = 1;
  string city = 2;
}

message AddressV2 {
  string street_address = 1;
  string city = 2;
  string postal_code = 3;
}
```

## Стратегия миграции

1. Добавьте `option deprecated = true;` к сообщению и пометьте устаревшими поля, которые на него ссылаются.
2. При необходимости введите новое сообщение-замену.
3. Удалите устаревшее сообщение только в новой мажорной версии пакета (например, `myapi.v2`).
