---
title: "Message No Delete"
description: "Checks that no top-level or nested message declarations are deleted."
---

- **Rule ID:** `MESSAGE_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that no top-level or nested `message` declarations are deleted from a protobuf package (synthetic map-entry messages are excluded). Deleting a message removes generated types and breaks compilation for consumers referencing it.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

message Address {
  string street = 1;
  string city = 2;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

// Address message was deleted
```

**Error:**

```text
user.proto:9:1: Message "myapi.v1.Address" was deleted. (MESSAGE_NO_DELETE)
```

### Good

Mark the message deprecated instead of deleting it in the same major version:

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
}

message Address {
  option deprecated = true;
  string street = 1;
  string city = 2;
}

message AddressV2 {
  string street_address = 1;
  string city = 2;
  string postal_code = 3;
}
```

## Migration Strategy

1. Add `option deprecated = true;` to the message and deprecate fields referencing it.
2. Introduce a replacement message if needed.
3. Remove the deprecated message only in a new major package version (for example, `myapi.v2`).
