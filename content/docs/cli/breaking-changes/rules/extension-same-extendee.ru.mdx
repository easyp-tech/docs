---
title: "Extension Same Extendee"
description: "Проверяет, что расширения продолжают расширять то же целевое сообщение."
---

- **ID правила:** `EXTENSION_SAME_EXTENDEE`
- **Профили:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

Это правило проверяет, что расширение продолжает относиться к тому же целевому сообщению (extendee). Перенос расширения на другое сообщение ломает и бинарную сериализацию, и сгенерированный код во всех четырёх профилях (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.FieldOptions {
  bool sensitive = 50001;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.MessageOptions {
  bool sensitive = 50001;
}
```

**Ошибка:**

```text
options.proto:8:3: Extension "myapi.v1.sensitive" changed the extended message. (EXTENSION_SAME_EXTENDEE)
```

### Правильно

Сохраните исходное расширение на его целевом сообщении и объявите новое расширение с другим именем для нового целевого сообщения:

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.FieldOptions {
  bool sensitive = 50001;
}

extend google.protobuf.MessageOptions {
  bool message_sensitive = 50001;
}
```
