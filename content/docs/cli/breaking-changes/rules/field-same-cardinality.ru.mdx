---
title: "Field Same Cardinality"
description: "Проверяет, что поля сохраняют точную кардинальность и модель присутствия в профилях совместимости исходного кода."
---

- **ID правила:** `FIELD_SAME_CARDINALITY`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что каждое поле сохраняет точную кардинальность и модель присутствия (`optional_implicit`, `optional_explicit`, `required`, `repeated` или `map`).

В proto3 обычные одиночные поля (например, `string email = 2;`) **не являются** `required` — у них **неявное присутствие** (`optional_implicit`), тогда как у `optional string email = 2;` — **явное присутствие** (`optional_explicit`). Переключение между неявным и явным присутствием меняет типы и методы в сгенерированном коде (например, `string` и `*string` в Go), поэтому `FIELD_SAME_CARDINALITY` отклоняет такое изменение в профилях `FILE` и `PACKAGE`.

<Callout type="info">
Переключение между неявным и явным `optional` (`string` ↔ `optional string`) совместимо по бинарному формату и JSON, поэтому допускается в профилях `WIRE` и `WIRE_JSON` (см. [`FIELD_WIRE_COMPATIBLE_CARDINALITY`](/ru/docs/cli/breaking-changes/rules/field-wire-compatible-cardinality) и [`FIELD_WIRE_JSON_COMPATIBLE_CARDINALITY`](/ru/docs/cli/breaking-changes/rules/field-wire-json-compatible-cardinality)).
</Callout>

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  string email = 2;
  repeated string tags = 3;
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  optional string email = 2; // optional_implicit -> optional_explicit
  string tags = 3;           // repeated -> optional_implicit
}
```

**Ошибка:**

```text
user.proto:7:3: Field "email" (2) on "myapi.v1.User" changed cardinality from optional_implicit to optional_explicit. (FIELD_SAME_CARDINALITY)
user.proto:8:3: Field "tags" (3) on "myapi.v1.User" changed cardinality from repeated to optional_implicit. (FIELD_SAME_CARDINALITY)
```

### Правильно

Сохраните кардинальность существующего поля и добавьте новое поле с нужной семантикой:

```proto
syntax = "proto3";

package myapi.v1;

message User {
  string name = 1;
  string email = 2 [deprecated = true];
  repeated string tags = 3;
  optional string email_address = 4;
}
```

## Матрица переходов (`FILE` / `PACKAGE` против `WIRE_JSON` / `WIRE`)

| Переход | `FILE` / `PACKAGE` | `WIRE_JSON` | `WIRE` |
| --- | --- | --- | --- |
| `optional_implicit` ↔ `optional_explicit` | Ошибка | Допустимо | Допустимо |
| `repeated` ↔ `map` (совместимое entry-сообщение) | Ошибка | Ошибка | Допустимо |
| одиночное ↔ `repeated` или `map` | Ошибка | Ошибка | Ошибка |
| `required` ↔ любой другой вариант | Ошибка | Ошибка | Ошибка |
