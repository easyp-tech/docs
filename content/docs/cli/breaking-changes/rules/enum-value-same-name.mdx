---
title: "Enum Value Same Name"
description: "Checks that existing enum values keep the same name for each number."
---

- **Rule ID:** `ENUM_VALUE_SAME_NAME`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`

This rule checks that existing enum `(name, number)` pairs are not renamed. Changing an enum value's name breaks generated constants and protobuf JSON serialization (which uses enum value names). In the `WIRE` profile, enum values are encoded by number only, so renaming is not flagged there.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_APPROVED = 2; // Renamed from ORDER_STATUS_CONFIRMED
}
```

**Error:**

```text
order.proto:5:1: Enum value "ORDER_STATUS_CONFIRMED" at number 2 in "myapi.v1.OrderStatus" changed name to "ORDER_STATUS_APPROVED". (ENUM_VALUE_SAME_NAME)
```

### Good

Add a new enum value and deprecate the old one:

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2 [deprecated = true];
  ORDER_STATUS_APPROVED = 3;
}
```

Or keep the original `(name, number)` pair alongside an alias when `option allow_alias = true;` is permitted in your project (note that the lint rule [`ENUM_NO_ALLOW_ALIAS`](/docs/cli/linter/rules/enum-no-allow-alias) discourages aliases):

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  option allow_alias = true;
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
  ORDER_STATUS_CONFIRMED = 2 [deprecated = true];
  ORDER_STATUS_APPROVED = 2;
}
```
