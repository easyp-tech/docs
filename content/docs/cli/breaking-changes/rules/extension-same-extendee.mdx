---
title: "Extension Same Extendee"
description: "Checks that extensions keep extending the same target message."
---

- **Rule ID:** `EXTENSION_SAME_EXTENDEE`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that an extension field keeps extending the same target message (extendee). Moving an extension to extend a different message breaks both wire serialization and generated extension types across all four profiles (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.FieldOptions {
  bool sensitive = 50001;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.MessageOptions {
  bool sensitive = 50001;
}
```

**Error:**

```text
options.proto:8:3: Extension "myapi.v1.sensitive" changed the extended message. (EXTENSION_SAME_EXTENDEE)
```

### Good

Keep the original extension on its original target message and define a differently named extension for the new target:

```proto
syntax = "proto3";

package myapi.v1;

import "google/protobuf/descriptor.proto";

extend google.protobuf.FieldOptions {
  bool sensitive = 50001;
}

extend google.protobuf.MessageOptions {
  bool message_sensitive = 50001;
}
```
