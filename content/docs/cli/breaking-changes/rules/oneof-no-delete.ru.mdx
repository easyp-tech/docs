---
title: "Oneof No Delete"
description: "Проверяет, что ни один настоящий блок oneof не был удалён из сообщения."
---

- **ID правила:** `ONEOF_NO_DELETE`
- **Профили:** `FILE`, `PACKAGE`

Это правило проверяет, что из сообщения не удалён ни один настоящий блок `oneof` (синтетические oneof для полей `optional` в proto3 не учитываются). Удаление `oneof` убирает сгенерированные типы-обёртки и нарушает семантику взаимной исключаемости.

<Callout type="info">
Вынос существующих полей из настоящего `oneof` дополнительно вызывает срабатывание [`FIELD_SAME_ONEOF`](/ru/docs/cli/breaking-changes/rules/field-same-oneof) во всех четырёх профилях (`FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`).
</Callout>

## Примеры

### Неправильно

**До:**

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;

  oneof credentials {
    string password = 2;
    string api_key = 3;
  }
}
```

**После:**

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;
  string password = 2;
  string api_key = 3;
}
```

**Ошибка:**

```text
login.proto:8:3: Oneof "credentials" on "myapi.v1.LoginRequest" was deleted. (ONEOF_NO_DELETE)
```

### Правильно

Сохраните существующий `oneof`, пометьте его поля опцией `[deprecated = true]` (в Protobuf нельзя задать `option deprecated = true;` непосредственно на самом блоке `oneof`), и при необходимости добавьте новый `oneof`:

```proto
syntax = "proto3";

package myapi.v1;

message LoginRequest {
  string username = 1;

  oneof credentials {
    string password = 2 [deprecated = true];
    string api_key = 3 [deprecated = true];
  }

  oneof auth_method {
    string password_v2 = 4;
    string oauth_token = 5;
  }
}
```
