---
title: "Enum No Delete"
description: "Checks that no top-level or nested enum declarations are deleted."
---

- **Rule ID:** `ENUM_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`

This rule checks that no top-level or nested `enum` declarations are deleted from a protobuf package. Deleting an enum removes generated enum types and constants, breaking compilation for consumers that reference it.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

enum UserRole {
  USER_ROLE_UNSPECIFIED = 0;
  USER_ROLE_ADMIN = 1;
  USER_ROLE_USER = 2;
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

// UserRole enum was deleted
```

**Error:**

```text
order.proto:10:1: Enum "myapi.v1.UserRole" was deleted. (ENUM_NO_DELETE)
```

### Good

Keep the enum and mark it deprecated instead of deleting it in the same major version:

```proto
syntax = "proto3";

package myapi.v1;

enum OrderStatus {
  ORDER_STATUS_UNSPECIFIED = 0;
  ORDER_STATUS_PENDING = 1;
}

enum UserRole {
  option deprecated = true;
  USER_ROLE_UNSPECIFIED = 0;
  USER_ROLE_ADMIN = 1;
  USER_ROLE_USER = 2;
}

enum UserPermission {
  USER_PERMISSION_UNSPECIFIED = 0;
  USER_PERMISSION_READ = 1;
  USER_PERMISSION_WRITE = 2;
}
```

## Migration Strategy

1. Mark the old enum with `option deprecated = true;` and deprecate any fields referencing it.
2. Introduce a replacement enum (if needed) alongside the deprecated one.
3. Remove the deprecated enum only in a new major package version (for example, `myapi.v2`).
