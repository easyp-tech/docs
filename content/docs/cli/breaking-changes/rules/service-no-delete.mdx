---
title: "Service No Delete"
description: "Checks that no service declarations are deleted."
---

- **Rule ID:** `SERVICE_NO_DELETE`
- **Profiles:** `FILE`, `PACKAGE`, `WIRE_JSON`, `WIRE`

This rule checks that no `service` declarations are deleted. Deleting a service removes generated client/server interfaces and breaks all RPC endpoints exposed under that service name.

## Examples

### Bad

**Before:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

service OrderService {
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse);
}
```

**After:**

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

// OrderService was deleted
```

**Error:**

```text
services.proto:9:1: Service "myapi.v1.OrderService" was deleted. (SERVICE_NO_DELETE)
```

### Good

Mark the service deprecated instead of deleting it:

```proto
syntax = "proto3";

package myapi.v1;

service UserService {
  rpc GetUser(GetUserRequest) returns (GetUserResponse);
}

service OrderService {
  option deprecated = true;
  rpc GetOrder(GetOrderRequest) returns (GetOrderResponse) {
    option deprecated = true;
  }
}
```

## Migration Strategy

1. Mark the service with `option deprecated = true;` and communicate the sunset schedule.
2. Keep the service registered until active clients migrate.
3. Remove the service only in a new major package version (for example, `myapi.v2`).
