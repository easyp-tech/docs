---
title: "Linter"
description: "Configure and run the EasyP v1 protobuf linter."
---

`easyp lint` checks `.proto` files using the v1 policy in `easyp.yaml`. It reports source locations and rule names for findings.

```yaml
# easyp.yaml
version: v1
linters:
  default: STANDARD
  enable: [COMMENT_SERVICE]
  disable: [SERVICE_SUFFIX]
linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
issues:
  exclude-rules:
    - linters: [COMMENT_FIELD]
```

The available presets are `MINIMAL`, `BASIC`, `STANDARD`, and `COMMENTS`. `enable` and `disable` add or remove individual rules. The pilot supports `ENUM_ZERO_VALUE_SUFFIX.suffix` and `SERVICE_SUFFIX.suffix` settings. Pathless `issues.exclude-rules` apply to every scanned file; path globs and `linters.extends` are not implemented yet and produce an error.

```bash
easyp lint --path proto
easyp --format json lint --path proto
easyp lint --root ./contracts --path proto
```

`--path` is relative to the scan root. By default the scan root is the directory of the selected policy file; `--root` changes it. The linter uses the nearest module's source roots and local or locked dependency roots to resolve imports. A policy can also be used without `protobuf.mod`.

Nested `easyp.yaml` files may override policy sections for files beneath their directories. See the [`easyp.yaml` reference](/docs/reference/easyp-yaml) for the supported fields and merging rules.

The older `lint.use`, `lint.except`, and `lint.ignore_only` configuration is not accepted by the v1 CLI.
