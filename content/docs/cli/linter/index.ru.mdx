<code>easyp lint</code> проверяет <code>.proto</code> по политике v1 из <code>easyp.yaml</code>, указывая положение в исходнике и имя правила.

~~~yaml
version: v1
linters:
  default: STANDARD
  enable: [COMMENT_SERVICE]
  disable: [SERVICE_SUFFIX]
  allow_comment_ignores: true
linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
issues:
  exclude-rules:
    - path: legacy/**/*.proto
      linters: [COMMENT_FIELD]
    - path: generated
~~~

Пресеты: <code>MINIMAL</code>, <code>BASIC</code>, <code>STANDARD</code> и <code>COMMENTS</code>. Списки enable/disable и исключений принимают реализованные правила и группы. Повторы не добавляют проверок; отключение приоритетнее включения. Неизвестные имена — ошибки, даже если повторены в противоположном списке. <code>PACKAGE_NO_IMPORT_CYCLE</code> зарезервировано и выбирать его нельзя. Поддерживаются настройки <code>ENUM_ZERO_VALUE_SUFFIX.suffix</code> и <code>SERVICE_SUFFIX.suffix</code>. <code>linters.extends</code> подключает локальную или закреплённую базу перед локальными изменениями; см. [общие политики](/ru/docs/guides/organization-lint-style).

~~~bash
easyp lint --path proto
easyp --format json lint --path proto
easyp lint --root ./contracts --path proto
~~~

<code>--path</code> считается от корня проверки, по умолчанию — каталога выбранной политики; <code>--root</code> меняет его. Поиск политики идёт вверх в пределах workspace. Без политики в предках можно выбрать одну однозначную внешнюю политику в потомках; несколько независимых политик требуют <code>--cfg</code>. Явный конфиг имеет приоритет. Каждая вложенная секция целиком заменяет ближайшую унаследованную секцию.

Для импортов линтер использует корни ближайшего модуля и его локальные или зафиксированные зависимости. Политика может работать без <code>protobuf.mod</code>. Вендорные исходники и скрытые каталоги хранилищ/Git исключены из поиска целей линтинга, включая явные пути в vendor; зависимости остаются доступными для импортов.

## Исключение путей

<code>issues.exclude-rules.path</code> считается от файла политики, предоставляющего эффективную секцию <code>issues</code>, в том числе унаследованную. Поддерживаются <code>&#42;</code>, <code>?</code>, <code>[]</code> и полные сегменты <code>&#42;&#42;</code>. Односегментные шаблоны не пересекают <code>/</code>; <code>&#42;&#42;</code> совпадает с нулём или более сегментами. Буквальный каталог включает своё поддерево. Буквальный путь с окончанием <code>.proto</code> совпадает только с файлом. Абсолютные пути, обратные слеши, переходы к родителю и некорректные шаблоны отклоняются.

Правило без пути действует на все файлы этой секции issues. Пустой или отсутствующий <code>linters</code> исключает совпавшие файлы целиком. Пустое правило <code>&#123;&#125;</code> явно исключает все файлы. Вложенная <code>issues: &#123;&#125;</code> очищает унаследованные исключения. В примере у legacy-файлов подавляется только <code>COMMENT_FIELD</code>, а поддерево generated исключено полностью.

## Подавление комментариями

~~~proto
// easyp:disable FIELD_LOWER_SNAKE_CASE
message Example {
  string legacyField = 1;
}

message Another {
  string legacyField = 1; // easyp:disable FIELD_LOWER_SNAKE_CASE
}

// easyp:disable MESSAGE_PASCAL_CASE
message old_name {}
message another_old_name {}
// easyp:enable MESSAGE_PASCAL_CASE
~~~

Непарный disable должен аннотировать объявление и действует на его строку или блок. Пара disable/enable ограничивает регион в одном файле; вложенные регионы одного правила сбалансированы. Подавления не переходят в другие файлы или политики. Имена правил разделяются запятыми или пробелами; группы в директивах комментариев не принимаются.

Старые <code>nolint:RULE</code> и <code>buf:lint:ignore RULE</code> остаются аннотациями объявлений. Пояснение можно добавить после отделённого пробелами <code>--</code> или <code>//</code>. Интерпретируются только разобранные комментарии. Пустые директивы, неизвестные правила, неподдерживаемые действия и enable без пары — ошибки с координатами исходника.

<code>linters.allow_comment_ignores</code> по умолчанию равен true для каждой эффективной политики. False отключает подавление комментариями в этой политике; некорректные директивы в проверяемых файлах остаются ошибками.

См. [справочник политики](/ru/docs/reference/easyp-yaml). Старые поля <code>lint.use</code>, <code>lint.except</code> и <code>lint.ignore_only</code> CLI v1 не принимает.
