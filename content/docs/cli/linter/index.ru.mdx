`easyp lint` проверяет `.proto`-файлы по политике v1 из `easyp.yaml`, указывая положение в исходнике и имя правила.

```yaml
version: v1
linters:
  default: STANDARD
  enable: [COMMENT_SERVICE]
  disable: [SERVICE_SUFFIX]
  allow_comment_ignores: true
linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
issues:
  exclude-rules:
    - path: legacy/**/*.proto
      linters: [COMMENT_FIELD]
    - path: generated
```

## Пресеты и группы правил

EasyP включает **44 правила линтинга**, разделённые на **5 выбираемых групп**, из которых собираются **4 пресета `linters.default`**:

### Пресеты `linters.default`

| Пресет | Входящие группы | Правил | Примечание |
| --- | --- | ---: | --- |
| `MINIMAL` | `MINIMAL` | 5 | Структура пакетов и каталогов, циклы импортов |
| `BASIC` | `MINIMAL`, `BASIC` | 27 | Базовый стиль, синтаксис, именование и опции пакетов для языков |
| `STANDARD` | `MINIMAL`, `BASIC`, `DEFAULT` | 35 | Пресет по умолчанию, если `linters.default` не задан |
| `COMMENTS` | `MINIMAL`, `BASIC`, `DEFAULT`, `COMMENTS` | 42 | Добавляет обязательные комментарии к объявлениям |

### Выбираемые группы правил

| Группа | Правил | Назначение |
| --- | ---: | --- |
| `MINIMAL` | 5 | `DIRECTORY_SAME_PACKAGE`, `PACKAGE_DEFINED`, `PACKAGE_DIRECTORY_MATCH`, `PACKAGE_SAME_DIRECTORY`, `PACKAGE_NO_IMPORT_CYCLE` |
| `BASIC` | 22 | Соглашения об именах, чистота импортов, `SYNTAX_SPECIFIED`, `FIELD_NOT_REQUIRED` и согласованность языковых опций пакетов |
| `DEFAULT` | 8 | Имена файлов, префиксы/суффиксы enum, версионный суффикс пакета, суффикс сервисов и стандартные имена сообщений RPC |
| `COMMENTS` | 7 | Комментарии перед объявлениями enum, значений enum, полей, сообщений, oneof, RPC и сервисов |
| `UNARY_RPC` | 2 | Подключается отдельно через `linters.enable`: `RPC_NO_CLIENT_STREAMING` и `RPC_NO_SERVER_STREAMING` |

Списки `linters.enable`, `linters.disable` и `issues.exclude-rules[].linters` принимают как имена отдельных правил, так и ключи групп (`MINIMAL`, `BASIC`, `DEFAULT`, `COMMENTS`, `UNARY_RPC`). Повторы идемпотентны; отключение приоритетнее включения. Неизвестные имена отклоняются с ошибкой, даже если указаны в обоих списках.

Поддерживаются настройки в `linters-settings`: `ENUM_ZERO_VALUE_SUFFIX.suffix` (по умолчанию `NONE`) и `SERVICE_SUFFIX.suffix` (по умолчанию `Service`). `linters.extends` подключает локальную или закреплённую базу перед локальными изменениями; см. [общие политики](/ru/docs/guides/organization-lint-style).

## Запуск линтера

```bash
easyp lint --path proto
easyp --format json lint --path proto
easyp lint --root ./contracts --path proto
easyp lint --config ./policies/easyp.yaml --path proto
easyp lint --frozen --path proto
```

- `--path` (`-p`) задаёт файл или каталог относительно корня проверки (по умолчанию `.`).
- `--root` (`-r`) переопределяет корень проверки, который по умолчанию совпадает с каталогом выбранной политики.
- `--config` указывает явный файл политики вместо автоматического поиска `easyp.yaml`. Поиск идёт вверх в пределах workspace; без политики в предках может быть выбрана одна однозначная внешняя политика в потомках, а при нескольких независимых политиках требуется `--config`. Явный `--config` имеет приоритет. Каждая вложенная секция политики целиком заменяет ближайшую унаследованную секцию.
- `--frozen` требует наличия `protobuf.mod` и проверенного `protobuf.lock` без разрешения зависимостей, изменения файлов и локальных директив `replace`.

Для импортов линтер использует корни ближайшего модуля и его локальные или зафиксированные зависимости. Политика может работать и без `protobuf.mod` (если не передан `--frozen`). Вендорные исходники и скрытые каталоги хранилищ/Git исключены из поиска целей линтинга, включая явные пути в vendor; исходники зависимостей при этом остаются доступными для импортов.

<Callout type="info">
Перед запуском правил линтера EasyP компилирует и линкует проверяемые файлы. Если в файлах есть синтаксические ошибки, отсутствующие импорты или другие ошибки компиляции, EasyP выводит диагностики компилятора и пропускает выполнение правил линтинга до исправления ошибок компиляции.
</Callout>

## Исключение путей

`issues.exclude-rules.path` считается от файла политики, предоставляющего эффективную секцию `issues`, в том числе унаследованную. Поддерживаются `*`, `?`, `[]` и полные сегменты `**`. Односегментные шаблоны не пересекают `/`; `**` совпадает с нулём или более сегментами. Буквальный каталог включает своё поддерево. Буквальный путь с окончанием `.proto` совпадает только с этим файлом. Абсолютные пути, обратные слеши, переходы к родителю и некорректные шаблоны отклоняются.

Правило без пути действует на все файлы этой секции `issues`. Пустой или отсутствующий `linters` исключает совпавшие файлы целиком. Пустое правило `{}` явно исключает все файлы. Вложенная `issues: {}` очищает унаследованные исключения. В примере выше у legacy-файлов подавляется только `COMMENT_FIELD`, а поддерево `generated` исключено полностью.

## Подавление комментариями

```proto
// easyp:disable FIELD_LOWER_SNAKE_CASE
message Example {
  string legacyField = 1;
}

message Another {
  string legacyField = 1; // easyp:disable FIELD_LOWER_SNAKE_CASE
}

// easyp:disable MESSAGE_PASCAL_CASE
message old_name {}
message another_old_name {}
// easyp:enable MESSAGE_PASCAL_CASE
```

Непарный disable должен аннотировать объявление и действует на его строку или блок. Пара disable/enable ограничивает регион в одном файле; вложенные регионы одного правила сбалансированы. Подавления не переходят в другие файлы или политики. Имена правил разделяются запятыми или пробелами; группы в директивах комментариев не принимаются.

Старые `nolint:RULE` и `buf:lint:ignore RULE` остаются аннотациями объявлений. Пояснение можно добавить после отделённого пробелами `--` или `//`. Интерпретируются только разобранные комментарии. Пустые директивы, неизвестные правила, неподдерживаемые действия и enable без пары — ошибки с координатами исходника.

`linters.allow_comment_ignores` по умолчанию равен `true` для каждой эффективной политики. Значение `false` отключает подавление комментариями в этой политике; некорректные директивы в проверяемых файлах остаются ошибками.

См. [справочник политики](/ru/docs/reference/easyp-yaml). Старые поля `lint.use`, `lint.except` и `lint.ignore_only` CLI v1 не принимает.
