---
title: "Линтер"
description: "Настройка и запуск protobuf-линтера EasyP v1."
---

`easyp lint` проверяет `.proto` по политике v1 из `easyp.yaml`. В найденных проблемах указываются положение в исходнике и имя правила.

```yaml
# easyp.yaml
version: v1
linters:
  default: STANDARD
  enable: [COMMENT_SERVICE]
  disable: [SERVICE_SUFFIX]
linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
issues:
  exclude-rules:
    - linters: [COMMENT_FIELD]
```

Доступные наборы: `MINIMAL`, `BASIC`, `STANDARD`, `COMMENTS`. Поля `enable` и `disable` добавляют или исключают отдельные правила. Пилотная версия поддерживает настройки `ENUM_ZERO_VALUE_SUFFIX.suffix` и `SERVICE_SUFFIX.suffix`. Правила `issues.exclude-rules` без пути действуют на все проверяемые файлы. Глобы путей и `linters.extends` пока не реализованы и вызывают ошибку.

```bash
easyp lint --path proto
easyp --format json lint --path proto
easyp lint --root ./contracts --path proto
```

`--path` задаётся относительно корня проверки. По умолчанию корень — каталог выбранного файла политики; `--root` меняет его. Для импортов линтер использует корни ближайшего модуля и его локальных либо зафиксированных зависимостей. Политика может работать и без `protobuf.mod`.

Вложенные `easyp.yaml` могут переопределять секции политики для файлов в своих каталогах. Поддерживаемые поля и правила объединения описаны в [справочнике `easyp.yaml`](/ru/docs/reference/easyp-yaml).

Старые поля `lint.use`, `lint.except` и `lint.ignore_only` CLI v1 не принимает.
