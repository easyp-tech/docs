---

- **ID правила:** `PACKAGE_DIRECTORY_MATCH`
- **Группа:** `MINIMAL`
- **Входит в пресеты (`linters.default`):** `MINIMAL`, `BASIC`, `STANDARD`, `COMMENTS`

- **ID правила:** `PACKAGE_DIRECTORY_MATCH`
- **Группа:** `MINIMAL`
- **Входит в пресеты (`linters.default`):** `MINIMAL`, `BASIC`, `STANDARD`, `COMMENTS`

Это правило проверяет, что каждый `.proto`-файл находится в каталоге, путь которого соответствует объявленному `package` (с заменой `/` на `.`).

Если в проекте есть манифест `protobuf.mod`, EasyP принимает оба варианта:

- путь каталога относительно корня модуля (`<dir>`, например `users.v1` для `users/v1/user.proto`);
- квалифицированное именем модуля название `<moduleBase>.<dir>` (например `acme.users.v1`, если в `protobuf.mod` указано `module github.com/org/acme`; суффиксы мажорной версии `/v2+` и `.git` при этом отбрасываются).

## Примеры

### Неправильно

```proto
// File: bar/v1/foo.proto
syntax = "proto3";

package foo.v1;

message Foo {
  string bar = 1;
}
```

### Правильно

```proto
// File: bar/v1/foo.proto
syntax = "proto3";

package bar.v1;

message Foo {
  string bar = 1;
}
```

При `module github.com/org/acme` в `protobuf.mod`:

```proto
// File: bar/v1/foo.proto
syntax = "proto3";

package acme.bar.v1;

message Foo {
  string bar = 1;
}
```
