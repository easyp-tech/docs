---
title: "Генератор"
description: "Выбор проектов-потребителей, генерация protobuf-кода и экспорт дескрипторов в EasyP v1."
---

<code>easyp generate</code> выбирает ближайший <code>easyp.gen.yaml</code> в текущем или родительском каталоге в пределах workspace. Команда компилирует выбранные модули и запускает плагины этого проекта. Имена модулей, корни исходников и версии зависимостей берутся из <code>protobuf.mod</code> и <code>protobuf.lock</code>.

## Настройка модуля

~~~text
# protobuf.mod
module github.com/acme/contracts
roots proto
require github.com/acme/shared v1.2.0
~~~

~~~yaml
# easyp.gen.yaml
version: v1
plugins:
  - name: go
    out: ./gen/go
    opts:
      paths: source_relative
  - name: go-grpc
    out: ./gen/go
    opts:
      paths: source_relative
options:
  go:
    package_prefix: github.com/acme/contracts/gen/go
~~~

~~~bash
easyp mod tidy
easyp generate
~~~

Если <code>generate.modules</code> не указан, EasyP выбирает ближайший <code>protobuf.mod</code> рядом с файлом генератора или выше в пределах workspace; без манифеста корнем исходников становится каталог проекта. Явные элементы выбирают локальный модуль по имени, путь относительно workspace или зависимость из манифеста и lock потребителя. <code>generate.packages</code> выбирает точные имена protobuf-пакетов; пустой список означает все исходники модуля.

## Выбор проектов

~~~bash
# Только ближайший проект
easyp generate
# Ровно два указанных проекта
easyp generate --project backend --project frontend
# Явный рекурсивный выбор внутри каталога запуска
easyp generate --all
# Явная граница workspace, полезная вне Git
easyp generate --workspace ../.. --project ..
~~~

<code>--project</code> можно повторять, но нельзя сочетать с <code>--all</code>. Рекурсивный поиск пропускает скрытые каталоги, <code>easyp_vendor</code>, <code>node_modules</code> и вложенные Git-репозитории. Проект в пропускаемом каталоге можно выбрать явно. Автоматический выбор отклоняет конфигурацию-симлинк; для неё нужен явный выбор проекта. Флаг <code>--all</code> разрешает запуск плагинов найденных проектов, включая command-плагины.

Границу workspace задаёт ближайший Git-репозиторий, включая worktree с файлом <code>.git</code>. Без Git граница определяется по охватывающим конфигам и манифестам EasyP; <code>--workspace</code> задаёт её явно. Пути проектов и дескрипторов считаются от каталога запуска. Пути результатов плагинов считаются от их <code>easyp.gen.yaml</code>. Флагов <code>--path</code> и <code>--root</code> у команды нет.

## Генерация в режиме frozen

~~~bash
easyp generate --frozen --project backend --project frontend
easyp --frozen generate --all --descriptor_set_out_dir build/descriptors
~~~

Каждому выбранному локальному native-модулю нужны <code>protobuf.mod</code> и <code>protobuf.lock</code>, в том числе пустой lock без зависимостей. Явный путь от workspace использует файлы выбранного модуля: <code>backend/easyp.gen.yaml</code> с <code>generate.modules: [proto/user]</code> проверяет <code>proto/user/protobuf.mod</code> и <code>proto/user/protobuf.lock</code>. Самому каталогу <code>backend</code>, содержащему только настройки генератора, эти файлы не нужны. Frozen отклоняет все корневые замены, даже неиспользуемые, и проверяет зафиксированный граф прямых и транзитивных зависимостей до запуска любого плагина. Ошибка в проекте, выбранном позже, поэтому не даст запустить плагины более ранних проектов. Проверка действует для обоих режимов экспорта дескрипторов, включая экспорт без плагинов.

Зависимость, выбранная по идентификатору через <code>generate.modules</code>, требует манифест и lock потребителя; собственный lock в скачанной зависимости не требуется. Невыбранные проекты игнорируются. <code>--frozen</code> не меняет существующие правила выбора и разрешения запуска плагинов через <code>--project</code>/<code>--all</code>.

Точные коммиты из lock могут скачиваться в кеш; хеши проверяются и при повторном использовании кеша. Манифест и lock никогда не переписываются, HEAD/теги зависимостей не разрешаются. Frozen включается явно, а не по окружению CI; он не отключает сеть удалённым плагинам и не фиксирует локальные исполняемые файлы плагинов. Подробнее — в [менеджере пакетов](/ru/docs/cli/package-manager).

## Экспорт дескрипторов

~~~bash
easyp generate --project backend --descriptor_set_out build/backend.pb --include_imports
easyp generate --all --descriptor_set_out_dir build/descriptors --include_imports
~~~

<code>--descriptor_set_out</code> объединяет выбранные графы в один бинарный <code>FileDescriptorSet</code>. Одинаковые дескрипторы объединяются; разные определения под одним import path или конфликтующие символы вызывают ошибку. Managed-опции участвуют в проверке совместимости.

<code>--descriptor_set_out_dir</code> записывает отдельный набор для каждой выбранной пары проект/модуль, позволяя потребителям сохранять разные опции и версии зависимостей. Пути проектов повторяются внутри каталога назначения; имя файла содержит безопасное имя модуля и первые 12 hex-символов SHA-256 его полного идентификатора. Внешние проекты размещаются в <code>_external</code>. Посторонние существующие файлы сохраняются.

Флаги назначения взаимоисключающие. <code>--include_imports</code> по умолчанию равен false и добавляет транзитивные импорты только в экспортируемые файлы. Компиляция и проверка совместимости всегда используют полный граф.

Все выбранные графы и пути экспорта проверяются до запуска плагинов. Настроенные плагины всё равно запускаются; проект без плагинов тоже может экспортировать дескрипторы. Дескрипторы записываются после успешного выполнения всех выбранных плагинов с атомарной заменой каждого файла. Общей транзакции для побочных эффектов плагинов и ошибок файловой системы нет.

## Плагины и managed mode

Каждый плагин задаёт ровно один источник: <code>name</code>, <code>path</code>, <code>command</code> или <code>remote</code>. Локальные бинарные файлы и команды запускаются из каталога вызова EasyP. Удалённому плагину нужен зафиксированный SemVer в <code>version</code>; локальные и встроенные плагины отдельную версию не принимают.

<code>plugins[].with_imports</code> по умолчанию равен false. Значение true включает генерацию транзитивных импортов только для этого плагина. Остальные плагины по-прежнему получают дескрипторы зависимостей для связывания. Настройка независима от <code>--include_imports</code> при экспорте дескрипторов. Согласуйте Go import path и выходные каталоги: разные Go-пакеты не должны попадать в один каталог. Одинаковые общие результаты объединяются; конфликт содержимого файлов или объявлений Go-пакетов обнаруживается до записи сгенерированных файлов.

<code>options.go.package_prefix</code> меняет только Go-опции. Значения по умолчанию для других языков и преобразования опций полей требуют явного <code>generate.managed.enabled: true</code>. Унаследованный Go-префикс применяется до явных managed-переопределений Go; префикс текущего файла имеет наивысший приоритет. Go-селекторы disable продолжают действовать. Подробнее — в [справочнике конфигурации](/ru/docs/reference/easyp-gen-yaml).

Зависимости могут использовать метаданные EasyP v1, старого EasyP, Buf v1 или Buf v2. EasyP читает метаданные зависимостей, не запуская их плагины.
