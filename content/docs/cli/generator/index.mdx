---
title: "Generator"
description: "Generate code from complete protobuf modules with the EasyP v1 pilot."
---

`easyp generate` finds `easyp.gen.yaml` files beneath the current directory, selects complete modules, compiles their `.proto` files, and runs the listed plugins. Module identities, roots, and dependency versions come from `protobuf.mod` and `protobuf.lock`.

## Configure a module

```text
# protobuf.mod
module github.com/acme/contracts
roots proto
require github.com/acme/shared v1.2.0
```

```yaml
# easyp.gen.yaml
version: v1
generate:
  modules: [github.com/acme/contracts]
plugins:
  - name: go
    out: ./gen/go
    opts:
      paths: source_relative
  - name: go-grpc
    out: ./gen/go
    opts:
      paths: source_relative
```

```bash
easyp mod tidy
easyp generate
```

If `generate.modules` is omitted, the generator uses `protobuf.mod` beside this `easyp.gen.yaml`, or the repository-root `protobuf.mod` when there is no sibling manifest. A locked dependency identity in `generate.modules` is resolved through that same selected manifest and its lock. A module entry may also be a repository-relative local module path. `generate.packages` is reserved for future package filtering and currently returns an error when nonempty.

## Select a project and output descriptors

```bash
easyp generate --project backend
easyp generate --descriptor_set_out descriptors.pb --include_imports
```

`--project` selects one consumer directory containing `easyp.gen.yaml`. `--include_imports` adds transitive imports to the descriptor set. The v1 command has no `--path` or `--root` flag; source roots are declared in `protobuf.mod`.

## Plugins and managed options

`plugins[].name` selects a local executable or a bundled WASM plugin. EasyP selects bundled plugins through the existing plugin resolver. `plugins[].path` runs a binary at an explicit path, while `plugins[].command` runs a command with arguments. Each plugin sets exactly one of `name`, `path`, `command`, or `remote`. A remote plugin uses `remote` with a separate pinned semantic `version`. Relative binary paths and commands run from the directory where EasyP starts; plugin outputs are relative to the generator file.

The existing managed rules remain available under `generate.managed`, including module, package, path, and field selectors. `options.go.package_prefix` can provide a Go package prefix; a repository-root generator file can supply a default for nested generator files. See the full [`easyp.gen.yaml` reference](/docs/reference/easyp-gen-yaml).

Dependency repositories may use v1 EasyP, older EasyP, Buf v1, or Buf v2 metadata for their proto roots. The consumer's generator still uses the v1 files.
