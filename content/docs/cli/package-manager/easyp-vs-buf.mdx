---
title: "Using Buf-configured Git dependencies"
description: "How the EasyP v1 pilot reads proto roots from Git dependencies that use Buf configuration."
---

An EasyP v1 project lists Git modules in `protobuf.mod`. A dependency repository can use Buf configuration; EasyP reads that configuration to find its `.proto` source roots. The consumer does not need to copy those roots into `easyp.gen.yaml`.

| Dependency file | Roots used by EasyP |
|-----------------|---------------------|
| `buf.work.yaml` v1 | `directories` |
| `buf.yaml` v2 | `modules[].path` |
| `buf.yaml` v1 | Repository root |
| `buf.yaml` v1beta1 | `build.roots`, or repository root if omitted |

When a dependency has no EasyP or Buf configuration, EasyP uses its repository root. If it has an older EasyP `protobuf.mod` or `easyp.yaml`, EasyP also reads its transitive requirements and declared roots.

```text
# Consumer protobuf.mod
module github.com/acme/service
roots proto
require github.com/acme/buf-contracts v1.2.0
```

```bash
easyp mod tidy
easyp mod download
easyp generate
```

`mod tidy` resolves the Git dependency and records the selected commit and content hash in `protobuf.lock`. Buf Registry dependency names are not converted into Git URLs automatically; declare a suitable Git source in the consumer manifest. Buf include/exclude filters are not yet supported for Git dependency import roots and produce an error.

The v1 pilot does not provide `mod vendor`. See the [package manager guide](/docs/cli/package-manager) for the supported commands.
