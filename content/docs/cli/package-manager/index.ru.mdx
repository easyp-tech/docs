---
title: "Менеджер пакетов"
description: "Разрешение и фиксация Git-зависимостей protobuf в EasyP v1."
---

Менеджер пакетов v1 читает `protobuf.mod` и записывает `protobuf.lock`. Для каждого выбранного модуля lock содержит точный Git-коммит и хеш содержимого `h1:`. Хеш проверяется при скачивании и повторном использовании кеша.

## Объявление зависимостей

```text
module github.com/acme/contracts
roots proto

require (
    github.com/acme/shared v1.2.0
    github.com/acme/weather v2.1.0
)
```

Если `roots` не указан, используется `.`. Версию в требовании можно опустить: `mod tidy` найдёт текущий HEAD Git-репозитория и закрепит точный коммит. Повторный `tidy` сохранит его, а `mod update` обновит требование без версии до HEAD. При необходимости можно указать SemVer-тег или полный хеш Git-коммита из 40 или 64 символов. `replace module => ../local-copy` направляет генерацию и линтинг на локальный каталог. Перед записью воспроизводимого lock через `mod tidy` или `mod update` локальные замены нужно убрать.

Если в Git-репозитории несколько `protobuf.mod`, объявляйте каждый вложенный модуль отдельным `require` по имени из его манифеста. Для модулей без тегов достаточно `require repo/foo` и `require repo/bar`: EasyP найдёт оба манифеста и закрепит найденные коммиты без отдельных тегов. Явно указанные хеши останутся закреплёнными при `mod update`. Теги для релизов необязательны; для модуля в `foo/` версия `v1.2.3` использует тег `foo/v1.2.3`. Корни исходников каждого модуля разрешаются независимо.

## Команды

| Команда | Поведение |
|---------|-----------|
| `easyp mod tidy` | Разрешает прямые и транзитивные требования и записывает `protobuf.lock` |
| `easyp mod download` | Скачивает точные коммиты из lock и проверяет хеши |
| `easyp mod update` | Обновляет требования в пределах текущих мажорных версий и пересоздаёт lock |
| `easyp mod vendor` | Проверяет зафиксированные зависимости и копирует их `.proto` в `easyp_vendor` |

```bash
easyp mod tidy
easyp mod download
easyp mod vendor
easyp generate
```

Храните `protobuf.mod` и `protobuf.lock` в репозитории для воспроизводимой сборки. Кеш по умолчанию расположен в `$HOME/.easyp/v1/git`; переменная `EASYPPATH` меняет его родительский каталог. `mod vendor` требует lock и отклоняет локальные замены и повторяющиеся import path. Каталог `easyp_vendor` — копия исходников зависимостей, а не замена lock-файла.

## Зависимости на Buf или старом EasyP

Git-зависимость может объявлять корни `.proto` через `buf.work.yaml`, Buf v1/v2 `buf.yaml` или старый EasyP `easyp.yaml`. Транзитивные требования из старого EasyP `protobuf.mod` также читаются. Если ни одного такого файла нет, корнем считается каталог репозитория. Совместимость относится к метаданным зависимости; проект-потребитель использует v1 `protobuf.mod`.

Зависимости Buf Registry не имеют автоматического Git-идентификатора. Если их импорты нужны, объявите соответствующий Git-модуль в `protobuf.mod` потребителя. Фильтры Buf include/exclude для корней Git-зависимостей пока не поддерживаются и вызывают явную ошибку.

Форматы полей описаны в справочниках [`protobuf.mod`](/ru/docs/reference/protobuf-mod) и [`protobuf.lock`](/ru/docs/reference/protobuf-lock).
