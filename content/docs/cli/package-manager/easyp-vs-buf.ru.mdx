---
title: "Git-зависимости с конфигом Buf"
description: "Как пилотная версия EasyP v1 извлекает корни proto из Git-зависимостей на Buf."
---

Проект EasyP v1 перечисляет Git-модули в `protobuf.mod`. Репозиторий зависимости может использовать конфигурацию Buf: EasyP читает её и находит корни исходных `.proto`. Дублировать эти корни в `easyp.gen.yaml` потребителя не нужно.

| Файл зависимости | Корни, которые использует EasyP |
|------------------|---------------------------------|
| `buf.work.yaml` v1 | `directories` |
| `buf.yaml` v2 | `modules[].path` |
| `buf.yaml` v1 | Корень репозитория |
| `buf.yaml` v1beta1 | `build.roots` или корень репозитория |

Если у зависимости нет конфигурации EasyP или Buf, её корнем считается каталог репозитория. Если есть старые EasyP `protobuf.mod` или `easyp.yaml`, EasyP также читает транзитивные требования и объявленные корни.

```text
# protobuf.mod потребителя
module github.com/acme/service
roots proto
require github.com/acme/buf-contracts v1.2.0
```

```bash
easyp mod tidy
easyp mod download
easyp generate
```

`mod tidy` разрешает Git-зависимость и записывает выбранный коммит и хеш содержимого в `protobuf.lock`. Имена зависимостей Buf Registry не превращаются в Git URL автоматически: подходящий Git-источник надо объявить в манифесте потребителя. Фильтры Buf include/exclude для корней Git-зависимостей пока не поддерживаются и вызывают ошибку.

В пилотной версии v1 нет `mod vendor`. Поддерживаемые команды перечислены в [руководстве менеджера пакетов](/ru/docs/cli/package-manager).
