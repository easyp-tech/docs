The v1 pilot separates module dependencies, generation, and lint and breaking policies:

| File | Purpose |
|------|---------|
| [`protobuf.mod`](/docs/reference/protobuf-mod) | Module identity, source roots, requirements, and local replacements |
| [`protobuf.lock`](/docs/reference/protobuf-lock) | Resolved Git commits and content hashes; generated by `easyp mod tidy` |
| [`easyp.gen.yaml`](/docs/reference/easyp-gen-yaml) | Modules to generate, plugins, outputs, and managed options |
| [`easyp.yaml`](/docs/reference/easyp-yaml) | Lint and breaking policies |

The CLI commands use the v1 files directly. They do not fall back to the older EasyP generation, lint, breaking, or module-management configuration. A Git dependency can still use older EasyP or Buf configuration: the dependency reader extracts its requirements and proto roots for import resolution.

## Typical workflow

```bash
easyp init --module github.com/acme/contracts
easyp mod tidy
easyp mod download
easyp generate
easyp lint --path proto
easyp breaking --path proto --against main
```

`mod tidy` resolves requirements and writes `protobuf.lock`. `mod download` fetches exactly the locked commits. `mod update` refreshes required versions within their current major versions, then updates the lock. Local `replace` directives work for generation and linting; remove them before `mod tidy` or `mod update` writes a reproducible lock.

## Command flags

| Command | Relevant flags |
|---------|----------------|
| `generate` | `--project`, `--descriptor_set_out`, `--include_imports` |
| `lint` | `--path` (`-p`), `--root` (`-r`) |
| `breaking` | `--path` (`-p`), `--root` (`-r`), `--against` |
| `init` | `--dir` (`-d`), `--module` |
| `validate-config` | `--config` (alias of `--cfg`), `--format` |
| `mod vendor` | No command-specific flags |
| `ls-files` | `--include-imports` (default `true`), `--format` (`json` or `text`) |
| `schema-gen` | `--out-dir` (default `schemas`) |

The global flags are `--cfg` (alias `--config`, default `easyp.yaml`), `--debug` (`-d`), and `--format` (`-f`, `text` or `json`). `EASYP_CFG`, `EASYP_DEBUG`, and `EASYP_FORMAT` set their respective defaults. The module cache uses `EASYPPATH` or `$HOME/.easyp`.

`generate` discovers `easyp.gen.yaml` files beneath the current directory. Use `--project` to choose one consumer project. Modules and their source roots come from `protobuf.mod`; `generate.packages` is reserved and currently returns an error if nonempty. The old `generate --path` and `generate --root` flags are unavailable.

`lint` and `breaking` read the v1 `easyp.yaml`. They use the nearest module's declared roots and locked or local dependency roots for imports. A policy may exist without a `protobuf.mod`; in that case the commands use the scanned files and built-in imports.

`breaking` applies the nearest `breaking` section to each reported file. When nested policies select different Git baselines, it compares against each baseline and reports an issue only under the policy that selected it.

`validate-config` recursively checks every `easyp.yaml`, `easyp.gen.yaml`, `protobuf.mod`, and `protobuf.lock` below the current directory. Pass `--cfg <file>` to check one file or `--cfg <directory>` to scan another directory. JSON errors identify the file; YAML structure errors also include line and column. Invalid lock versions, incomplete entries, and malformed hashes are reported as validation errors.

```bash
easyp validate-config
easyp validate-config --cfg ./services --format json
easyp validate-config --cfg ./services/api/easyp.gen.yaml
```

`mod vendor` verifies the locked Git dependencies and copies their `.proto` files into `easyp_vendor` using their import paths. It replaces a previous vendor tree only after all files have been copied successfully. Duplicate import paths are errors. Run `mod tidy` first; local `replace` directives cannot be vendored.

`ls-files` lists local `.proto` files from `protobuf.mod` roots. By default it also includes reachable imports from dependencies and bundled well-known protos, resolving dependencies through the v1 lock or local replacements. Use `--include-imports=false` to list only local files without resolving dependencies. JSON output contains `files`, `roots`, and any import `errors`.

`schema-gen --out-dir schemas` writes separate JSON Schemas for `easyp.yaml`, `easyp.gen.yaml`, and `protobuf.lock`, each with a `-v1.schema.json` filename and an unversioned alias. `protobuf.mod` is a text manifest, so validate it with `validate-config` instead. CLI validation also checks semantic rules beyond the JSON Schemas.

## Minimal files

```text
module github.com/acme/contracts
roots proto
require github.com/acme/shared v1.2.0
```

```yaml
# easyp.gen.yaml
version: v1
generate:
  modules: [github.com/acme/contracts]
plugins:
  - name: go
    out: ./gen/go
```

```yaml
# easyp.yaml
version: v1
linters:
  default: STANDARD
breaking:
  baseline: git:main
```

For the exact fields and current limits, use the linked reference pages above.
