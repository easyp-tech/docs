---
title: "GitLab CI"
description: "Run frozen EasyP v1 config validation, dependency verification, linting, breaking checks, and code generation in GitLab CI."
---

Use a pinned EasyP v1 image such as `ghcr.io/easyp-tech/easyp:v1.0.0` (or a derived project image that also includes any required local `protoc-gen-*` executables; remote and 15 built-in WASM plugins require no extra local binaries). Commit your configs and `protobuf.lock`. This example has one module and a root generation config; in a monorepo run module commands per module and explicitly select generation projects with `--project` or `--all`.

~~~yaml
image:
  name: ghcr.io/easyp-tech/easyp:v1.0.0
  entrypoint: [""]

variables:
  GIT_DEPTH: "0"

stages: [validate]

contracts:
  stage: validate
  script:
    - easyp validate-config
    - easyp mod download --frozen
    - easyp lint --frozen
    - git fetch origin +refs/heads/main:refs/remotes/origin/main
    - easyp breaking --frozen --against refs/remotes/origin/main
    - easyp generate --frozen
    - git diff --exit-code
    - test -z "$(git status --porcelain --untracked-files=normal -- gen)"
~~~

Adjust `main` and `gen` to the project baseline and output directory. Passing `--frozen` enforces the committed `protobuf.lock` and rejects any local `replace` directives in CI. The last assertion catches newly generated untracked files. Do not mask breaking failures with `|| echo`. Configure private Git access through the runner; do not put credentials into EasyP YAML.
