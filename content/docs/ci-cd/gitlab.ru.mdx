title: "GitLab CI"
---

Для примера ниже задайте <code>EASYP_CI_IMAGE</code>: закреплённый образ с проверенной сборкой EasyP v1, Git и нужными плагинами. Конфиги и lock должны быть закоммичены. Здесь показан один модуль с generation-конфигом в корне; в монорепозитории команды модулей запускаются для каждого модуля, а генерация выбирается явно.

~~~yaml
image: $EASYP_CI_IMAGE

variables:
  GIT_DEPTH: "0"

stages: [validate]

contracts:
  stage: validate
  script:
    - easyp validate-config
    - easyp mod download
    - easyp lint
    - git fetch origin +refs/heads/main:refs/remotes/origin/main
    - easyp breaking --against refs/remotes/origin/main
    - easyp generate
    - git diff --exit-code
    - test -z "$(git status --porcelain --untracked-files=normal -- gen)"
~~~

Замените <code>main</code> и <code>gen</code> на baseline и каталог результатов проекта. Последняя проверка учитывает новые неотслеживаемые generated-файлы. Не маскируйте ошибку breaking через <code>|| echo</code>. Доступ к приватным Git-источникам настраивается средствами runner; секреты не записываются в YAML-конфиги EasyP.
