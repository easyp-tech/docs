---
title: "Организационные политики линтинга"
description: "Согласованные политики репозиториев и каскадирование целых секций для локальных исключений."
---

Команды могут хранить согласованную политику линтинга в каждом репозитории и задавать исключения для отдельных каталогов. EasyP v1 не загружает общие политики: <code>linters.extends</code> и <code>breaking.extends</code> зарезервированы, непустые значения отклоняются. Встроенного механизма доставки общих политик нет.

## 1. Политика репозитория

Сохраните полную политику в <code>proto/easyp.yaml</code>:

~~~yaml
version: v1
linters:
  default: STANDARD
  enable:
    - ENUM_VALUE_PREFIX
    - RPC_REQUEST_RESPONSE_UNIQUE
  disable:
    - PACKAGE_VERSION_SUFFIX
linters-settings:
  ENUM_ZERO_VALUE_SUFFIX:
    suffix: UNSPECIFIED
breaking:
  baseline: git:main
  categories: [FILE]
~~~

Проверяйте изменения политики вместе с изменениями схем. <code>FILE</code> добавляет проверки перемещения объявлений к существующим проверкам совместимости; категории вроде <code>WIRE</code> не поддерживаются.

## 2. Каскадирование секций

Каждая секция <code>linters</code>, <code>linters-settings</code>, <code>issues</code> и <code>breaking</code> берётся целиком из ближайшего файла, где она определена. Поля внутри секции не сливаются частично.

Например, дочерняя секция <code>linters</code> только с <code>disable</code> не сохраняет родительский список <code>enable</code>. Укажите в дочернем файле весь нужный набор правил. Отсутствующие секции по-прежнему берутся из ближайшего предка, который их определяет.

## 3. Исключения для устаревших поддеревьев

~~~text
proto/
├── easyp.yaml
├── user/v1/user.proto
└── legacy/
    ├── easyp.yaml
    └── old.proto
~~~

Чтобы ослабить линтинг только в <code>proto/legacy</code>, создайте <code>proto/legacy/easyp.yaml</code>:

~~~yaml
version: v1
linters:
  default: MINIMAL
  disable:
    - FIELD_LOWER_SNAKE_CASE
    - ENUM_VALUE_PREFIX
~~~

Дочерний файл заменяет всю секцию <code>linters</code>. Родительские <code>linters-settings</code> и <code>breaking</code> продолжают действовать: дочерний файл их не определяет.

Если исключение нужно только для одного правила, сохраните родительский набор линтеров и вместо этого добавьте в родительскую политику секцию <code>issues</code>:

~~~yaml
# Добавьте в proto/easyp.yaml
issues:
  exclude-rules:
    - path: legacy/**/*.proto
      linters: [FIELD_LOWER_SNAKE_CASE]
~~~

Путь отсчитывается от <code>proto/easyp.yaml</code>, даже когда секция наследуется более глубоким каталогом. Дочерняя <code>issues: &#123;&#125;</code> очищает унаследованные исключения.

Из корня репозитория запустите проверку с явной политикой:

~~~bash
easyp --cfg proto/easyp.yaml lint --path .
~~~

Поддерживаемые правила, шаблоны путей и подавление замечаний комментариями описаны в [справочнике политики](/ru/docs/reference/easyp-yaml).
