---
title: "Изоляция микросервисов"
description: "Как помодульное (per-module) разрешение зависимостей позволяет независимо обновлять сервисы в монорепозитории."
---

В крупных монорепозиториях принудительное использование единой версии зависимости для всех микросервисов приводит к жёсткому связыванию команд. В данном руководстве показывается, как EasyP обеспечивает **помодульную изоляцию зависимостей (per-module isolation)**, позволяя сервисам обновлять общие библиотеки независимо друг от друга.

---

## Проблема единых workspace-резолверов

Инструменты вроде Buf v2 выполняют резолюцию на весь workspace целиком: каждый сервис в монорепозитории обязан перейти на одну и ту же версию каждой зависимости. Если `team-user` требуется `common v2.0.0`, а `team-order` ещё не готова мигрировать с `common v1.2.0`, сборка всего репозитория блокируется или требует ручного согласования.

---

## Помодульное решение EasyP

EasyP выполняет резолюцию зависимостей независимо для каждого Protobuf-модуля, определяемого собственным `protobuf.mod`.

```text
repo/
└── proto/
    ├── user/
    │   ├── protobuf.mod     # Запрашивает common v1.2.0
    │   └── protobuf.lock    # Зафиксирован на common v1.2.0
    └── order/
        ├── protobuf.mod     # Запрашивает common v2.0.0
        └── protobuf.lock    # Зафиксирован на common v2.0.0
```

### Модуль 1: `proto/user/protobuf.mod`

```protobuf
module github.com/acme/user

require (
    github.com/acme/common v1.2.0
)
```

### Модуль 2: `proto/order/protobuf.mod`

```protobuf
module github.com/acme/order

require (
    github.com/acme/common v2.0.0
)
```

---

## Ключевые преимущества

1. **Независимые релизные циклы**: Команда `order` может обновиться до `common v2.0.0`, не дожидаясь команды `user`.
2. **Отдельные решения о версиях**: lock-файлы модулей обновляются независимо. Изменения общей конфигурации или самих контрактов всё равно требуют межкомандной проверки.
3. **Изолированные графы зависимостей**: каждый модуль компилируется со своей выбранной версией. Это не гарантирует отсутствие коллизий сгенерированных пакетов: настройте отдельные output/import paths. Несовместимые графы нельзя объединять в один descriptor set; используйте раздельный экспорт.
