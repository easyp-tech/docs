---

В данном руководстве рассматривается процесс добавления сторонних или общих Protobuf-модулей в проект EasyP.

---

## Общий процесс

1. **Объявление зависимости**: Добавление Git-репозитория и тега версии в `protobuf.mod`. Через `import` в `.proto` используются файлы объявленной зависимости.
2. **Запуск резолюции**: Выполнение `easyp mod tidy` для вычисления полного графа транзитивных зависимостей.
3. **Фиксация в Git**: Проверка и коммит обновлённых файлов `protobuf.mod` и `protobuf.lock`.

---

## Шаг 1: Объявление зависимости

Откройте `protobuf.mod` вашего модуля и добавьте требуемый модуль в блок `require`:

```protobuf
// proto/user/protobuf.mod

require (
    github.com/googleapis/googleapis v1.5.0
    github.com/acme/weather v1.2.3
)
```

После этого импортируйте файл зависимости в Protobuf-файле:

```protobuf
// proto/user/v1/user.proto
syntax = "proto3";

package user.v1;

import "google/type/datetime.proto";
```

---

## Шаг 2: Выполнение `easyp mod tidy`

Запустите команду `easyp mod tidy` в терминале:

```bash
easyp mod tidy
```

### Что делает `easyp mod tidy`:
- Сканирует все `.proto` файлы модуля для поиска активных `import`.
- Загружает метаданные требуемых модулей из Git-репозиториев.
- Вычисляет Minimal Version Selection (MVS) для транзитивных зависимостей.
- Дописывает транзитивные зависимости в `protobuf.mod` с пометкой `// indirect`.
- Генерирует или обновляет `protobuf.lock` с хешами коммитов и контрольными суммами.

### Git-репозитории с конфигурацией Buf или старого EasyP

Проект-потребитель по-прежнему объявляет Git-источник через `require`. Репозиторий зависимости может использовать другой формат:

- EasyP v1 `protobuf.mod`: читаются `roots` и `require`.
- Buf v2 `buf.yaml`: `modules[].path` задаёт корни импортов.
- Buf v1 `buf.work.yaml`: читаются `directories`; одиночный модуль с `buf.yaml` v1 использует `.`.
- Buf v1beta1 `buf.yaml`: читаются `build.roots`, по умолчанию `.`.
- Старый EasyP: из прежнего `protobuf.mod` читаются зависимости `direct`, а из `easyp.yaml` — локальные `generate.inputs[].directory.root` и Git-входы.

Если в старой зависимости EasyP у Git-зависимости не указана версия, `mod tidy` выбирает последний стабильный тег SemVer и фиксирует выбранный commit в v1 lock. `deps` из Buf Registry не являются Git-источниками: когда нужны их импорты, укажите соответствующий Git-модуль в `protobuf.mod` проекта-потребителя. Фильтры Buf `includes`/`excludes` для корней Git-зависимости пока не поддерживаются и вызывают явную ошибку.

Обновлённый `protobuf.mod`:

```protobuf
require (
    github.com/googleapis/googleapis v1.5.0
    github.com/acme/weather v1.2.3
    github.com/grpc-ecosystem/grpc-gateway v2.19.0 // indirect
)
```

---

## Шаг 3: Коммит изменений

Всегда коммитьте файлы `protobuf.mod` и `protobuf.lock` в репозиторий. Это гарантирует, что все разработчики и CI-пайплайны будут использовать идентичные версии схем:

```bash
git add protobuf.mod protobuf.lock
git commit -m "feat: add googleapis and weather dependencies"
```
