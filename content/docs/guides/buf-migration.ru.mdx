---
title: "Миграция с Buf на EasyP"
description: "Пошаговое руководство по миграции конфигураций и команд с Buf на EasyP."
---

Это руководство сопоставляет конфигурацию Buf с файлами и командами EasyP v1. Проверяйте каждую настройку по схеме v1, а не переносите прежнюю конфигурацию без изменений.

---

## Прямое соответствие концепций и файлов

| Конструкция Buf | Эквивалент в EasyP | Ключевое отличие |
| --- | --- | --- |
| <code>buf.yaml</code> (секция deps) | <code>protobuf.mod</code> | Независимый от инструментов DSL; использует Git URL вместо BSR. |
| <code>buf.yaml</code> (секция lint) | <code>easyp.yaml</code> (linters) | Использует пресеты и списки правил; каждая секция политики берётся целиком из ближайшего определения. Непустое <code>extends</code> не поддерживается. |
| <code>buf.yaml</code> (секция breaking) | <code>easyp.yaml</code> (breaking) | Явное сравнение с git-baseline (например, <code>git:main</code>). |
| <code>buf.gen.yaml</code> | <code>easyp.gen.yaml</code> | Находится у потребителя и выбирает целые модули. |
| <code>buf.gen.yaml</code> (managed) | <code>easyp.gen.yaml</code> (generate.managed) | Явный managed mode; <code>options.go.package_prefix</code> — отдельная настройка только для Go. |
| <code>buf.lock</code> | <code>protobuf.lock</code> | Включает SHA коммитов Git и хеши содержимого. |
| <code>buf dep update</code> | <code>easyp mod tidy</code> | Разрешает объявленные требования через MVS и записывает lock; обновления версий проверяйте отдельно. |
| <code>buf lint</code> | <code>easyp lint</code> | Каскадируется через ближайший <code>easyp.yaml</code>. |
| <code>buf breaking</code> | <code>easyp breaking</code> | CI-гейт против явного baseline. |
| <code>buf generate</code> | <code>easyp generate</code> | Выбирает ближайший вышестоящий файл генератора; используйте <code>--project</code> или явный рекурсивный <code>--all</code>. |

---

## Пошаговый процесс миграции

### Шаг 1: Первичная инициализация

В новом проекте <code>easyp init</code> создаёт <code>protobuf.mod</code>, <code>easyp.yaml</code> и <code>easyp.gen.yaml</code>. Укажите <code>--module</code>, если идентификатор Git-модуля нельзя получить из удалённого репозитория <code>origin</code>.

~~~bash
easyp init --module github.com/acme/my-service
~~~

Автоматический перенос зависимостей Buf Registry отложен. При наличии <code>buf.yaml</code> или <code>buf.yml</code> команда <code>easyp init</code> завершится до записи файлов: имя <code>buf.build/...</code> нельзя безопасно считать URL Git-модуля. Выберите Git-источник для каждой зависимости и создайте v1-файлы явно.

### Шаг 2: Вынос зависимостей в <code>protobuf.mod</code>

Перенесите зависимости модулей из <code>buf.yaml</code> в <code>protobuf.mod</code>:

~~~protobuf
// protobuf.mod
module github.com/acme/my-service

require (
    github.com/googleapis/googleapis v1.5.0
)
~~~

### Шаг 3: Конвертация правил в <code>easyp.yaml</code>

Перенесите конфигурацию линтера и breaking-проверок в <code>easyp.yaml</code>:

~~~yaml
# easyp.yaml
version: v1

linters:
  default: STANDARD

breaking:
  baseline: git:main
~~~

### Шаг 4: Выбор модулей для генерации

Замените старые блоки <code>inputs</code> выбором модулей. В примере корневой <code>protobuf.mod</code> владеет схемами, а <code>backend/easyp.gen.yaml</code> выбирает этот корневой модуль через <code>.</code>. Корни исходников определяются манифестом:

~~~yaml
# backend/easyp.gen.yaml
version: v1

generate:
  modules:
    - .

plugins:
  - name: go
    out: ./gen/go
    opts:
      paths: source_relative
~~~

Локальному плагину <code>go</code> нужен <code>protoc-gen-go</code> в окружении сборки. Фиксируйте версию там: локальные плагины отклоняют <code>version</code> в YAML. Удалённым плагинам нужна отдельная фиксированная семантическая версия. <code>generate.packages</code> зарезервировано и не фильтрует пакеты.

### Шаг 5: Наведение порядка и проверка

Из корня репозитория разрешите зависимости, проверьте схемы линтером и запустите выбранный проект генерации:

~~~bash
easyp mod tidy
easyp lint
easyp generate --project ./backend
~~~

Проверьте и закоммитьте <code>protobuf.mod</code> и <code>protobuf.lock</code>. Перед <code>tidy</code> или <code>update</code> нужно убрать активные локальные замены: обе команды их отклоняют. В CI проверяйте зафиксированные зависимости через <code>easyp mod download</code> и запускайте <code>easyp breaking --against main</code> с доступной локально базой.

В <code>breaking.categories</code> поддерживается только <code>FILE</code>; <code>ignore_unstable</code> доступно. Перед переносом breaking-настроек Buf сверьтесь со [справочником политики](/ru/docs/reference/easyp-yaml), сравните результат генерации и запустите тесты потребителей до отказа от старого workflow.
