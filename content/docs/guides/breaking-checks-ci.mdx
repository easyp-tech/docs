---
title: "Breaking checks in CI"
description: "Run the EasyP v1 breaking checker against a Git baseline in CI."
---

The v1 breaking checker compares current `.proto` files with a Git ref. Configure the baseline in `easyp.yaml`:

```yaml
version: v1
breaking:
  baseline: git:origin/main
  ignore: [experimental]
```

Then run the check from a checkout containing the comparison ref:

```bash
easyp mod download
easyp lint --path proto
easyp breaking --path proto
```

`mod download` verifies the commits and content hashes already recorded in `protobuf.lock`. Fetch the baseline ref in CI before the breaking check. If no `breaking.baseline` is set, pass the ref through `--against origin/main`; the command's default is `master`.

For example, a GitHub Actions checkout step can use full history:

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- name: Check protobuf compatibility
  run: easyp breaking --path proto --against origin/main
```

Install the v1 pilot binary earlier in the job. Keep `protobuf.mod` and `protobuf.lock` committed, and resolve dependency updates before CI rather than rewriting the lock during a check.

The pilot uses the existing breaking rule set. `breaking.categories` and `breaking.ignore_unstable` are not supported yet and cause an error. See [breaking checks](/docs/cli/breaking-changes).
