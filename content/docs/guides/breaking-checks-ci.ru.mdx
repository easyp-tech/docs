---
title: "Breaking-проверки в CI"
description: "Запуск проверки совместимости EasyP v1 относительно Git-базы в CI."
---

Проверка v1 сравнивает текущие `.proto` с Git-ссылкой. Укажите базу в `easyp.yaml`:

```yaml
version: v1
breaking:
  baseline: git:origin/main
  ignore: [experimental]
```

Запустите проверку из рабочего каталога, где доступна ссылка для сравнения:

```bash
easyp mod download
easyp lint --path proto
easyp breaking --path proto
```

`mod download` проверяет коммиты и хеши содержимого из уже созданного `protobuf.lock`. Перед breaking-проверкой получите базовую Git-ссылку в CI. Если `breaking.baseline` не указан, передайте ссылку как `--against origin/main`; значение команды по умолчанию — `master`.

Например, в GitHub Actions можно получить полную историю:

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- name: Check protobuf compatibility
  run: easyp breaking --path proto --against origin/main
```

Установите бинарный файл пилотной версии v1 в предыдущем шаге job. Храните `protobuf.mod` и `protobuf.lock` в репозитории, а обновления зависимостей разрешайте до CI, не переписывая lock во время проверки.

Пилотная версия использует существующий набор breaking-правил. `breaking.categories` и `breaking.ignore_unstable` пока не поддерживаются и вызывают ошибку. См. [breaking-проверки](/ru/docs/cli/breaking-changes).
