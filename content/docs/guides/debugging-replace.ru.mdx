---
title: "Отладка через replace"
description: "Локальные замены модулей при разработке и их ограничения для lock-файла и сети."
---

Локальный <code>replace</code> в <code>protobuf.mod</code> позволяет менять зависимость вместе с потребителем, не публикуя каждое промежуточное изменение.

## Настройка локального replace

Предположим, <code>proto/user</code> требует <code>github.com/acme/weather</code>. Разместите checkout зависимости в <code>proto/weather-fork</code>, рядом с <code>proto/user</code>, и добавьте:

~~~protobuf
// proto/user/protobuf.mod
module github.com/acme/user

require (
    github.com/acme/weather v1.2.3
)

replace github.com/acme/weather => ../weather-fork
~~~

Относительный путь замены отсчитывается от каталога с этим <code>protobuf.mod</code> и указывает на <code>proto/weather-fork</code> независимо от рабочего каталога shell. Абсолютные пути также поддерживаются. Нативный <code>protobuf.mod</code> замены должен объявлять <code>github.com/acme/weather</code>; отсутствие каталога или несовпадение имени вызывает ошибку.

## Процесс локальной разработки

Если файл генератора расположен в <code>proto/user</code>, запустите из корня репозитория:

~~~bash
easyp generate --project ./proto/user
~~~

Применяются только замены главного модуля-потребителя, на любой глубине требуемого графа. EasyP читает требования и корни из <code>protobuf.mod</code> замены, но игнорирует директивы замены в зависимостях. Относительные пути всегда считаются от главного манифеста. Сама директива замены не добавляет зависимость; неиспользуемые замены не читаются и не скачиваются. Обычные циклы зависимостей обходятся без повторной обработки. Старые метаданные поддерживаются существующим адаптером совместимости; плагины зависимостей не запускаются.

Генерация, выбор зависимостей для генерации, оба режима экспорта дескрипторов, lint, ls-files и разрешение импортов breaking используют один эффективный граф. Заменённые модули не требуют удалённой загрузки и могут быть неопубликованными. Полностью локальный граф работает офлайн без lock-файла.

## Локальный режим и публикуемый lock

Пока в главном манифесте есть замены, EasyP оставляет существующий <code>protobuf.lock</code> **побайтно неизменным**, а отсутствующий не создаёт. Локальные пути, версии/хеши и транзитивные зависимости только из форка не попадают в общий lock. Это явный инвариант EasyP: <code>protobuf.lock</code> не является <code>go.sum</code>, и это не утверждение, что Go никогда не меняет <code>go.sum</code> при заменах. Правила применения замен главного модуля следуют [модели Go](https://go.dev/ref/mod#go-mod-file-replace).

- <code>mod tidy</code> разрешает и проверяет эффективный граф и устанавливает нужные удалённые снимки без изменения манифеста или lock.
- <code>get</code> может изменить явно запрошенное требование. <code>mod update</code> обновляет незаменённые прямые требования по прежним правилам версий; заменённые требования сохраняют объявленные версии без удалённого поиска. Обе команды не добавляют транзитивные зависимости только из форка и не записывают lock.
- <code>mod download</code> проверяет/устанавливает только нужные незаменённые снимки. Новые удалённые требования форка разрешаются без записи в общий lock; заменённые модули и неиспользуемые записи lock не скачиваются.
- <code>mod vendor</code> копирует текущие локальные и проверенные удалённые исходники в <code>easyp_vendor</code>, не меняя lock. Этот локальный артефакт не доказывает воспроизводимость опубликованного графа.

<Callout type="info">
Эффективный граф существует только в памяти. Совпадающие опубликованные ревизии и pins требований без версии используют проверенные снимки кеша. Для нового удалённого требования форка может понадобиться сеть при разрешении и установке; проверки неизменности версий и содержимого сохраняются. Удалённые плагины также могут требовать сеть.
</Callout>

### Подготовка к отправке PR

1. Опубликуйте изменения зависимости в Git под нужной версией.
2. Обновите <code>require</code> в <code>protobuf.mod</code> потребителя.
3. Удалите директиву <code>replace</code>.
4. В этом модуле запустите <code>easyp mod tidy</code> для обновления <code>protobuf.lock</code>.
5. Повторите генерацию выбранного проекта, запустите тесты потребителей и закоммитьте проверенные изменения манифеста, lock и сгенерированных файлов.

При breaking-проверках замены внутри Git-репозитория используют содержимое соответствующей ревизии. Внешние локальные замены отклоняются: у базы нет восстановимой исторической копии. Удалённому требованию без версии из исторического форка нужен pin в историческом lock: текущий HEAD не подставляется вместо базы. См. [breaking-проверки](/ru/docs/cli/breaking-changes).
