---
title: "Отладка через replace"
description: "Локальные замены модулей при разработке и их ограничения для lock-файла и сети."
---

Локальный <code>replace</code> в <code>protobuf.mod</code> позволяет менять зависимость вместе с потребителем, не публикуя каждое промежуточное изменение.

## Настройка локального replace

Предположим, <code>proto/user</code> требует <code>github.com/acme/weather</code>. Разместите checkout зависимости в <code>proto/weather-fork</code>, рядом с <code>proto/user</code>, и добавьте:

~~~protobuf
// proto/user/protobuf.mod
module github.com/acme/user

require (
    github.com/acme/weather v1.2.3
)

replace github.com/acme/weather => ../weather-fork
~~~

Относительный путь замены отсчитывается от каталога с этим <code>protobuf.mod</code> и указывает на <code>proto/weather-fork</code> независимо от рабочего каталога shell. Корни модуля и импорты замены должны оставаться корректными.

## Процесс локальной разработки

Если файл генератора расположен в <code>proto/user</code>, запустите из корня репозитория:

~~~bash
easyp generate --project ./proto/user
~~~

Генерация использует локальные исходники заменённой зависимости. Можно менять обе схемы, не публикуя новый тег зависимости после каждой правки.

<Callout type="info">
Загрузки зависимостей не нужны, только если весь граф локальный или уже находится в проверенном кеше. Одна локальная замена не делает локальными остальные зависимости и их транзитивные импорты. Нужным удалённым зависимостям по-прежнему требуются корректные lock-файлы и, возможно, загрузки; удалённым плагинам нужна сеть.
</Callout>

## Защита воспроизводимого lock-файла

<Callout type="warn">
<code>easyp mod tidy</code> и <code>easyp mod update</code> явно отклоняют активные локальные замены, даже если генерация с ними работает. Перед разрешением воспроизводимого lock-файла зависимостей удалите замены.
</Callout>

Эти команды изменяют зависимости, а не выполняют проверку CI только для чтения. Для установки и проверки подготовленного lock используйте <code>easyp mod download</code>; команда не является универсальным запретом локальных замен. Проверяйте манифест перед релизом.

### Подготовка к отправке PR

1. Опубликуйте изменения зависимости в Git под нужной версией.
2. Обновите <code>require</code> в <code>protobuf.mod</code> потребителя.
3. Удалите директиву <code>replace</code>.
4. В этом модуле запустите <code>easyp mod tidy</code> для обновления <code>protobuf.lock</code>.
5. Повторите генерацию выбранного проекта, запустите тесты потребителей и закоммитьте проверенные изменения манифеста, lock и сгенерированных файлов.

При breaking-проверках замены внутри Git-репозитория используют содержимое соответствующей ревизии. Внешние локальные замены отклоняются: у базы нет восстановимой исторической копии. См. [breaking-проверки](/ru/docs/cli/breaking-changes).
