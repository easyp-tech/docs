title: "Установка EasyP"
---

Текущий релиз — EasyP v1. Все способы ниже устанавливают его; проекты на v0 переводятся командой [`easyp migrate`](/ru/docs/migration/easyp-v0).

## Установка CLI

<Tabs items={["Homebrew", "Go install", "Binary Download", "Docker"]}>
  <Tab value="Homebrew">
    #### Homebrew

    На macOS и Linux формула устанавливает `easyp` и MCP-сервер `easyp-mcp`:

    ```bash
    brew install easyp-tech/tap/easyp
    ```

    `Work in progress`: поддержка apt, yum, pacman и других менеджеров в разработке.
  </Tab>
  <Tab value="Go install">
    #### Go toolchain

    Для сборки v1 нужен **Go 1.26.6 или новее**:

    ```bash
    go install github.com/easyp-tech/easyp/cmd/easyp@latest
    go install github.com/easyp-tech/easyp/cmd/easyp-mcp@latest
    ```
  </Tab>
  <Tab value="Binary Download">
    Каждый архив содержит `easyp` и `easyp-mcp`. Скачайте архив для своей ОС и архитектуры из [последнего релиза](https://github.com/easyp-tech/easyp/releases/latest) и проверьте его по контрольным суммам релиза. Для Linux amd64:

    ```bash
    TAG=$(curl -fsSL https://api.github.com/repos/easyp-tech/easyp/releases/latest | sed -n 's/.*"tag_name": *"\([^"]*\)".*/\1/p')
    VERSION="${TAG#v}"
    ASSET="easyp-${VERSION}-linux-amd64.tar.gz"
    curl -fLO "https://github.com/easyp-tech/easyp/releases/download/${TAG}/${ASSET}"
    curl -fLO "https://github.com/easyp-tech/easyp/releases/download/${TAG}/easyp-${VERSION}-checksums.txt"
    sha256sum --check --ignore-missing "easyp-${VERSION}-checksums.txt"
    tar -xzf "$ASSET"
    sudo install "easyp-${VERSION}-linux-amd64/easyp" "easyp-${VERSION}-linux-amd64/easyp-mcp" /usr/local/bin/
    ```

    Архивы для macOS называются `darwin`; для Windows используется `.zip` с бинарниками `.exe`. Для запуска бинарников Go не нужен.
  </Tab>
  <Tab value="Docker">
    Образ CLI публикуется в GHCR с тегом `latest` и с точным тегом каждого релиза:

    ```bash
    docker run --rm -v "$PWD:/workspace" -w /workspace \
      ghcr.io/easyp-tech/easyp:latest --version
    ```

    Замените `--version` нужной командой EasyP, а в CI закрепляйте точный тег. В образе только CLI; MCP-сервер ставьте через Homebrew, Go install или архив.
  </Tab>
</Tabs>

Подключите `easyp-mcp` в MCP-клиенте как stdio-сервер: он отдаёт справочник конфигурации v1 через `easyp_config_describe`.

## Если нужно остаться на v0

v0 доступен по точной версии — для проектов, которые ещё не мигрировали, или чтобы снять эталон перед миграцией:

```bash
go install github.com/easyp-tech/easyp/cmd/easyp@v0.17.0
docker run --rm -v "$PWD:/workspace" -w /workspace ghcr.io/easyp-tech/easyp:v0.17.0 --version
```

## Предрелизы

Предрелизные сборки публикуются тегами `v1.X.Y-nightly.YYYYMMDD.N` на [GitHub Releases](https://github.com/easyp-tech/easyp/releases) и образами `ghcr.io/easyp-tech/easyp:<nightly-тег>`. Они ставятся только по точному тегу, например `go install github.com/easyp-tech/easyp/cmd/easyp@<nightly-тег>`, и никогда не обновляют Homebrew, Go `@latest` и Docker-образ `latest`.

## Go modules: переход с v0 на v1

EasyP v0 и v1 используют один путь модуля `github.com/easyp-tech/easyp`, суффикса `/v1` нет. Go требует новый путь `/v2` начиная со второй мажорной версии, чтобы несовместимые версии могли сосуществовать. См. [нумерацию версий Go](https://go.dev/doc/modules/version-numbers).

Поэтому код, который импортирует EasyP как библиотеку, перейдёт на v1 при `go get -u` или `@latest`, а API и конфигурация v1 могут потребовать изменений. Закрепите `v0.17.0`, пока код не перенесён. Go выбирает одну версию на путь модуля в сборке, поэтому другая зависимость, требующая v1, тоже может поднять выбранную версию EasyP через [minimal version selection](https://go.dev/ref/mod#minimal-version-selection).
