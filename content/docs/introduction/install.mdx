title: "Install EasyP"
---

EasyP v1 is the current release. Every channel below installs it; projects still on v0 can move with [`easyp migrate`](/docs/migration/easyp-v0).

## Install the CLI

<Tabs items={["Homebrew", "Go install", "Binary Download", "Docker"]}>
  <Tab value="Homebrew">
    #### Homebrew

    On macOS or Linux, the formula installs both `easyp` and the `easyp-mcp` server:

    ```bash
    brew install easyp-tech/tap/easyp
    ```

    `Work in progress`: support for apt, yum, pacman, etc. is under development.
  </Tab>
  <Tab value="Go install">
    #### Go toolchain

    Building v1 requires **Go 1.26.6 or later**:

    ```bash
    go install github.com/easyp-tech/easyp/cmd/easyp@latest
    go install github.com/easyp-tech/easyp/cmd/easyp-mcp@latest
    ```
  </Tab>
  <Tab value="Binary Download">
    Every archive contains both `easyp` and `easyp-mcp`. Download the one for your OS and architecture from the [latest release](https://github.com/easyp-tech/easyp/releases/latest) and verify it with the release checksums. For Linux amd64:

    ```bash
    TAG=$(curl -fsSL https://api.github.com/repos/easyp-tech/easyp/releases/latest | sed -n 's/.*"tag_name": *"\([^"]*\)".*/\1/p')
    VERSION="${TAG#v}"
    ASSET="easyp-${VERSION}-linux-amd64.tar.gz"
    curl -fLO "https://github.com/easyp-tech/easyp/releases/download/${TAG}/${ASSET}"
    curl -fLO "https://github.com/easyp-tech/easyp/releases/download/${TAG}/easyp-${VERSION}-checksums.txt"
    sha256sum --check --ignore-missing "easyp-${VERSION}-checksums.txt"
    tar -xzf "$ASSET"
    sudo install "easyp-${VERSION}-linux-amd64/easyp" "easyp-${VERSION}-linux-amd64/easyp-mcp" /usr/local/bin/
    ```

    macOS archives use `darwin`; Windows archives use `.zip` and contain `.exe` binaries. No Go toolchain is needed to run these binaries.
  </Tab>
  <Tab value="Docker">
    The CLI image is published to GHCR as `latest` and as each exact release tag:

    ```bash
    docker run --rm -v "$PWD:/workspace" -w /workspace \
      ghcr.io/easyp-tech/easyp:latest --version
    ```

    Replace `--version` with the EasyP command you need, and pin an exact tag in CI. This image contains the CLI; use Homebrew, Go install or an archive for the MCP stdio server.
  </Tab>
</Tabs>

Configure your MCP client to run `easyp-mcp` as a stdio server; it exposes the v1 configuration reference through `easyp_config_describe`.

## Staying on v0

v0 remains available by its exact version, for projects that have not migrated yet or to record a baseline before migrating:

```bash
go install github.com/easyp-tech/easyp/cmd/easyp@v0.17.0
docker run --rm -v "$PWD:/workspace" -w /workspace ghcr.io/easyp-tech/easyp:v0.17.0 --version
```

## Prereleases

Prerelease builds are published as `v1.X.Y-nightly.YYYYMMDD.N` tags on [GitHub Releases](https://github.com/easyp-tech/easyp/releases) and as `ghcr.io/easyp-tech/easyp:<nightly-tag>`. They are installed only by their exact tag, for example `go install github.com/easyp-tech/easyp/cmd/easyp@<nightly-tag>`, and never update Homebrew, Go `@latest` or the Docker `latest` image.

## Go modules: moving from v0 to v1

EasyP v0 and v1 share the module path `github.com/easyp-tech/easyp`; there is no `/v1` suffix. Go requires a new `/v2` path starting at major version 2 so incompatible major versions can coexist. See [Go's version numbering](https://go.dev/doc/modules/version-numbers).

Code that imports EasyP as a library therefore moves to v1 on `go get -u` or `@latest`, and the v1 API and configuration may require changes. Pin `v0.17.0` until that code is ported. Go selects one version per module path for a build, so a different dependency requiring v1 can also raise the selected EasyP version through [minimal version selection](https://go.dev/ref/mod#minimal-version-selection).
