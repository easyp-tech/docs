title: "Что такое EasyP?"
---

EasyP — это современный инструментарий для работы с Protocol Buffers, который объединяет весь ваш protobuf‑workflow в один мощный CLI‑инструмент. Он совмещает линтинг, управление пакетами, генерацию кода и проверку совместимости в единой среде и устраняет сложность традиционной работы с protobuf.

</Callout>

## Проблема: фрагментированные protobuf‑процессы

Работа с Protocol Buffers в разных проектах часто создает лишнюю сложность и трение:

### Хаос инструментов
- **Много отдельных утилит**: Отдельно для линтинга, генерации и управления зависимостями
- **Несогласованные конфигурации**: Разные форматы и правила в разных командах
- **Сложный онбординг**: Новым разработчикам нужно долго вникать

### Проблемы управления зависимостями
- **Нет стандартизированного подхода**: Каждый проект решает это по‑своему
- **Конфликты версий**: Трудно сводить разные версии одних и тех же proto‑библиотек
- **Неповторяемость сборок**: Сложно гарантировать одинаковый результат в разных окружениях

### Трение в разработке
- **Ручные операции**: Много повторяющихся шагов
- **Разрастание конфигураций**: Множество файлов и форматов
- **Затратная проверка совместимости**: Часто вручную и постфактум

## Решение: единый protobuf‑инструментарий

EasyP устраняет эти проблемы, предоставляя целостный opinionated‑подход и стандартизируя процессы:

### Один инструмент — все задачи
Вместо жонглирования утилитами EasyP даёт:
- **Linting** с расширенными наборами правил
- **Package management** с Git‑нативными зависимостями
- **Code generation** локально и удалённо
- **Breaking change detection** для контроля совместимости API

### Единая конфигурация
Один файл `easyp.yaml` описывает весь workflow — меньше расхождений, проще сопровождать.

### Git‑native зависимости
Прямое использование Git‑репозиториев вместо централизованных реестров: прозрачная история, контроль версий, воспроизводимые сборки.

## Типы поддерживаемых плагинов

EasyP гибко подходит к выполнению генерации:

### Local Plugins
Стандартные установленные protoc‑плагины:
```yaml
plugins:
  - name: go
    out: .
    opts:
      paths: source_relative
```

### Remote Plugins
Плагины через EasyP API сервис для воспроизводимости:
```yaml
plugins:
  - remote: api.easyp.tech/protoc-gen-typescript:latest
    out: ./web/generated
```

### Custom Plugins
Поддержка экосистемы пользовательских расширений.

## Децентрализованный менеджмент пакетов

В отличие от других решений EasyP не требует централизованного реестра. Любой Git‑репозиторий может быть источником:

- **Гибкость**: Любой Git‑хостинг (GitHub, GitLab, self‑hosted)
- **Нет vendor lock‑in**: Зависимости не привязаны к одному провайдеру
- **Полная история**: Ветки, теги, ревью
- **Enterprise‑совместимость**: Поддержка приватных репозиториев

## Зависимости с конфигурацией Buf

Проект EasyP v1 объявляет Git-зависимости в `protobuf.mod`. Если Git-зависимость использует конфигурацию Buf v1 или v2, EasyP читает её корни `.proto` для разрешения импортов. Старые конфиги EasyP в зависимостях поддерживаются таким же образом. Проект-потребитель использует отдельные `protobuf.mod`, `easyp.gen.yaml` и `easyp.yaml`.

Поддерживаемые форматы и ограничения описаны на странице [Git-зависимостей с конфигом Buf](/ru/docs/cli/package-manager/easyp-vs-buf).

- Безопасность приватных репозиториев
- Лёгкая интеграция в существующие пайплайны
