## Защита транспорта

| Режим | Настройки | Кто может подключиться |
|---|---|---|
| Без шифрования | нет `server.tls.cert_file` | Любой, кто достучался до порта. При старте в лог пишется предупреждение. Только для локальной разработки. |
| TLS | `server.tls.cert_file`, `server.tls.key_file` | Любой, кто достучался до порта; трафик шифруется. |
| Взаимный TLS | плюс `server.tls.client_ca_file` | Только клиенты с сертификатом, подписанным этим CA. |

Взаимный TLS проверяет центр сертификации и больше ничего — списка разрешённых
субъектов нет. Используйте CA, существующий только для этого сервиса, а не
корпоративный корень, подписавший тысячи сертификатов.

Сертификат и ключ читаются один раз при старте; после ротации нужен перезапуск
(Helm-чарт может сделать его через stakater/Reloader).

MCP-эндпоинт работает по обычному HTTP при любых этих настройках.

## Токены записи

Единственные учётные данные, которые понимает сервис, — статический
bearer-токен в gRPC-метаданных `authorization: Bearer <token>`.

```bash
easyp-svc auth new-token --name ci
```

один раз печатает случайный токен и запись, которая его разрешает:

```yaml
auth:
  write_tokens:
    - name: "ci"
      sha256: "4761f1d6…"
```

В конфигурации хранится только sha256-дайджест, так что это не секрет. `name`
обозначает вызывающего в логах и в аудите. В окружении:
`AUTH_WRITE_TOKENS=ci=<64 hex>,me=<64 hex>`. Имена должны быть уникальны.

| Метод | По умолчанию | С `auth.require_authentication: true` |
|---|---|---|
| `GenerateCode`, `Plugins` | анонимно | нужен токен |
| `CreatePlugin`, `UpdatePlugin`, `DeletePlugin` | нужен токен | нужен токен |
| gRPC Health | анонимно | анонимно |
| MCP `/mcp` | анонимно | нужен токен (без него HTTP 401) |

Пустой список `write_tokens` запрещает любую запись: забытая конфигурация ломает
регистрацию, а не оставляет реестр открытым.

Отказы считаются в `easyp_auth_failures_total{reason}` с
`reason="no_credentials"` или `reason="unknown_token"` и получают ответ
`UNAUTHENTICATED`.

<Callout type="warn">
easyp CLI не отправляет токен и не умеет предъявлять клиентский сертификат.
Сервисом с `auth.require_authentication: true` или listener'ом, требующим
взаимный TLS, из `easyp generate` напрямую пользоваться нельзя. Для доверенных
сетей поставьте перед ним прокси, который сам делает mTLS, или используйте Go
SDK — он поддерживает и то, и другое (`sdk.WithToken`,
`sdk.WithTransportCredentials`).
</Callout>

### Чего нет

- Пользователей, организаций, ролей и областей действия. Токен либо есть в
  списке, либо нет; любой токен записи может создать, изменить и удалить любой
  плагин.
- SSO, OIDC, LDAP, SCIM.
- Срока действия токенов. Отзыв — удалить дайджест и перезапустить.

## Community и Enterprise

Бинарник один; редакцию определяет лицензия. Без действующей лицензии сервис
работает как **Community**.

| | Community | Enterprise |
|---|---|---|
| Генерация кода, список плагинов | да | да |
| Создание/изменение/удаление плагинов | да | да |
| Ограничение частоты и параллельности | да | да |
| MCP-эндпоинт | да | да |
| Метрики Prometheus, трейсы, профили | да | да |
| **Журнал аудита в PostgreSQL** | нет | да |
| `worker_pool.workers` | не больше 4 | без потолка |
| `worker_pool.max_concurrent_generations` | не больше 16 | без потолка |
| Зарегистрированных версий плагинов | не больше 10 | без потолка |

Журнал аудита — единственная функция, которую добавляет Enterprise; остальное —
потолки. Работают они по-разному:

- **Потолки воркеров и генераций применяются при старте.** Значение выше потолка
  понижается, и сервис пишет в лог
  `worker_pool.workers lowered to the licence tier's limit` с обоими числами.
  Запуск он не прерывает. Значения по умолчанию (4 и 16) ровно равны потолкам
  Community, так что нетронутое развёртывание Community это не затрагивает.
- **Потолок плагинов проверяется на каждом `CreatePlugin`.** При 10
  зарегистрированных строках следующая регистрация падает с
  `RESOURCE_EXHAUSTED`, reason `MAX_PLUGINS_EXCEEDED`. Каждая версия — отдельная
  строка: `protocolbuffers/go` в трёх версиях занимает три.

Счётчик операций `easyp_operations_total` работает в обеих редакциях; без
лицензии записи аудита считаются в `easyp_audit_events_skipped_total` вместо
того, чтобы записываться.

## Как проверяется лицензия

Лицензия — токен PASETO v4.public, подписанный Ed25519. Проверка офлайновая:
сервис никуда не обращается.

1. Токен берётся из `license.key` (`LICENSE_KEY`) или из файла `license.file`.
2. Key id из футера токена выбирает публичный ключ из `license.public_keys`;
   запись под `"*"` проверяет любой key id. Helm-чарт поставляется с текущим
   публичным ключом easyp.tech (`2026-08`).
3. Публичный ключ не задан: токен игнорируется, сервис работает как Community и
   пишет предупреждение в лог. Ключ, который не декодируется, останавливает запуск.
4. Любая другая ошибка — неверная подпись, неизвестный key id — приводит к
   Community, а не к ошибке.

Токен называет редакцию; какие функции в неё входят, решает релиз, а не токен.

### Истечение и grace-период

- Токен может содержать `grace_days`. Без этого поля grace-период нулевой.
- После момента истечения (плюс минута допуска на расхождение часов) сервис
  сохраняет Enterprise ещё `grace_days`, выставляет `easyp_license_in_grace` в 1
  и пишет предупреждение.
- После grace-периода он переходит на Community и пишет
  `licence expired past its grace period; running in community mode`.
- Токен перепроверяется каждые `license.cache_ttl` (5 минут), поэтому редакция
  меняется на работающем сервисе. Замена самого токена требует перезапуска.

Для клиентов переход на Community незаметен: аудит прекращается, потолок
плагинов начинает отклонять регистрации сверх 10. Для этого есть алерты
[EasypLicenceExpiringSoon](/ru/docs/api-service/runbooks#easyplicenceexpiringsoon)
и [EasypLicenceInGrace](/ru/docs/api-service/runbooks#easyplicenceingrace).

<Callout type="info">
Якорь доверия — ваша конфигурация. Кто может править `license.public_keys`, тот
решает, какой издатель может выдавать лицензии для этой установки.
</Callout>

| Часть | Лицензия | Что это значит на практике |
|---|---|---|
| Сервис (`easyp-svc`, всё вне `api/` и `sdk/`) | Elastic License 2.0 | Можно запускать, в том числе в продакшене и коммерчески, и изменять. Нельзя предоставлять его третьим лицам как облачный или управляемый сервис и нельзя удалять или обходить механизм лицензионных ключей. Точные условия — в тексте лицензии. |
| `api/` (gRPC-контракт) и `sdk/` (Go-клиент) | Apache-2.0 | Отдельные Go-модули, так что программа, общающаяся с сервисом, импортирует только код под Apache-2.0. |
| Релизы до v0.8.0 включительно | Apache-2.0 | Остаются доступны на этих условиях. |

Elastic License — это source-available лицензия, а не одобренная OSI
open-source лицензия.
