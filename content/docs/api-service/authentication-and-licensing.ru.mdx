## Bearer-токены

Сервис использует статический список разрешённых SHA-256-хешей. Создайте токен локально операторским CLI:

~~~sh
easyp-svc auth new-token --name ci-registration
~~~
Сохраните выведенный токен в secret manager; в <code>auth.write&#95;tokens</code> внесите только его хеш с уникальным непустым именем. Команда генерирует 32 случайных байта и кодирует их в hex. Сервер сравнивает хеш bearer-значения с настроенными хешами. Имя — метка аудита, а не scope авторизации.

Формат переменной окружения: <code>AUTH&#95;WRITE&#95;TOKENS=name=sha256,name2=sha256</code>. Каждый хеш должен содержать ровно 64 шестнадцатеричных символа. Пустой список запрещает все изменения. Если аутентификация обязательна, а токенов нет, генерация и чтение также запрещены.

| Операция | По умолчанию | При <code>auth.require&#95;authentication: true</code> |
| --- | --- | --- |
| <code>GenerateCode</code>, <code>Plugins</code> | Анонимны; переданный токен на обходящих проверку методах не устанавливает actor. | Нужен bearer-токен. |
| <code>CreatePlugin</code>, <code>UpdatePlugin</code>, <code>DeletePlugin</code> | Нужен bearer-токен. | Нужен bearer-токен. |
| MCP <code>plugins&#95;list</code> | Анонимен, если MCP включён. | HTTP wrapper требует bearer-токен. |
| Health | Прикладной токен не требуется. | Прикладной токен не требуется. |

Отсутствующий, некорректный или неизвестный credential приводит к <code>Unauthenticated</code>; подробности отказа не используются как подсказки о валидности токена. Здесь нет OAuth/OIDC login, SSO, ролей организаций, истечения токенов или scopes на плагины. Все принятые токены дают одинаковый прикладной доступ. Для ротации или отзыва измените хеши в конфигурации и перезапустите сервис.

<code>EASYP&#95;TOKEN</code> — клиентский fallback для **<code>easyp-svc plugins register</code>**. Это не настройка аутентификации сервера; проверенный remote executor в <code>easyp</code> её не читает. См. [Использование клиентами](./client-usage).

## TLS и mTLS

~~~yaml
server:
  tls:
    cert_file: /run/tls/tls.crt
    key_file: /run/tls/tls.key
    client_ca_file: /run/tls/ca.crt
~~~
Пара сертификата и ключа включает gRPC TLS с минимальной версией TLS 1.3 на сервере. <code>client&#95;ca&#95;file</code> дополнительно требует проверенный клиентский сертификат. Для TLS только с аутентификацией сервера не задавайте этот ключ. Сертификаты должны читаться при старте; ротируйте их средствами развёртывания. Статические прикладные токены и лицензия также загружаются при старте.

mTLS проверяет транспортную идентичность через CA, но не даёт прикладную роль и не заменяет bearer-проверки. Операторский клиент регистрации принимает <code>--tls-ca</code>, <code>--tls-cert</code> и <code>--tls-key</code>. Флаг <code>--insecure</code> означает **plaintext**, а не «TLS без проверки сертификата»; используйте его только в изолированной разработческой среде.

Дефолты Helm отличаются от бинарника: TLS включён, а пустой <code>tls.clientCASecret</code> использует <code>ca.crt</code> из серверного Secret, фактически запрашивая mTLS. Значение <code>tls.clientCASecret: "-"</code> выбирает server-only TLS. См. [Установка](./installation). MCP — отдельный HTTP listener, который не наследует эти настройки TLS.

## Community / Enterprise

| Возможность или потолок | Community | Enterprise |
| --- | --- | --- |
| Генерация, каталог, CRUD плагинов, MCP, rate limiting | Доступны с учётом аутентификации и конфигурации. | Доступны. |
| Lookup workers | До 4. | Лицензионного потолка нет; число workers всё равно задаётся конфигурацией. |
| Зарегистрированные версии плагинов | До 10 строк, не десять семейств плагинов. | Лицензионного потолка нет. |
| Одновременные генерации | До 16. | Лицензионного потолка нет; семафор конфигурации сохраняется. |
| Запись аудита Core | Пропускается. | Включена. |

В реализации отсутствие лицензионного потолка обозначено <code>-1</code>; не переносите это значение в поля конфигурации, требующие положительные числа. При старте число workers и генераций ограничивается положительными потолками лицензии, эффективные значения выводятся в лог. Новые регистрации проверяют текущий потолок числа плагинов и при его достижении возвращают <code>ResourceExhausted</code>; существующие строки автоматически не удаляются.

Обновление claims не меняет уже созданный пул. После перехода Enterprise-лицензии в Community меняются допуск аудита и ограничение новых регистраций, но выбранная при старте ёмкость workers и генераций сохраняется до рестарта. Аналогично, установка лицензии без рестарта не расширяет Community-пул. Индивидуальные ресурсные потолки из токена в этой реализации не читаются.

## Проверка лицензии и истечение

Enterprise использует офлайн-проверку токена **PASETO v4.public** с публичными ключами Ed25519. Токен задаётся через <code>license.key</code> или путь <code>license.file</code>; значение key имеет приоритет. Доверенные ключи издателя задаются в <code>license.public&#95;keys</code>: map от key ID к 32-байтному публичному ключу в hex. Запись <code>"&#42;"</code> служит fallback, когда подходящий именованный ключ не выбран. Получайте лицензию и доверенные ключи через уполномоченную процедуру лицензиара; команды выдачи клиентской лицензии в этом сервисе нет.

Verifier проверяет issuer <code>easyp.tech</code>, audience <code>easyp-service</code>, Enterprise tier, сроки действия и необязательный claim <code>grace&#95;days</code>. Допускается рассинхронизация часов в одну минуту. Grace по умолчанию равен нулю. Валидный токен в разрешённом grace-интервале сохраняет Enterprise claims; после grace либо при невалидном или непроверяемом токене результатом становятся Community claims. Неправильный формат публичного ключа — ошибка старта. Нечитаемый настроенный файл лицензии — ошибка конфигурации или preflight, а не успешный старт Community.

Claims обновляются с периодом <code>license.cache&#95;ttl</code>, по умолчанию пять минут. Токен читается один раз: refresh проверяет закэшированный токен относительно текущего времени, а не новое содержимое файла. Одна замена файла его не перезагружает. При неожиданной ошибке verifier менеджер сохраняет прежние claims; штатная обработка невалидного или истёкшего токена возвращает Community без такой ошибки. Следите за метриками expiry/grace и планово перезапускайте сервис после ротации лицензии.
