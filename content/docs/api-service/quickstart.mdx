This walk-through runs the service with the least possible around it: one
PostgreSQL container, the released image, no object storage, no TLS. It is for
seeing the moving parts, not for exposing to a network.

## Prerequisites

- Docker with the compose plugin.
- A checkout of [easyp-tech/service](https://github.com/easyp-tech/service) —
  plugin binaries are built from its `registry/` directory.
- Go 1.26+ to run the operator CLI from source, or the `easyp-svc` binary from the
  [releases page](https://github.com/easyp-tech/service/releases).
- The [easyp CLI](/docs/introduction/install).

## 1. Build a plugin

Plugins are built from the Dockerfiles in `registry/`. Building the whole
catalogue takes hours; a filter builds one version:

```bash
cd service
go run ./cmd/easyp-svc plugins build registry \
  --output plugins \
  --filter 'protocolbuffers/go:v1.36.10'
```

The result is `plugins/protocolbuffers/go/v1.36.10/plugin`. The build runs in
Docker, so the binary is a Linux binary: it runs inside the service container,
not natively on macOS.

## 2. Create a write token

Registering a plugin is a write, and writes need a token. The service stores only
its sha256:

```bash
go run ./cmd/easyp-svc auth new-token --name quickstart
```

The command prints the token once and the `name`/`sha256` pair the service
needs. Keep both.

## 3. Start PostgreSQL and the service

Save as `compose.yml` next to the `plugins/` directory, with the digest from
step 2:

```yaml
services:
  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: easyp
      POSTGRES_PASSWORD: easyp
      POSTGRES_DB: easyp
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "easyp"]
      interval: 2s
      retries: 30

  service:
    image: ghcr.io/easyp-tech/service:v1.3.2
    command: ["service", "start"]
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      DB_POSTGRES_DSN: postgres://easyp:easyp@postgres:5432/easyp?sslmode=disable
      AUTH_WRITE_TOKENS: quickstart=<sha256 from step 2>
    volumes:
      - ./plugins:/plugins
    ports:
      - "127.0.0.1:23410:23410"   # gRPC
      - "127.0.0.1:23411:23411"   # metrics
      - "127.0.0.1:23412:23412"   # health
```

```bash
docker compose up -d
curl -i http://localhost:23412/live   # 200 once the process is up
curl -i http://localhost:23412/       # 200 once PostgreSQL answers
```

The service applies its database migrations on start. Its log begins with a
`configuration resolved` line listing every setting that differs from the
default, and warns that gRPC is running without TLS.

<Callout type="warn">
Mount `plugins/` read-write. The service creates `plugins/.tmp` on start even
without object storage, and a read-only mount stops it with
`mkdir /plugins/.tmp: read-only file system`.

The image runs as UID and GID 65532, not as root. On Linux the bind-mounted
directory keeps its host owner, so it must be writable by that user:
`sudo chown -R 65532:65532 plugins`, or set `user:` on the service to your own
UID and GID (`id -u`, `id -g`), for example `user: "1000:1000"`. Docker Desktop
on macOS maps ownership itself.
</Callout>

## 4. Register the plugin

```bash
EASYP_TOKEN=<token from step 2> \
go run ./cmd/easyp-svc plugins publish \
  --plugins-dir plugins \
  --addr localhost:23410 \
  --insecure
```

With neither a registry path nor `--archives`, `publish` takes `--plugins-dir`
as its source: it walks `plugins/` and calls `CreatePlugin` for each version
found there. The service derives the command path itself
(`/plugins/protocolbuffers/go/v1.36.10/plugin`), so the client never needs to
know where the directory is mounted. Without the token `publish` stops before
registering anything, because the service refuses it. Needs a v1.2.0 or newer
service.

## 5. Generate code

In a project with `.proto` files (for example with `roots proto` in
`protobuf.mod`), create `easyp.gen.yaml`:

```yaml
# easyp.gen.yaml
version: v1
plugins:
  - remote: localhost:23410/protocolbuffers/go
    version: v1.36.10
    out: gen/go
    opts:
      paths: source_relative
```

```bash
easyp generate
```

The CLI talks plaintext to `localhost` and TLS to any other host. EasyP v1
requires an explicit semver `version:` field in `easyp.gen.yaml` and rejects
`:version` inside `remote:` or `latest`. On EasyP v0.17, configure the same
plugin in `easyp.yaml` under `generate.plugins` as
`remote: "localhost:23410/protocolbuffers/go:v1.36.10"`. See
[Client usage](/docs/api-service/client-usage).

## Running from source

The service repository carries no development stack of its own. To run the
binary from a checkout against your own PostgreSQL instead of the image, see
[From source](https://github.com/easyp-tech/service#from-source) in its README.
On macOS keep the image: plugins built by `plugins build` are Linux binaries,
and a service running natively fails them with `exec format error`.
