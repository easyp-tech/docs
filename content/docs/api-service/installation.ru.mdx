## Требования к развёртыванию

Каждому развёртыванию нужны PostgreSQL и доступный учётной записи сервиса каталог доверенных исполняемых файлов плагинов. S3-совместимое хранилище необязательно. Новая БД мигрируется при старте; роли БД нужны соответствующие DDL-права. Установка сервера не устанавливает и не регистрирует каталог плагинов. См. [Плагины](./plugins).

Страница следует релизу сервиса/SDK **v1.0.2**, Helm-чарту **1.0.2** (appVersion **v1.0.2**) и Go **1.26.6** из проверенных manifests. Проверенный runtime-код совпадает с релизом; последующие изменения касаются документации и healthcheck development Compose.

## Docker-образ и каналы релизов

Release workflow задаёт имя образа <code>ghcr.io/easyp-tech/service</code>. Каналы имеют разный смысл:

| Тег | Значение | Как выбирать |
| --- | --- | --- |
| <code>v1.0.2</code> / <code>vX.Y.Z</code> | Версионный релиз. | Согласуйте конфигурацию и release notes; сохраните разрешённый digest. |
| <code>latest</code> | Последний опубликованный релиз, не текущий master. | Изменяемый тег; не является гарантией воспроизводимости. |
| <code>edge</code> | Успешная сборка master. | Подвижный канал разработки, не обещание релизной стабильности. |
| <code>sha-&lt;семь символов commit&gt;</code> | Edge-сборка определённого commit. | Точнее edge, но неизменяемый идентификатор содержимого — digest. |

Workflows собирают Linux amd64 и arm64. Версионные и commit-теги — соглашение об именовании, не доказательство запрета их замены реестром. Доступность опубликованных образов и чарта в рамках этого аудита не проверялась.

Entrypoint образа — <code>/easyp-svc</code>, **дефолтной команды нет**: передайте <code>service start</code>. Runtime — Debian Bookworm slim с CA-сертификатами и UID/GID 65532; он не включает все языковые runtimes произвольных плагинов. Смонтируйте конфигурацию и задайте <code>EASYP&#95;CONFIG</code>, чтобы отдельный healthcheck образа видел тот же файл:

~~~sh
docker run --rm --name easyp-service \
  -e EASYP_CONFIG=/run/easyp/service.yaml \
  -p 127.0.0.1:23410:23410 \
  -p 127.0.0.1:23412:23412 \
  --mount type=bind,src="$PWD/service.yaml",dst=/run/easyp/service.yaml,readonly \
  --mount type=bind,src="$PWD/plugins",dst=/plugins \
  ghcr.io/easyp-tech/service:v1.0.2 service start
~~~
Подготовьте <code>service.yaml</code> с БД, доступной **из контейнера**. <code>localhost</code> внутри контейнера — не PostgreSQL хоста. Том плагинов должен разрешать UID 65532 чтение и исполнение, а при распаковке S3-кэша — запись. Разработческие опубликованные порты привязывайте к loopback; до внешней публикации настройте TLS и доступ. Healthcheck образа проверяет liveness <code>/live</code>, не readiness БД.

Сборка из исходников без обращения к GHCR:

~~~sh
git clone --branch v1.0.2 https://github.com/easyp-tech/service.git
cd service
docker build --build-arg VERSION=v1.0.2 -t easyp-service:local .
~~~
Шаги Dockerfile могут скачивать зависимости и базовые образы. Это не рецепт air-gapped сборки: для отключённой среды заранее подготовьте и проверьте эти артефакты.

## Compose

В репозитории есть development Compose и более крупный deployment/observability stack. Последний содержит специфичные для размещения маршрутизацию, credentials, предположения о tiers и сервисы телеметрии; это не универсальная production-установка одной командой. Для одной БД PostgreSQL, одного сервиса и одного плагина используйте изолированный [быстрый старт](./quickstart). Не копируйте production hostnames и credentials из исторических примеров.

Перед запуском изучите <code>docker compose config</code>. Согласуйте путь конфигурации сервера и healthcheck через <code>EASYP&#95;CONFIG</code> либо явный <code>--cfg</code> healthcheck. Готовность БД и реальная генерация проверяются отдельно.

## Отдельные бинарники

Конфигурация GoReleaser собирает <code>easyp-svc</code> для Linux и macOS, amd64 и arm64, с выключенным CGO. Архивы именуются <code>easyp-svc&#95;1.0.2&#95;&lt;os&gt;&#95;&lt;arch&gt;.tar.gz</code> и содержат LICENSE и README; release workflow также создаёт checksums и software-bill-of-materials. Возьмите нужный архив из [релиза сервиса](https://github.com/easyp-tech/service/releases/tag/v1.0.2), проверьте checksum и сохраните точный артефакт. В этом аудите собирались локальные бинарники, но скачиваемые release assets не проверялись.

~~~sh
go build -trimpath -ldflags='-X main.version=v1.0.2' \
  -o ./easyp-svc ./cmd/easyp-svc
./easyp-svc config validate --cfg ./service.yaml
./easyp-svc service start --cfg ./service.yaml
~~~
Версия Go из go.mod — требование сборки исходников. Linux-executable, извлечённый при сборке плагина, не становится исполняемым на macOS-сервере из-за наличия операторского бинарника для macOS. Согласуйте артефакт и sidecars каждого плагина с ОС, архитектурой и установленным runtime сервера.

## Установка Helm

Адрес чарта — <code>oci://ghcr.io/easyp-tech/charts/easyp-service</code>. Он развёртывает сервис, не PostgreSQL и объектное хранилище. Заранее подготовьте Kubernetes Secret с <code>DB&#95;POSTGRES&#95;DSN</code> и нужными <code>AUTH&#95;WRITE&#95;TOKENS</code>, лицензией или S3 credentials в формате окружения; альтернатива — <code>secrets.create</code> и <code>secrets.data</code> из защищённого источника values. Не коммитьте credentials в values-файл.

При включённом TLS задайте <code>tls.serverSecret</code> либо включите cert-manager с настроенным issuer. Пустой <code>tls.clientCASecret</code> по умолчанию означает, что серверный Secret должен также содержать <code>ca.crt</code>, а сервис требует клиентские сертификаты. Значение <code>"-"</code> выбирайте только при осознанном использовании server-only TLS без mTLS. Прикладная bearer-аутентификация остаётся независимой.

~~~yaml
secrets:
  existingSecret: easyp-service-env
tls:
  enabled: true
  serverSecret: easyp-service-tls
  clientCASecret: "-"
extraEnv:
  - name: AUTH_REQUIRE_AUTHENTICATION
    value: "true"
~~~
Пример требует клиента, умеющего передавать bearer-токен, например Go SDK; текущий remote executor <code>easyp</code> этого не умеет. Также нужен способ доставки артефактов: настроенный S3 либо заполненный локальный том плагинов.

~~~sh
helm template easyp ./deploy/charts/easyp-service --values values.yaml
helm upgrade --install easyp oci://ghcr.io/easyp-tech/charts/easyp-service \
  --version 1.0.2 --namespace easyp --create-namespace --values values.yaml
~~~
Первая команда рендерит локальный checkout; вторая устанавливает сервис в кластер пользователя и обращается к реестру. Это инструкции, не действия, выполненные аудитом.

## Обязательные и опасные настройки чарта

Дефолтное развёртывание одной реплики использует Recreate и ReadWriteOnce-том. Несколько реплик с RWO чарт отклоняет. Хотя RWX проходит эту проверку, у кэша плагинов нет межпроцессной координации: не превращайте обход валидации в рекомендацию HA с общим кэшем. Планируйте отдельные кэши и проверяйте всю топологию.

Хранилище должно быть строго больше положительного cache budget. При выключенном persistence лимит ephemeral-storage также должен превышать лимит emptyDir; простое выключение persistence с дефолтными 2 GiB лимита ресурса и 25 GiB emptyDir не проходит рендеринг. Проверка памяти вычисляет <code>2 × maxConcurrentGenerations × maxOutputSize</code>; это не предел памяти дочернего процесса и не полная модель ресурсов. Завершение должно удовлетворять <code>terminationGracePeriodSeconds &gt; forceShutdownAfterSeconds &gt; generationTimeoutSeconds</code>.

Ingress требует hostname и CIDR доверенных proxy. Текущая валидация чарта дополнительно требует клиентский сертификат для включённого ServersTransport, даже когда <code>clientCASecret: "-"</code> выбирает server-only TLS: это ограничение чарта, не требование mTLS сервиса. Специфичные для Traefik ресурсы требуют соответствующих CRD и настройки controller.

NetworkPolicy по умолчанию включена. Пустой ingress namespace selector не ограничивает gRPC-клиентов выбранным namespace. Разрешённые egress-порты не являются списком доверенных адресатов. **Шаблон не добавляет ingress-правило для MCP при его включении**; для разрешённого доступа к MCP нужна отдельно проверенная дополнительная политика. Дефолтный egress также не включает все возможные порты S3 и профилирования.

Для ServiceMonitor и PrometheusRule нужны monitoring CRD. Аннотация reloader работает только при установленном совместимом reloader controller; встроенного hot-reload секретов она не создаёт. Учитывайте права и раскрытие метрик и health как эксплуатационных данных.
