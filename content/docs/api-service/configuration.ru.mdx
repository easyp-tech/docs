Таблица ниже сгенерирована из проверенных структур конфигурации и <code>config.Defaults</code>, а не из примеров развёртывания. Она содержит все **55 настроек сервиса** с отображением на переменные окружения. Это **дефолты бинарника**; Helm и Compose могут их переопределять. Длительности задаются в формате Go, например <code>120s</code> или <code>5m</code>; размеры — целыми числами байтов. Пустая строка означает отсутствие значения, а не рабочее подключение к БД.

## Приоритеты и проверка

Непустые переменные окружения приоритетнее явно заданного YAML, YAML — приоритетнее встроенных дефолтов. Явный ноль или false в YAML сохраняется и затем проверяется. Пустые переменные окружения считаются незаданными. Неизвестные ключи YAML и несколько YAML-документов отклоняются; размер конфигурационного файла ограничен 1 MiB. Неизвестные имена переменных с распознаваемыми префиксами сервиса вызывают диагностику, а не становятся настройками молча.

~~~sh
easyp-svc config validate --cfg service.yaml
easyp-svc config print --cfg service.yaml --origin
easyp-svc config print --cfg service.yaml --changed
~~~
По умолчанию <code>config print</code> скрывает значения, помеченные как секреты. Не отправляйте вывод <code>--show-secrets</code> в логи CI или заявку поддержки. Валидация проверяет локальную конфигурацию и preflight-требования, но не соединение с БД и не реальную генерацию.

## Составные значения и дополнительные переменные

<code>auth.write&#95;tokens</code> — YAML-список объектов с ключами <code>name</code> и <code>sha256</code>. У полей исходника есть теги <code>env:"NAME"</code> и <code>env:"SHA256"</code>, но список реализует собственный decoder: поддерживается **<code>AUTH&#95;WRITE&#95;TOKENS=ci=HASH,operator=HASH</code>**, а не независимые переменные <code>NAME</code> и <code>SHA256</code>. Хеш содержит ровно 64 hex-символа, имена должны быть непустыми и уникальными.

<code>license.public&#95;keys</code> — YAML-map. Формат окружения: <code>LICENSE&#95;PUBLIC&#95;KEYS="key-id:HEX,&#42;:FALLBACK&#95;HEX"</code>; каждый публичный ключ содержит 64 hex-символа. <code>server.trusted&#95;proxies</code> задаётся YAML-последовательностью или списком через запятую в <code>SERVER&#95;TRUSTED&#95;PROXIES</code>.

<code>OTEL&#95;EXPORTER&#95;OTLP&#95;ENDPOINT</code> принимается как alias для <code>TELEMETRY&#95;OTLP&#95;ENDPOINT</code>; при наличии обоих приоритет имеет каноническая переменная сервиса. Старые <code>TELEMETRY&#95;OTEL&#95;EXPORTER&#95;OTLP&#95;ENDPOINT</code>, <code>LICENSE&#95;PUBLIC&#95;KEY</code>, <code>license.public&#95;key</code> и <code>db.driver</code> не являются текущими настройками: учитывайте диагностику и мигрируйте, а не копируйте старые примеры. Когда статические credentials S3 не заданы, их поиск делегирован default credential chain закреплённой версии AWS SDK; его переменные, файлы и instance roles — поведение SDK, не дополнительные YAML-ключи EasyP.

**<code>EASYP&#95;CONFIG</code> выбирает файл конфигурации для команд с <code>--cfg</code>.** Контейнерный healthcheck — отдельный процесс: запуск сервера с <code>--cfg /run/service.yaml</code> не передаёт этот аргумент в <code>easyp-svc health</code>. Задайте <code>EASYP&#95;CONFIG=/run/service.yaml</code> для обоих процессов либо передайте <code>--cfg</code> явно в обе команды. <code>health --addr</code> переопределяет определение адреса и проверяет <code>/live</code>, а не readiness.

**<code>EASYP&#95;TOKEN</code> читает только операторский клиент регистрации как fallback для <code>--token</code>.** Эта переменная не задаёт разрешённые серверу токены; проверенный remote executor CLI <code>easyp</code> её не читает.

## Связанные ограничения

Все четыре порта должны быть допустимыми и различаться. Сертификат TLS и ключ задаются вместе; client CA требует TLS. Число workers, размер очереди, бюджеты исполнения и завершения, лимиты сообщений и вывода должны проходить валидацию. В частности, <code>server.force&#95;shutdown&#95;after</code> должен превышать <code>worker&#95;pool.generation&#95;timeout</code>, а предел исходящего сообщения не может быть меньше разрешённого вывода плагина. Ненулевой бюджет кэша не должен быть меньше лимита вывода. Параметры bucket, endpoint и credentials S3 должны быть согласованы.

Wire-ответ оборачивает вывод плагина, поэтому одинаковые пределы байтов для сырого вывода и содержащего его gRPC-сообщения не гарантируют доставку точно на границе размера. Оставляйте запас транспорта и согласуйте лимит приёма клиента.
