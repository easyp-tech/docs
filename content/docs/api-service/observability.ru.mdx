По умолчанию бинарник публикует Prometheus text на <code>http://127.0.0.1:23411/metrics</code>. Helm использует metrics-порт 8081. Оставляйте endpoint в разрешённой сети мониторинга: координаты плагинов, показатели БД и активность ошибок являются эксплуатационной информацией.

## Справочник Prometheus

Ниже перечислены labels инструментации. Prometheus/Alloy может добавлять <code>job</code>, <code>instance</code>, <code>tier</code> и метки развёртывания; это не дополнительные прикладные labels каждой метрики. Histogram families создают серии <code>&#95;bucket</code>, <code>&#95;sum</code> и <code>&#95;count</code>, причём у buckets появляется <code>le</code>. <code>plugin</code> — разрешённые координаты group/name:version.

Сервер также регистрирует стандартные Go- и process-collectors закреплённой версии Prometheus client (<code>go&#95;&#42;</code>, <code>process&#95;&#42;</code>). Их точный набор зависит от runtime и ОС и не является контрактом конфигурации EasyP. Business collectors обращаются к БД при scrape; при ошибке запроса соответствующая серия может отсутствовать, а не содержать ноль. Отсутствие серии не означает пустой каталог или отсутствие событий аудита.

## Трейсы, логи и профили

<code>telemetry.otlp&#95;endpoint</code> включает **OTLP/gRPC traces и metrics**. В этой реализации адрес <code>host:port</code> без схемы выбирает незащищённый транспорт; когда нужен TLS, задавайте явный URL <code>https://</code> и соответствующим образом настраивайте collector. Настройки TLS gRPC-сервера не конфигурируют экспортёр. В trace resources входят <code>service.name=easyp</code>, версия сборки и необязательный настроенный tier. Эта метка не синхронизируется автоматически с claims лицензии. OTLP metrics используют periodic reader с интервалом 15 секунд.

Trace wrappers охватывают операции Core, доступ к registry, генерацию и <code>process.exec</code>. Настроен W3C trace-context propagation; структурированные логи содержат trace/span IDs при их наличии в context. Сервис не экспортирует логи напрямую через OTLP log exporter; поставляемый observability stack собирает логи контейнеров отдельно. Histogram OpenTelemetry <code>plugin.execution.duration</code> измеряется в секундах и имеет label <code>plugin.name</code>; не смешивайте его с Prometheus histogram попыток исполнения.

<code>telemetry.pyroscope&#95;endpoint</code> включает профили CPU, allocations, in-use memory и goroutines **Go-процесса сервиса**. Plugin tag связывает работу на стороне сервиса с плагином, но не делает доступным CPU-профиль самого дочернего executable. Ошибки инициализации экспортёров записываются в лог; сервис может продолжить работу без этой телеметрии. Ни readiness, ни liveness не подтверждают доставку экспортёру.

## Алерты и дашборды

Helm-чарт может создавать <code>ServiceMonitor</code> и <code>PrometheusRule</code>; нужны соответствующие monitoring CRD, а обе функции по умолчанию выключены. Чарт определяет одиннадцать прикладных алертов. В Compose observability tree есть те же прикладные алерты и ещё шесть алертов хоста, discovery и сертификатов. Для каждого предусмотрен [runbook](./runbooks). Метрики хоста создаёт поставляемый Alloy Unix exporter; метрика сертификата относится к Traefik, не к <code>easyp-svc</code>.

Поставляемый generation-error ratio делит ошибки попыток исполнения на принятые lookup jobs. Из-за retry и ошибок до исполнения это **не точная доля неудачных RPC конечных пользователей**. Для RPC failure SLI используйте handled-RPC counter и явно определите, какие gRPC-коды считать ошибками. В клиентской синтетической проверке также учитывайте сбои транспорта и результаты с <code>CodeGeneratorResponse.error</code>.

<code>EasypServiceMissing</code> предполагает наличие обоих targets — Community и Enterprise — с поставляемыми Alloy job/tier labels. Для развёртывания одного tier измените или выключите ветку отсутствующего tier, иначе алерт будет срабатывать на его намеренное отсутствие. <code>EasypTargetDown</code> использует <code>up == 0</code> для обнаруженных targets, не только для endpoint генерации.

Cache alert отслеживает мягкий бюджет S3-кэша, не свободное место файловой системы. Gauge DEFAULT-партиции аудита обычно обновляется только во время обслуживания раз в шесть часов; ошибка обслуживания может оставить старое значение. Во время инцидента проверяйте БД прямым read-only запросом. См. [Runbooks](./runbooks), [Архитектура](./architecture) и [Резервное копирование](./backup).
