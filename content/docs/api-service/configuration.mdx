The table below is generated from the checked service configuration structs and <code>config.Defaults</code>, not from deployment examples. It contains all **55 service settings** with an environment mapping. These are **binary defaults**; Helm and Compose can override them. Durations use Go duration notation such as <code>120s</code> or <code>5m</code>; byte limits are integer bytes. Empty strings mean no configured value, not a usable database connection.

## Resolution and inspection

Non-empty environment values override explicit YAML values, which override built-in defaults. An explicit YAML zero or false is preserved, then validated. Empty environment values are treated as unset. Unknown YAML keys and multiple YAML documents are rejected; configuration files are limited to 1 MiB. Unknown environment names under recognized service prefixes produce diagnostics rather than silently becoming settings.

~~~sh
easyp-svc config validate --cfg service.yaml
easyp-svc config print --cfg service.yaml --origin
easyp-svc config print --cfg service.yaml --changed
~~~
<code>config print</code> masks secret-tagged values by default. Do not send <code>--show-secrets</code> output to CI logs or a support ticket. Validation checks local configuration/preflight requirements but is not a database connection test or a real generation.

## Compound values and additional environment inputs

<code>auth.write&#95;tokens</code> is a YAML list of objects with <code>name</code> and <code>sha256</code> keys. The source fields have <code>env:"NAME"</code> and <code>env:"SHA256"</code> tags, but the list implements its own decoder: the supported environment input is **<code>AUTH&#95;WRITE&#95;TOKENS=ci=HASH,operator=HASH</code>**, not independent <code>NAME</code> or <code>SHA256</code> variables. A hash is exactly 64 hexadecimal characters and names must be unique and non-empty.

<code>license.public&#95;keys</code> is a YAML map. Its environment encoding is <code>LICENSE&#95;PUBLIC&#95;KEYS="key-id:HEX,&#42;:FALLBACK&#95;HEX"</code>; each public key has 64 hexadecimal characters. <code>server.trusted&#95;proxies</code> uses a YAML sequence or a comma-separated <code>SERVER&#95;TRUSTED&#95;PROXIES</code> value.

<code>OTEL&#95;EXPORTER&#95;OTLP&#95;ENDPOINT</code> is an accepted alias of <code>TELEMETRY&#95;OTLP&#95;ENDPOINT</code>; the canonical service variable wins when both are set. The old <code>TELEMETRY&#95;OTEL&#95;EXPORTER&#95;OTLP&#95;ENDPOINT</code>, <code>LICENSE&#95;PUBLIC&#95;KEY</code>, <code>license.public&#95;key</code>, and <code>db.driver</code> are not current settings: heed diagnostics and migrate rather than copying old examples. When static S3 credentials are omitted, credential discovery is delegated to the pinned AWS SDK default credential chain; its environment/files/instance-role inputs are SDK behavior, not additional YAML keys in EasyP.

**<code>EASYP&#95;CONFIG</code> selects the configuration file for commands with <code>--cfg</code>.** A container healthcheck is a separate process: starting the server with <code>--cfg /run/service.yaml</code> does not pass that argument to <code>easyp-svc health</code>. Set <code>EASYP&#95;CONFIG=/run/service.yaml</code> for both, or pass <code>--cfg</code> explicitly in both commands. <code>health --addr</code> overrides address discovery and probes <code>/live</code>, not readiness.

**<code>EASYP&#95;TOKEN</code> is read only by the operator registration client as a fallback for <code>--token</code>.** It does not configure accepted server tokens and the checked <code>easyp</code> CLI remote executor does not read it.

## Cross-field constraints

All four ports must be valid and distinct. TLS certificate and key must be configured together; a client CA requires TLS. Worker counts, queue size, execution and shutdown budgets, and message/output limits must satisfy validation. In particular, <code>server.force&#95;shutdown&#95;after</code> must exceed <code>worker&#95;pool.generation&#95;timeout</code>, and the send-message limit cannot be lower than the permitted plugin output. A nonzero cache budget must not be lower than the output bound. S3 settings must form a coherent bucket/endpoint/credential configuration.

The wire response wraps plugin output, so allowing exactly the same maximum byte count for raw output and the surrounding gRPC message does not guarantee delivery of a response at the exact boundary. Leave transport headroom and align the client's receive limit as well.
