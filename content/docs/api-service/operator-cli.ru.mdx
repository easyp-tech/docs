`easyp-svc` — один бинарник с шестью группами команд. Сервер — одна из них
(`service start`); остальное оператор запускает с ноутбука или из CI.

```
easyp-svc service start
easyp-svc plugins build | publish
easyp-svc auth new-token
easyp-svc api descriptor
easyp-svc config validate | print
easyp-svc health
```

Глобальные флаги: `--help`/`-h`, `--version`/`-v`.

Каждая команда с `--cfg` читает путь и из `EASYP_CONFIG`.

## service start

Запускает listener'ы gRPC, метрик, health и (если включён) MCP.

| Флаг | Смысл |
|---|---|
| `--cfg string` | Путь к YAML-конфигу. Без него — конфигурация только из окружения. |
| `--log-level string` (также `--log_level`) | `debug`, `info`, `warn`, `error`. Переопределяет `log.level`. |

## plugins build

`easyp-svc plugins build [options] <registry-path>`

Собирает бинарники плагинов по Dockerfile'ам реестра, ничего не загружая. Нужен
Docker. Каждая версия из `plugin.yaml` собирается с `--build-arg VERSION=…`, а
файловая система образа распаковывается в `<output>/{group}/{name}/{version}/`.
Затем каждая версия проверяется так, как её будет запускать сервис: упаковывается
и распаковывается распаковщиком сервиса и пробно запускается в runtime-образе;
от версии, не прошедшей проверку, остаётся только `build.log`.

С `--archive` от каждой версии остаётся только проверенный
`<output>/{group}/{name}/{version}/plugin.tgz` — дерево, которое принимает
`plugins publish --archives`, чтобы собирать на одной машине, а публиковать с
другой.

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--output`, `-o` | `plugins` | Каталог результата. |
| `--archive` | false | Оставить от каждой версии только проверенный `plugin.tgz` вместо распакованного бандла. |
| `--filter` | — | Glob по `group/name[:version]`, например `protocolbuffers/*`, `grpc/go:v1.5.1`. |
| `--parallel`, `-p` | `4` | Одновременных Docker-сборок. |
| `--force` | false | Пересобрать, даже если версия уже собрана. Версия, собранная более старым `easyp-svc`, не проверялась так, как проверяет этот, и пересобирается только с этим флагом. |
| `--dry-run` | false | Показать, что будет собрано. |
| `--non-interactive` | false | Без интерактивного интерфейса и прогресс-баров. |
| `--keep-going` | **true** | Продолжать после неудачной сборки. |
| `--runtime-image` | `debian:trixie-slim` | Образ, в котором пробно запускается каждый собранный плагин; должен совпадать с базой образа сервиса. |
| `--no-smoke` | false | Не запускать плагин. Архив всё равно проверяется на распаковку тем же способом, что в сервисе. |
| `--platform` | как у этой машины | Платформа сборки и пробного запуска, например `linux/amd64`. Пробный запуск под другую архитектуру идёт через эмуляцию Docker. |

## plugins publish

`easyp-svc plugins publish [options] [registry-path]`

Проводит каждую версию за один проход: собирает её из реестра (или берёт её
`plugin.tgz` из `--archives`), проверяет, загружает архив в
`{prefix}{group}/{name}/{version}/plugin.tgz` с sha256 в метаданных объекта,
регистрирует — `CreatePlugin`, или `UpdatePlugin` для версии, которая у сервиса
уже есть, — и удаляет локальную копию, прежде чем место понадобится следующей
версии. Нужен сервер v1.2.0 или новее; на более старом команда останавливается на
первой регистрации и сообщает об этом.

Источник — ровно один из:

- **путь к реестру**, собираемый версия за версией;
- `--archives <dir>` — дерево `{group}/{name}/{version}/plugin.tgz`, записанное
  `plugins build --archive`;
- ни того ни другого, но `--plugins-dir`: регистрируется то, что уже распаковано
  в этом каталоге.

Назначение: объектное хранилище, заданное S3-флагами и `--cfg`; или, с
`--plugins-dir <dir>`, этот каталог — `plugins_dir` сервиса на той же машине,
работающего без объектного хранилища, — куда каждый архив распаковывается вместо
загрузки.

Команда идемпотентна. Без `--force` версия, которая зарегистрирована и лежит в
хранилище, пропускается; лежащая в хранилище, но не зарегистрированная — только
регистрируется; загрузка пропускается, если в хранилище уже тот же архив.
Прерванный запуск продолжается повторным запуском. `--force` пересобирает и
перепубликует всё, что подходит под фильтр (см.
[Плагины](/ru/docs/api-service/plugins#republishing)). Прежде чем что-то
собирать, `publish` проверяет, что хранилище отвечает, что сервис принимает
токен, и какие версии у сервиса уже есть.

Плагины собираются и пробно запускаются под платформу, которую сообщает сервис,
например `linux/amd64`, так что Mac на Apple silicon публикует бинарники, которые
сервис сможет запустить; `--platform` её заменяет. Сервис старше v1.3.0
платформу не сообщает: `publish` предупреждает и собирает под машину, на которой
запущен. Архивы упаковываются воспроизводимо, поэтому неизменённая пересборка
побайтно совпадает и повторно не загружается.

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--archives` | — | Опубликовать это дерево `plugin.tgz` вместо сборки. |
| `--plugins-dir` | — | Распаковывать в этот каталог вместо загрузки. Без другого источника — зарегистрировать то, что в нём уже есть. |
| `--workdir` | `$TMPDIR/easyp-publish` | Где собираются версии; каждая удаляется после публикации. |
| `--keep` | false | Оставлять собранные версии в `--workdir` после публикации. |
| `--filter` | — | Glob-фильтр. |
| `--force` | false | Публиковать версии, которые у сервиса уже есть: пересобрать и заменить их конфиг. |
| `--build-parallel` | `4` | Одновременных Docker-сборок. |
| `--parallel`, `-p` | `8` | Версий, одновременно загружаемых и регистрируемых. Держите не выше `rate_limit.max_concurrent_per_ip` сервера. |
| `--dry-run` | false | Показать, что будет опубликовано, ничего не собирая и никуда не обращаясь. |
| `--non-interactive` | false | Без интерактивного интерфейса. |
| `--runtime-image`, `--no-smoke` | как у `build` | Проверка. |
| `--platform` | как у сервиса | Платформа сборки и пробного запуска вместо той, что сообщает сервис. |
| `--cfg` | — | **Полный** конфиг сервиса; `registry.s3` заполняет то, что не передано флагами. Фрагмент только с `registry.s3` отвергается. |
| `--bucket` | — | Бакет (переопределяет конфиг). |
| `--endpoint` | — | URL эндпоинта, например `http://localhost:9000`. |
| `--region` | — | Регион. |
| `--prefix` | — | Префикс ключей. |
| `--force-path-style` | false | Path-style адресация (MinIO, RustFS). |
| `--addr` | `localhost:23410` | gRPC-адрес сервиса; `host:port` разрешает системный резолвер, `dns:///…` — резолвер grpc-go. |
| `--token` | `$EASYP_TOKEN` | Токен записи. |
| `--tls-ca` | системное хранилище | CA, подписавший сертификат сервера. |
| `--tls-cert`, `--tls-key` | — | Клиентский сертификат и ключ для взаимного TLS. |
| `--insecure` | false | Без шифрования. Только для локальной разработки. |

Учётные данные хранилища берутся из стандартной цепочки AWS
(`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, профили). Объектные хранилища
обычно ограничивают одно соединение намного ниже ширины канала, поэтому
пропускную способность дают потоки `--parallel`; `publish` отступает при
упоре в лимиты частоты и конкурентности сервера и перестаёт начинать новые
версии, когда достигнут лимит плагинов лицензии. Если хоть одна версия не
опубликована, код выхода ненулевой.

```bash
# Собрать на одной машине…
easyp-svc plugins build registry --archive --output plugin-archives

# …и опубликовать откуда угодно, где есть доступ к хранилищу и токен записи.
export AWS_ACCESS_KEY_ID=… AWS_SECRET_ACCESS_KEY=… EASYP_TOKEN=…
easyp-svc plugins publish --archives plugin-archives \
  --endpoint https://storage.example.com --bucket easyp-plugins --force-path-style \
  --addr plugins.example.com:443 --parallel 24
```

<Callout>
Удалено в v1.2.0: `plugins push` и `plugins register` заменены на
`plugins publish`, `plugins pack` — на `plugins build --archive`, флаги
`--packed` и `--plugins-prefix` убраны — команду выводит сервис.
</Callout>

## auth new-token

`easyp-svc auth new-token [--name string]`

Генерирует случайный токен записи, один раз печатает его и печатает запись
`auth.write_tokens` (имя и sha256), которая его разрешает. `--name` по умолчанию
`unnamed`; это метка токена в логах и аудите.

## api descriptor

`easyp-svc api descriptor [--output string]`

Пишет `FileDescriptorSet` API для `grpcurl -protoset`; сервер не отдаёт
reflection. `--output`/`-o` по умолчанию `-` (stdout).

## config validate

`easyp-svc config validate [--cfg string]`

Разрешает конфигурацию ровно так же, как `service start`, и завершается с
ненулевым кодом, если сервис её отверг бы. Без `--cfg` проверяет только
окружение.

## config print

`easyp-svc config print [options]`

| Флаг | Смысл |
|---|---|
| `--cfg` | Файл конфигурации; без него — только окружение. |
| `--origin` | Подписать у каждой настройки, из какого слоя она пришла. |
| `--changed` | Печатать только отличия от значений по умолчанию — то, что нужно указать в файле. |
| `--show-secrets` | Печатать учётные данные вместо заглушки. |

## health

`easyp-svc health [--addr host:port] [--cfg string]`

Завершается с кодом 0, если `/live` на health-listener'е отвечает, иначе 1. Это
`HEALTHCHECK` образа. Проверяется liveness, а не readiness: readiness зависит от
PostgreSQL, а перезапуск контейнера при каждом сбое БД превращает простой в цикл
падений. Без `--addr` порт берётся из `--cfg`/`EASYP_CONFIG`, затем из
окружения, затем по умолчанию 23412.

## Сокращения в Taskfile

`Taskfile.yml` репозитория сервиса оборачивает эти команды для разработки:
`task build-plugins`, `FILTER=… task build-plugins-filter`, `task publish-plugins`
(собрать, загрузить и зарегистрировать на стенде разработки; `FILTER=…` — для
части каталога), `task publish-archives` (дерево `build --archive` в любой сервис
и хранилище), `task up`, `task up-minimal`, `task run`, `task run-local`. Все,
кроме `publish-archives`, рассчитаны на адреса и учётные данные стенда
разработки.
