EasyP API Service запускает зарегистрированные генераторы кода Protocol Buffers на сервере, который выбирает оператор. Клиент отправляет <code>CodeGeneratorRequest</code> с дескрипторами файлов и параметрами плагина. Сервис возвращает <code>CodeGeneratorResponse</code>; сгенерированные файлы записывает клиент.

Раздел описывает сервис **v1.0.2**, ревизию <code>4b01518b42c6f448d21216e3c0e8c35ef66d5c2d</code>, проверенную **2026-09-23**. Сервис, его wire API, Go SDK и CLI <code>easyp</code> — разные компоненты. Возможность сервера не обязательно доступна через каждый клиент.

## Что централизуется

Развёртывание централизует регистрацию плагинов, доставку исполняемых файлов, вычислительные ресурсы для генерации и эксплуатационный мониторинг. Разработчикам не требуется устанавливать одинаковые генераторы на каждой рабочей станции. Явно заданная версия избавляет от текстовой сортировки при поиске <code>latest</code>, но сама по себе не делает изменяемый бинарник или недетерминированный плагин воспроизводимым.

~~~text
.proto-файлы -> компиляция на клиенте -> CodeGeneratorRequest
                                       |
                                       | gRPC, при необходимости TLS/mTLS
                                       v
                                EasyP API Service
                                 |           |
                                 |           +-> PostgreSQL: регистрации, аудит
                                 +-> локальный каталог плагинов
                                      ^           |
                                      |           v
                                 S3, опционально  дочерний процесс
                                                  |
файлы клиента <- CodeGeneratorResponse <----------+
~~~
Docker используется для упаковки сервиса и может собирать артефакты плагинов. **Генерация запускает локальный дочерний процесс, а не новый Docker-контейнер. Отдельной песочницы для плагина нет.** До открытия регистрации плагинов или доступа к сервису прочитайте [Модель безопасности](./security).

## Границы продукта

В gRPC API пять операций: <code>GenerateCode</code>, <code>Plugins</code>, <code>CreatePlugin</code>, <code>UpdatePlugin</code> и <code>DeletePlugin</code>. Необязательный MCP endpoint предназначен для поиска плагинов. PostgreSQL хранит метаданные плагинов и, при наличии лицензии, записи аудита; он нужен даже при полностью локальных бинарниках. Объектное хранилище необязательно.

Сервис не предоставляет реестр схем и модулей, сервер пакетов Go/npm/Maven с готовыми SDK, портал документации загруженных схем или проверки совместимости при публикации в реестр. Его Go SDK — клиент сервиса генерации, а не система распространения сгенерированных SDK. Управление зависимостями модулей рассматривается в отдельном [сравнении пакетных менеджеров](../cli/package-manager/easyp-vs-buf).

## Когда сервис подходит

Выбирайте сервис, когда требуется самостоятельно размещать endpoint генерации, определять набор доверенных исполняемых файлов и обслуживать PostgreSQL, артефакты, учётные данные, вычислительные ресурсы и обновления. Работа без внешней сети возможна только после подготовки всех необходимых бинарников, библиотек, зависимостей схем, образов и конфигурации, а также исключения плагинов, которым самим нужна сеть.

Если команде не нужен общий сервер исполнения, локальная генерация обычно проще. Управляемая платформа схем может лучше подходить, если важнее доставка готовых пакетов, управление схемами и правами организаций или снижение эксплуатационной нагрузки. Различия разобраны в [сравнении EasyP и Buf BSR](./vs-buf-bsr).

## Ресурсы и доступ

Community допускает до четырёх lookup workers, десяти зарегистрированных версий плагинов и шестнадцати одновременных генераций. Enterprise снимает эти лицензионные потолки и включает запись аудита; эксплуатационные ограничения конфигурации сохраняются. Два ограничения, связанные с исполнением, применяются при старте процесса. Последующая смена состояния лицензии не меняет размер уже созданного пула.

Для записи всегда нужен настроенный bearer-токен. Чтение и генерация по умолчанию анонимны; это меняется через <code>auth.require&#95;authentication</code>. Текущий remote executor в <code>easyp</code> не отправляет bearer-токены и не поддерживает клиентские сертификаты. При таких требованиях используйте [Go SDK или подходящий клиент](./client-usage), а не несуществующие ключи конфигурации CLI.
