The binary exposes Prometheus text on <code>http://127.0.0.1:23411/metrics</code> by default. Helm uses the metrics port 8081. Keep this endpoint inside an authorized monitoring network: plugin coordinates, database-derived counts, and error activity are operational information.

## Prometheus reference

Labels below are instrumentation labels. Prometheus/Alloy can add <code>job</code>, <code>instance</code>, <code>tier</code>, or deployment labels; those are not additional application labels on every metric. Histogram families produce <code>&#95;bucket</code>, <code>&#95;sum</code>, and <code>&#95;count</code> series, with <code>le</code> added on buckets. <code>plugin</code> is the resolved group/name:version coordinate.

The server also registers the pinned Prometheus client's standard Go and process collectors (<code>go&#95;&#42;</code>, <code>process&#95;&#42;</code>). Their exact runtime/OS-dependent family set is not an EasyP configuration contract. Database business collectors perform queries at scrape time; on a query error the affected series can be omitted rather than emitted as zero. Do not interpret a missing series as an empty catalog or an absence of audit events.

## Traces, logs, and profiles

<code>telemetry.otlp&#95;endpoint</code> enables **OTLP/gRPC traces and metrics**. A bare <code>host:port</code> selects an insecure transport in this implementation; use an explicit <code>https://</code> URL when TLS is required and configure the collector accordingly. gRPC server TLS settings do not configure the exporter. Trace resources include <code>service.name=easyp</code>, the build's service version, and an optional configured tier. That tier is not automatically synchronized with license claims. OTLP metrics use a 15-second periodic reader.

Trace wrappers cover Core operations, registry access, plugin generation, and <code>process.exec</code>. W3C trace-context propagation is installed, and structured logs include trace/span IDs when the context has them. The service does not directly export logs using an OTLP log exporter; the supplied observability stack collects container logs separately. The OpenTelemetry histogram <code>plugin.execution.duration</code> has unit seconds and a <code>plugin.name</code> label; do not confuse it with the Prometheus execution-attempt histogram.

<code>telemetry.pyroscope&#95;endpoint</code> enables CPU, allocation, in-use memory, and goroutine profiles of the **Go service process**. A plugin tag attributes service-side work to a plugin; it does not make the child executable's own CPU profile available. Exporter initialization failures are logged and can leave the service running without that telemetry. Neither readiness nor liveness proves exporter delivery.

## Alerting and dashboards

The Helm chart can render a <code>ServiceMonitor</code> and a <code>PrometheusRule</code>; both require the corresponding monitoring CRDs and are disabled by default. The chart defines eleven application alerts. The Compose observability tree contains the same application alerts and six additional host/discovery/certificate alerts. Every alert has a matching [runbook](./runbooks). Host metrics are produced by the supplied Alloy Unix exporter; the certificate metric belongs to Traefik, not to <code>easyp-svc</code>.

The supplied generation-error ratio divides execution-attempt errors by accepted lookup jobs. Retries and failures before execution mean it is **not an exact proportion of failed end-user RPCs**. For an RPC failure SLI, use the handled-RPC counter and explicitly choose which gRPC codes count as failures. Keep transport failures and plugin-protocol <code>CodeGeneratorResponse.error</code> results in your client-side synthetic check as well.

<code>EasypServiceMissing</code> assumes that both Community and Enterprise targets exist with the shipped Alloy job/tier labels. Adapt or disable the absent-tier branch for a one-tier deployment; otherwise it alerts on an intentionally absent service. <code>EasypTargetDown</code> uses <code>up == 0</code> across discovered targets, not only generation endpoints.

The cache alert watches a soft S3-cache budget, not filesystem free space. The audit DEFAULT-partition gauge normally updates only during the six-hour maintenance pass, and a maintenance error can leave it stale. Use a direct, read-only database query during incident response. See [Runbooks](./runbooks), [Architecture](./architecture), and [Backup](./backup).
