title: "Operator CLI"
description: "easyp-svc: every command and flag of the binary that is both the server and the operator's tool."
---

`easyp-svc` is one binary with six command groups. The server is one of them
(`service start`); the rest are what an operator runs from a laptop or CI.

```
easyp-svc service start
easyp-svc plugins build | publish
easyp-svc auth new-token
easyp-svc api descriptor
easyp-svc config validate | print
easyp-svc health
```

Global flags: `--help`/`-h`, `--version`/`-v`.

Every command that takes `--cfg` also reads the path from `EASYP_CONFIG`.

## service start

Starts the gRPC, metrics, health and (if enabled) MCP listeners.

| Flag | Meaning |
|---|---|
| `--cfg string` | Path to the YAML config. Omit to configure from the environment alone. |
| `--log-level string` (also `--log_level`) | `debug`, `info`, `warn`, `error`. Overrides `log.level`. |

## plugins build

`easyp-svc plugins build [options] <registry-path>`

Builds plugin binaries from registry Dockerfiles without uploading anything.
Needs Docker. Each version listed in a `plugin.yaml` is built with
`--build-arg VERSION=…` and the image filesystem is extracted to
`<output>/{group}/{name}/{version}/`. Every version is then verified the way the
service will run it — packed and unpacked with the service's unpacker, and
smoke-run in the runtime image; a version that fails is emptied down to its
`build.log`.

With `--archive`, only each version's verified
`<output>/{group}/{name}/{version}/plugin.tgz` is kept — the tree
`plugins publish --archives` takes, for building on one machine and publishing
from another.

| Flag | Default | Meaning |
|---|---|---|
| `--output`, `-o` | `plugins` | Output directory. |
| `--archive` | false | Keep only each version's verified `plugin.tgz` instead of the unpacked bundle. |
| `--filter` | — | Glob on `group/name[:version]`, e.g. `protocolbuffers/*`, `grpc/go:v1.5.1`. |
| `--parallel`, `-p` | `4` | Concurrent Docker builds. |
| `--force` | false | Rebuild even if the version is already built. A version built by an older `easyp-svc` was not verified the way this one verifies, and is only rebuilt with this. |
| `--dry-run` | false | List what would be built. |
| `--non-interactive` | false | No interactive UI or progress bars. |
| `--keep-going` | **true** | Continue after a failed build. |
| `--runtime-image` | `debian:trixie-slim` | Image each built plugin is smoke-tested in; must match the base of the service image. |
| `--no-smoke` | false | Skip the smoke run. The archive is still checked to unpack the way the service unpacks it. |

## plugins publish

`easyp-svc plugins publish [options] [registry-path]`

Takes each version through in one pass: build it from the registry (or take its
`plugin.tgz` from `--archives`), verify it, upload the archive to
`{prefix}{group}/{name}/{version}/plugin.tgz` with its sha256 in the object
metadata, register it — `CreatePlugin`, or `UpdatePlugin` for a version the
service already has — and delete the local copy before the next version needs
the disk. Needs a v1.2.0 or newer server; against an older one it stops at the
first registration and says so.

Source — exactly one of:

- a **registry path**, built version by version;
- `--archives <dir>`, a `{group}/{name}/{version}/plugin.tgz` tree written by
  `plugins build --archive`;
- neither, with `--plugins-dir`: what is already unpacked in that directory is
  registered.

Destination: object storage, configured by the S3 flags and `--cfg`; or, with
`--plugins-dir <dir>`, that directory — the `plugins_dir` of a service on the
same host running without object storage — into which each archive is unpacked
instead of uploaded.

It is idempotent. Without `--force`, a version that is registered and in
storage is skipped, one in storage but not registered is only registered, and an
upload is skipped whenever storage already holds the same archive; an
interrupted run resumes by re-running it. `--force` rebuilds and republishes
everything it matches (see [Plugins](/docs/api-service/plugins#republishing)).
Before anything is built, `publish` checks that storage answers, that the
service accepts the token, and which versions the service already has.

| Flag | Default | Meaning |
|---|---|---|
| `--archives` | — | Publish this `plugin.tgz` tree instead of building. |
| `--plugins-dir` | — | Unpack into this directory instead of uploading. With no other source, register what is already in it. |
| `--workdir` | `$TMPDIR/easyp-publish` | Where versions are built; each is removed once published. |
| `--keep` | false | Leave built versions in `--workdir` after publishing them. |
| `--filter` | — | Glob filter. |
| `--force` | false | Publish versions the service already has, rebuilding them and replacing their config. |
| `--build-parallel` | `4` | Concurrent Docker builds. |
| `--parallel`, `-p` | `8` | Versions uploading and registering at once. Keep it at or below the server's `rate_limit.max_concurrent_per_ip`. |
| `--dry-run` | false | List what would be published without building or contacting anything. |
| `--non-interactive` | false | No interactive UI. |
| `--runtime-image`, `--no-smoke` | as for `build` | Verification. |
| `--cfg` | — | A **full** service config; `registry.s3` fills settings not given as flags. A fragment containing only `registry.s3` is refused. |
| `--bucket` | — | Bucket (overrides the config). |
| `--endpoint` | — | Endpoint URL, e.g. `http://localhost:9000`. |
| `--region` | — | Region. |
| `--prefix` | — | Key prefix. |
| `--force-path-style` | false | Path-style addressing (MinIO, RustFS). |
| `--addr` | `localhost:23410` | Service gRPC address; `host:port` is resolved by the system resolver, `dns:///…` by grpc-go's. |
| `--token` | `$EASYP_TOKEN` | Write token. |
| `--tls-ca` | system store | CA that signed the server certificate. |
| `--tls-cert`, `--tls-key` | — | Client certificate and key, for mutual TLS. |
| `--insecure` | false | Plaintext. Local development only. |

Storage credentials come from the standard AWS chain (`AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`, profiles). Object storage commonly caps a single
connection well below the link, so throughput comes from `--parallel` streams;
`publish` backs off on the server's rate and concurrency limits and stops
starting new versions at the licence tier's plugin cap. It exits non-zero if
any version failed.

```bash
# Build on one machine…
easyp-svc plugins build registry --archive --output plugin-archives

# …publish from anywhere with the storage credentials and a write token.
export AWS_ACCESS_KEY_ID=… AWS_SECRET_ACCESS_KEY=… EASYP_TOKEN=…
easyp-svc plugins publish --archives plugin-archives \
  --endpoint https://storage.example.com --bucket easyp-plugins --force-path-style \
  --addr plugins.example.com:443 --parallel 24
```

<Callout>
Removed in v1.2.0: `plugins push` and `plugins register` became
`plugins publish`, `plugins pack` became `plugins build --archive`, and
`--packed` and `--plugins-prefix` are gone — the service derives the command.
</Callout>

## auth new-token

`easyp-svc auth new-token [--name string]`

Generates a random write token, prints it once, and prints the
`auth.write_tokens` entry (name and sha256) that authorises it. `--name`
defaults to `unnamed`; it labels the token in logs and the audit trail.

## api descriptor

`easyp-svc api descriptor [--output string]`

Writes a `FileDescriptorSet` of the API for `grpcurl -protoset`; the server does
not serve reflection. `--output`/`-o` defaults to `-` (stdout).

## config validate

`easyp-svc config validate [--cfg string]`

Resolves the configuration exactly as `service start` would and exits non-zero
if the service would refuse it. Without `--cfg`, checks the environment alone.

## config print

`easyp-svc config print [options]`

| Flag | Meaning |
|---|---|
| `--cfg` | Config file; omit to resolve from the environment alone. |
| `--origin` | Annotate each setting with the layer it came from. |
| `--changed` | Print only settings that differ from the defaults — what a config file needs to state. |
| `--show-secrets` | Print credentials instead of a placeholder. |

## health

`easyp-svc health [--addr host:port] [--cfg string]`

Exits 0 if `/live` on the health listener answers, 1 otherwise. It is the
image's `HEALTHCHECK`. It probes liveness, not readiness: readiness depends on
PostgreSQL, and restarting a container on every database blip turns an outage
into a crash loop. Without `--addr` the port comes from `--cfg`/`EASYP_CONFIG`,
then the environment, then the default 23412.

## Taskfile shortcuts

The service repository's `Taskfile.yml` wraps these for development:
`task build-plugins`, `FILTER=… task build-plugins-filter`, `task publish-plugins`
(build, upload and register into the development stack; `FILTER=…` for a slice),
`task publish-archives` (a `build --archive` tree to any service and storage),
`task up`, `task up-minimal`, `task run`, `task run-local`. Except
`publish-archives`, they assume the development stack's addresses and
credentials.
