These headings are an external interface: the Helm chart and Compose alert rules link to their lowercase anchors. Do not translate or rename the alert-name headings. Eleven application alerts come from the chart; the final six come from the Compose host/discovery/edge rules. Their thresholds are not service SLAs.

Before changing a deployment, capture the failing time window, exact build, resolved non-secret configuration, caller-visible errors, and affected plugin version. Change one cause at a time and validate a real generation as well as health. Avoid deleting source artifacts or audit data to suppress an alert.

## EasypLicenceExpiringSoon

The configured expiry is nonzero and is within the chart warning window for one hour. Check the actual expiry, clock synchronization, and the token’s grace interval. Obtain a replacement through the authorized licensing process, update the configured token and trusted public keys as needed, and restart. A changed license file is not hot-reloaded. Verify expiry/valid/grace metrics after the rollout; do not merely check that the file changed.

## EasypLicenceInGrace

The license is in grace for fifteen minutes. Treat the end of grace as the deadline: Enterprise claims currently remain valid, but audit and new-registration gating will become Community after expiry plus grace and refresh. Renew and restart, then confirm grace is zero. Existing worker/generation capacities are not resized by refresh, so an apparent unchanged throughput is not proof that the license is still Enterprise.

## EasypGenerationsRejected

The generation-wait queue has refused work continuously over the alert window. Compare generations_active, generations_waiting, execution latency, per-IP concurrency rejections, and lookup rejections; these are different admission points. Reduce client parallelism and apply bounded backoff. Increase generation capacity only after checking Community ceilings and CPU/memory/output budgets. Do not mount the same cache directory on multiple replicas as an unreviewed scaling shortcut. Verify refusals and caller-visible errors fall, not just queue length.

## EasypGenerationQueueSaturated

At least one generation has been waiting for ten minutes; the rule does not measure a full queue. Identify slow or stuck plugin versions and compare their execution durations with request deadlines. A larger queue absorbs a burst but does not increase service rate and can turn overload into deadline failures. Tune clients or execution capacity, then verify queueing and end-to-end latency recover.

## EasypPluginCacheAtLimit

S3-cache bytes remain above the configured fraction of the soft limit for thirty minutes. Inspect actual filesystem space, eviction activity, artifact sizes, and recently used entries protected from eviction. Raise storage and the soft budget together with extraction headroom, or remove unused versions through a reviewed maintenance procedure. A local-only plugin directory is authoritative data, not disposable S3 cache. Check both filesystem headroom and cold-generation success afterward.

## EasypAuditEventsLost

Read the reason label: enqueue_timeout means no queue room within the enqueue budget; save_failed means a batch exhausted its save attempts/budget; shutdown_timeout means drain did not finish. Inspect database latency, write errors, queue depth, and shutdown timing before changing buffer sizes. Lost events are not replayed by the service. Record the affected interval as an audit gap and correlate independent access/CI logs without claiming they reconstruct every event. Verify new loss stops and writes resume.

## EasypAuditMaintenanceStale

No successful partition-maintenance timestamp has advanced for more than a day, sustained for one hour. Check PostgreSQL availability, DDL permissions, lock contention, maintenance errors, and whether DEFAULT rows block creation of a missing month. Missing monthly partitions can route writes into DEFAULT; writes do not inevitably fail immediately. Fix the cause and allow or deliberately restart maintenance during a controlled window. Verify future partitions and the last-success timestamp, not only a healthy process.

## EasypAuditDefaultPartitionUsed

Maintenance observed at least one row in the DEFAULT partition and the cached gauge remains one for fifteen minutes. Confirm directly with a read-only query; the gauge is not refreshed on every scrape. Preserve a database backup, identify affected UTC months, pause conflicting writes/maintenance, and have a database operator move rows into correctly constrained monthly partitions in a reviewed transaction. Do not discard DEFAULT rows to silence the alert. Verify rows are retained and DEFAULT is empty, then confirm the next successful maintenance refresh clears the gauge.

## EasypGenerationErrorRate

The chart’s execution-error/accepted-lookup ratio exceeds its threshold for ten minutes. Break down execution errors by plugin and transient/permanent classification, and examine actual gRPC statuses and plugin response errors in the client. This ratio is not an exact failed-RPC percentage. Check executable compatibility, wrapper paths, stderr, output bounds, timeouts, and cold-cache checksum failures. Prefer a known-good immutable plugin version over overwriting an existing one. Verify the same input succeeds on cold and warm paths.

## EasypPanics

The recovered-panic counter increased. Preserve the stack trace, build revision, operation, and relevant request metadata without publishing schema contents or credentials. The counter has no goroutine/name labels: find the goroutine field in background panic logs where present. A recovered background panic may end that task even while liveness is healthy. Confirm the affected worker or maintenance task still progresses; restart only after preserving evidence and assessing impact, and track a code defect.

## EasypAuthFailures

The configured failed-authentication rate has been exceeded for ten minutes. Separate no_credentials from unknown_token, and correlate the resolved client IP with gateway logs after checking trusted-proxy configuration. A rejected token cannot reliably identify its intended user by token name. Check credential rotation and whether required authentication was enabled for a client that cannot send tokens. Do not disable production authentication as a workaround. Verify the intended caller succeeds and invalid credentials remain rejected.

## EasypHostDiskLow

The observed filesystem has less than 15% available space for thirty minutes. Identify the mount, inode pressure, database growth, artifact cache, container logs, and build cache separately. Preserve PostgreSQL volumes and authoritative local plugins. Remove only reviewed disposable data or expand storage; a blanket Docker volume prune can destroy the registry. Verify free space and representative writes/generation recover.

## EasypHostDiskFillingUp

A six-hour linear trend predicts no available space within four days while current free space is below 40%, sustained for one hour. Treat this as a forecast, not a guaranteed deadline. Find the growing directory and distinguish a burst from persistent growth before resizing retention or storage. Re-evaluate the trend after the change and retain the fixed free-space alert as a separate safeguard.

## EasypHostMemoryLow

Linux MemAvailable is below 10% for fifteen minutes. Inspect host and pod/process memory, OOM events, database buffers, and plugin children. Limiting stdout does not bound child memory. Reduce generation parallelism or isolate resource-heavy plugins and size the host/pod with output-buffer headroom. Avoid unbounded concurrency changes while diagnosing overload. Verify available memory and restart/OOM activity stabilize.

## EasypTargetDown

A discovered target has up=0 for five minutes. Check which job and instance failed: exporter failure, a blocked scrape, and a failed service are different incidents. Compare scrape diagnostics with HTTP /live, HTTP readiness /, and a client generation. A healthy /live with failed readiness points toward startup/database work rather than proof of a healthy generation path. Restore the affected listener, network route, credentials, or process and verify scrapes resume.

## EasypServiceMissing

An expected Community or Enterprise target is absent from the shipped Docker discovery labels for ten minutes. Confirm that this deployment is actually meant to run both tiers; customize the rule for one-tier installations. Inspect container state and discovery/scrape labels. A missing series is not up=0, so restarting the metrics backend alone is not a diagnosis. Verify the intended target is rediscovered with the expected labels.

## EasypCertificateExpiringSoon

Traefik reports an edge certificate expiring within 21 days for one hour. Identify the certificate and hostname, then inspect the configured renewal mechanism, issuer limits, challenge routing, DNS, and certificate storage. HTTP-01 troubleshooting applies only when that challenge is actually configured. Verify the renewed certificate served to clients, not just a newly written file. This rule does not monitor every internal gRPC or client certificate; monitor those lifetimes separately.
