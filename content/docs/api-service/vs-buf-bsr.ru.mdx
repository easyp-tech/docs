Эта страница сравнивает **удалённую генерацию кода**: запуск protobuf-плагинов
на сервере вместо каждой машины разработчика. Buf Schema Registry (BSR) — более
широкий продукт: реестр схем с remote plugins, generated SDKs и многим другим.
Про управление зависимостями (модули против Git) — см.
[EasyP и Buf](/ru/docs/cli/package-manager/easyp-vs-buf).

## Если коротко

BSR — облачный продукт: remote plugins работают сразу, как только вы запускаете
`buf generate`, плагины выполняются в песочнице Buf, а сгенерированный код можно
получать обычными пакетами из npm, Go, Maven, PyPI и других. Он лучше, если вам
не нужно выполнять генерацию внутри своей сети без Enterprise-контракта. EasyP
API Service — ПО, которое вы эксплуатируете сами: бесплатная редакция Community,
доступный исходный код (source-available), ваши `.proto` не покидают вашу
инфраструктуру — а взамен вы держите PostgreSQL, хранилище и мониторинг и
принимаете, что плагины не изолированы.

## Где сильнее BSR

- **Нечего эксплуатировать.** Remote plugins на `buf.build` не требуют ни
  сервера, ни базы, ни хранилища, ни сертификатов, ни алертов, ни обновлений. С
  EasyP всё это ваша работа, и качество сервиса равно качеству вашей эксплуатации.
- **Плагины выполняются в песочнице.** Buf пишет, что remote plugins работают под
  ограничениями файловой системы и сети песочницы [²](#sources). EasyP запускает
  плагины обычными процессами; изоляция хоста остаётся на вас (см.
  [Безопасность](/ru/docs/api-service/security)). Для реестра, общего для команд,
  которые не вполне доверяют друг другу, разница существенная.
- **Generated SDKs.** Потребители могут сделать `go get`, `npm install` или
  `pip install` сгенерированного кода для схемы, не запуская генераторов
  [⁵](#sources). У EasyP аналога нет.
- **Один продукт для схем и генерации.** Модули, зависимости, документация,
  Studio (браузерный клиент для живых API), Reflection API и проверки политик при
  push (Enterprise) живут рядом с remote plugins [¹¹](#sources). Сервис генерации
  EasyP ничего не знает о схемах.
- **Идентификация и доступ.** Организации с ролями Member/Writer/Admin/Owner,
  роли на уровне ресурса, бот-пользователи, SSO и SCIM на приватных инстансах
  [⁷](#sources). У EasyP статические токены, и любой токен записи может изменить
  любой плагин.
- **Аутентификация клиента работает от начала до конца.** `buf registry login`
  или `BUF_TOKEN` аутентифицируют `buf generate` [¹²](#sources). easyp CLI не
  умеет отправлять токен или клиентский сертификат, так что приватный сервис
  EasyP приходится закрывать на уровне сети.
- **Сопровождение каталога.** bufbuild/plugins обновляется постоянно (на момент
  написания — коммиты от 22 сентября 2026 года) [³](#sources), и каждая
  опубликованная версия сразу готова к использованию. Каталог EasyP — набор
  рецептов: каждое развёртывание само собирает и регистрирует нужные версии.
- **Доступность и масштаб.** SaaS с опубликованными SLA доступности на платных
  тарифах [⁹](#sources). Сервис EasyP работает одной репликой на кеш и
  масштабируется только вертикально.
- **Семантика «latest».** Незафиксированный плагин BSR разрешается в последнюю
  версию [²](#sources). `latest` в EasyP — версия, последняя при сравнении строк
  (`v1.36.9` раньше `v1.36.10`), так что фиксируйте версии.

## Где сильнее EasyP API Service

- **Self-hosted без контракта с отделом продаж.** Редакция Community бесплатна,
  не требует лицензионного ключа и не тарифицируется по типам. Self-hosted BSR —
  это Enterprise [⁹](#sources).
- **Исходный код доступен.** Сервис можно читать, проверять и патчить; клиентский
  API и Go SDK — Apache-2.0.
- **Данные по умолчанию остаются в вашей сети.** Запросы генерации уходят только
  в ваш сервис. С публичным BSR они уходят в сервис Buf; внутри вашей сети BSR их
  держит только в on-prem-развёртывании [¹⁰](#sources).
- **Любой плагин, включая внутренние, в любой редакции.** Регистрация своего
  плагина не требует платного тарифа. Работают и плагины, которые BSR не
  поддерживает, — читающие файлы или ходящие в сеть [⁴](#sources); это следствие
  отсутствия песочницы, а не функция, на которую стоит опираться.
- **Нет лимитов поставщика.** Публичный BSR ограничивает генерацию без
  аутентификации 10 запросами в час на IP, а с аутентификацией — 960 в час на
  пользователя, и не больше 20 плагинов в запросе [⁶](#sources). У self-hosted
  сервиса только те лимиты, что настроили вы, — и только та мощность, что вы
  выделили.
- **Архитектура хоста.** Образ сервиса публикуется для amd64 и arm64. Исполнитель
  своих плагинов у Buf — linux/amd64 [⁴](#sources).
- **Наблюдаемость для оператора в комплекте.** Метрики Prometheus, набор
  алертов и ранбук на каждый алерт. У on-prem BSR есть собственная документация
  по наблюдаемости [¹⁰](#sources); в SaaS это забота Buf, а не ваша.

MCP-эндпоинт есть у обоих, но с разным охватом: у EasyP — список плагинов
(только чтение); у Buf — Registry API BSR, включая запись [¹¹](#sources).

## Совместимость

- `buf generate` с `remote:` обращается к инстансу BSR. Сервис EasyP не реализует
  API BSR, поэтому `buf` не может использовать его как remote.
- `easyp generate` с `remote:` говорит на API EasyP `easyp.generator.v1`.
  `remote: buf.build/...` в `easyp.yaml` не попадёт в remote plugins Buf.
- Оба запускают стандартные `protoc`-плагины через `CodeGeneratorRequest`, так
  что одна и та же версия плагина даёт одинаковый результат; имена плагинов в
  основном совпадают (`protocolbuffers/go`, `grpc/go`, `connectrpc/go`, …).

Переход между ними — изменение конфигурации клиента, описанное в
[Миграции с BSR](/ru/docs/api-service/migrating-from-bsr).

## Производительность

Ни один из проектов не публиковал бенчмарк, сравнивающий их, и здесь он тоже не
приводится. Структурно можно сказать одно: сервис EasyP добавляет один сетевой
круг на плагин и, при промахе кеша, одно скачивание архива; задержка до BSR
зависит от вашего расстояния до сервиса Buf. Измеряйте на своих схемах.

## Стоимость владения

BSR тарифицируется за тип protobuf в месяц [⁹](#sources); план Community
публичного BSR бесплатен, а remote plugins и generated SDKs доступны на любом
тарифе [¹³](#sources). Редакция Community EasyP бесплатна, Enterprise — это
лицензия, но настоящая цена — эксплуатация: база PostgreSQL, S3-совместимое
хранилище, под или VM под ваши плагины (чарт по умолчанию — 4 CPU и 4 ГиБ),
мониторинг, обновления и изоляция, описанная в
[Безопасности](/ru/docs/api-service/security). Для небольшой команды на
бесплатном плане публичного BSR эти расходы почти наверняка выше того, что
берёт Buf.

## Когда выбирать BSR

- Нужна удалённая генерация, и не хочется ничего эксплуатировать.
- Нужны также реестр схем, generated SDKs через пакетные менеджеры, Studio или
  проверки политик при push.
- Нужны SSO, SCIM, организации и роли.
- Пользователи плагинов не все доверяют друг другу, а изолировать хост генерации
  сами вы не можете.
- Бесплатный или Teams-план покрывает размер ваших схем, и публичные rate
  limits приемлемы.

## Когда выбирать EasyP API Service

- Генерация должна выполняться внутри вашей сети, а BSR Enterprise on-prem вы не
  хотите (или не можете) покупать.
- Вы уже эксплуатируете PostgreSQL, объектное хранилище и Prometheus.
- Нужны приватные или нестандартные плагины без платного тарифа или на arm64.
- Вы используете easyp CLI и зависимости через Git, и реестр схем вам не нужен.
- Те, кто может регистрировать плагины, доверяют друг другу, и вы можете
  изолировать хост сервиса.
