---
title: "MCP endpoint"
---

Необязательный endpoint Model Context Protocol (MCP) позволяет агенту находить зарегистрированные плагины без запуска генерации. Включение задаётся явно:

~~~yaml
mcp:
  enabled: true
server:
  port:
    mcp: "23413"
~~~
Эквивалентная переменная — <code>MCP&#95;ENABLED=true</code>. Endpoint streamable HTTP находится на <code>/mcp</code>; при дефолтах бинарника это <code>http://127.0.0.1:23413/mcp</code>. Helm использует порт 8083. Имя MCP implementation — <code>easyp-service-mcp</code>; строка версии implementation в сервисе v1.0.2 жёстко задана как <code>v1.0.0</code> и не определяет фактический релиз сервера.

## Инструменты

Зарегистрирован ровно один generated tool: **<code>plugins&#95;list</code>**. Он принимает поля <code>PluginsRequest</code>: group, name, version, tags, page size и page token. Ответ содержит метаданные плагинов и continuation token; используется та же реализация списка, что и в gRPC. Фильтры group/name/version требуют точного совпадения; должны присутствовать все переданные tags. Следующую страницу запрашивайте с прежними фильтрами.

В этой версии нет инструментов генерации, записи и получения схемы <code>easyp.yaml</code>. Endpoint не предоставляет доступ к shell или файловой системе. Каталог раскрывает идентификаторы, tags и время регистрации плагинов, но не конфигурацию команд. Отдельно оцените допустимость раскрытия и этих метаданных.

## Аутентификация и публикация

По умолчанию MCP выключен. После включения это отдельный HTTP listener, не часть gRPC-транспорта. При <code>auth.require&#95;authentication: true</code> HTTP wrapper требует bearer-токен. OAuth flow для этого endpoint в сервисе не реализован. Настройки gRPC TLS/mTLS не включают TLS для MCP, а gRPC-интерсепторы rate limiting и конкурентности не защищают HTTP-запросы.

Размещайте MCP за подходящим TLS/authentication gateway либо оставляйте в доверенной сети с явными ограничениями доступа. Чтение каталога всё равно проходит через Core, поэтому Enterprise-аудит может его записывать; отсутствие gRPC-интерсепторов не означает отсутствия аудита Core. См. [Модель безопасности](./security) и [Использование клиентами](./client-usage).
