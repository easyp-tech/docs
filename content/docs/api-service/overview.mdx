title: "API Service"
---

EasyP API Service runs registered Protocol Buffers code generators on a server selected by the operator. A client sends a <code>CodeGeneratorRequest</code> containing file descriptors and plugin parameters. The service returns a <code>CodeGeneratorResponse</code>; the client writes the generated files.

This section describes service **v1.0.2**, source revision <code>4b01518b42c6f448d21216e3c0e8c35ef66d5c2d</code>, checked on **2026-09-23**. The service, its wire API, its Go SDK, and the <code>easyp</code> CLI are different components. A server capability is not necessarily available through every client.

## What is centralized

A deployment centralizes plugin registration, executable distribution, generation capacity, and operational monitoring. Developers do not need the same generator executables installed on every workstation. Pinning an explicit plugin version avoids the service's text-sorted <code>latest</code> lookup; it does not, by itself, make a mutable executable or a non-deterministic plugin reproducible.

~~~text
.proto files -> client compilation -> CodeGeneratorRequest
                                      |
                                      | gRPC, optionally TLS/mTLS
                                      v
                               EasyP API Service
                                |           |
                                |           +-> PostgreSQL: registrations, audit
                                +-> local plugin directory
                                     ^           |
                                     |           v
                                optional S3   child process
                                                 |
client output files <- CodeGeneratorResponse <----+
~~~
Docker is used to package the service and can build plugin artifacts. **A generation runs a local child process, not a new Docker container. There is no per-plugin sandbox.** Read [Security](./security) before accepting plugin registrations or exposing the service.

## Product boundaries

The five gRPC operations are <code>GenerateCode</code>, <code>Plugins</code>, <code>CreatePlugin</code>, <code>UpdatePlugin</code>, and <code>DeletePlugin</code>. The optional MCP endpoint provides plugin discovery. PostgreSQL stores plugin metadata and, when licensed, audit records; it is required even when all executables are local. Object storage is optional.

The service does not provide a schema/module repository, a Go/npm/Maven package server for generated SDKs, an API documentation portal for uploaded schemas, or registry-side breaking-change policy checks. Its Go SDK is a client of this generation service, not a generated-SDK distribution product. For module dependency management, see the separate [package-manager comparison](../cli/package-manager/easyp-vs-buf).

## When it fits

Use this service when you need to operate a generation endpoint in your own environment, control which trusted executables it runs, and accept responsibility for PostgreSQL, plugin artifacts, credentials, capacity, and upgrades. A disconnected installation is possible only after provisioning all required binaries, libraries, schema dependencies, images, and configuration, and excluding plugins that themselves need the network.

Local generation is usually simpler when a team does not need a shared execution service. A managed schema platform may be a better fit when generated package distribution, schema governance, organizational access controls, or reduced operator workload matter more than operating the execution environment. See [EasyP and Buf BSR](./vs-buf-bsr) for the different trade-offs.

## Capacity and access

Community permits up to four lookup workers, ten registered plugin versions, and sixteen simultaneous generations. Enterprise removes these license ceilings and enables audit recording; configured operational limits still apply. The two execution-related ceilings are applied when the process starts. A later license transition does not resize an existing pool.

Writes always require a configured bearer token. Reads and generation are anonymous by default; <code>auth.require&#95;authentication</code> changes that. The current <code>easyp</code> remote executor does not send bearer tokens or support client certificates. Use the [Go SDK or an appropriate client](./client-usage) when those are required rather than inventing CLI configuration keys.
