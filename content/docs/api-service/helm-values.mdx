## resources

Sized against what the service is configured to do, not guessed. The plugin's output is read into memory whole, so peak usage tracks config.workerPool.maxConcurrentGenerations × config.registry.maxOutputSize — 16 × 64 MiB = 1 GiB of buffers with the defaults below, and the same bytes again once marshalled into the gRPC response. _helpers.tpl refuses an install where that product no longer fits in the limit. The earlier default was 1Gi, which the buffers alone filled. The pod was OOMKilled under load, and an OOMKill reads as a crash rather than as overload: no log line, no rejected-generation counter, no saturation alert.

## persistence

Storage for the plugin cache. Plugin archives are downloaded lazily and unpacked here, and the directory is pruned: once it passes config.registry.cacheMaxBytes the least recently used plugin versions are removed. So size this for the working set you want resident, not for every plugin that could ever be requested. Eviction only ever removes local files. The archive stays in object storage, so an evicted plugin costs one download on its next request rather than being lost — which is why the cache can be sized to taste. Whichever of the two sizes below applies has to exceed cacheMaxBytes, and the chart refuses to install when it does not: eviction starts at the limit, so storage sized exactly to it is already full by the time the cache first needs headroom.

|---|---|---|---|

| <code>persistence.existingClaim</code> | string | <code>""</code> | — |
| <code>persistence.storageClass</code> | string | <code>""</code> | — |
| <code>persistence.accessMode</code> | string | <code>"ReadWriteOnce"</code> | — |
| <code>persistence.size</code> | string | <code>"25Gi"</code> | — |
| <code>persistence.ephemeralSizeLimit</code> | string | <code>"25Gi"</code> | Used when enabled=false, where the cache lives in an emptyDir on the node instead of a volume of its own. With it, an overrun stops at the pod that caused it. Remember this is per replica: with persistence off, every pod keeps its own copy, so plan for replicaCount × this much on the nodes. |
